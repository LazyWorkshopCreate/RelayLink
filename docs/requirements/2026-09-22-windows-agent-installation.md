## FR-17 Windows Agent 安装兼容性与可诊断性

本节描述当前安装依赖与故障可见性。拟议的多服务端版本对新装、重新配置及仅更新的配置格式另有要求，见 [REQ-001J](2026-09-28-multi-server-agent.md)；依赖检查和失败可见性仍适用。

- Windows Agent 安装包最低支持 Windows Server 2012 R2 x64；低于该版本或非 x64 系统必须在复制文件、修改配置和注册服务前停止安装。
- 安装向导在欢迎页之后显示独立的依赖检查页，以列表列出操作系统、处理器架构、Microsoft Visual C++ x64 运行库和 .NET 10 ASP.NET Core Runtime x64。通过项显示绿色对勾，失败项显示红色叉；可补装的失败依赖显示可点击的官方下载安装链接。依赖未全部通过时不得继续安装，静默安装也必须执行同一检查并以失败退出。自包含包的 .NET 项显示运行时已内置，不以系统安装结果阻止安装。
- Windows Agent 程序压缩包与安装包均同时提供 `win-x64` 自包含和框架依赖两种构建。自包含包携带 .NET 10 运行时；框架依赖包不携带运行时，目标机必须预装同一主版本的 .NET 10 x64 与 ASP.NET Core 共享框架。只安装基础 .NET Runtime 不满足本机状态页的运行依赖。Visual C++ x64 运行库是两种安装包的前置依赖。
- 两种安装包允许在已有安装上互相切换。程序直接位于 Agent 安装根目录；“仅更新”停服后清理已知程序文件和运行时文件，再写入完整的新构建，避免旧运行时和程序集混入；保留安装器卸载记录及 ProgramData 中的配置、身份、端口状态与日志。旧版 `program` 子目录须清理，服务改指向安装根目录。发布内容如增加安装器清理规则未覆盖的文件或子目录，打包必须失败。
- 服务注册、升级、停止和卸载脚本必须兼容 Windows Server 2012 R2 自带的 Windows PowerShell 4.0，不能依赖 PowerShell 5+ 语法或会破坏带空格参数的旧版原生命令参数传递。服务使用 `LocalService`、自动启动及失败恢复策略。
- 服务创建、配置、启动、停止或删除失败时，安装/卸载必须失败，向导显示具体阶段以及底层返回码或错误原因；禁止吞掉退出码或把部分完成报告为成功。失败后的回滚不得删除 ProgramData 中需保留的配置、身份和诊断日志。
- 安装包默认启用 Inno Setup 详细日志，并将可留存副本写入 `C:\ProgramData\RelayLink\Agent\installer-logs`。日志可以记录安装阶段、检查结果、脚本退出码和错误，但不得记录客户端密钥、CA 内容或完整配置正文。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A54 | 在 Windows Server 2012 R2 x64、较新 Windows x64、低版本 Windows 和非 x64 环境打开安装包 | 支持环境进入依赖页；不支持环境显示红叉并无法继续；尚未修改程序、配置或服务 |
| A55 | 对两种安装包分别模拟 VC++、.NET 10 或 ASP.NET Core 共享框架缺失和依赖齐全，并执行交互与静默安装 | 页面逐项显示绿色对勾或红叉，失败项可打开官方下载页；两种包均拒绝缺失 VC++；框架依赖包在 .NET 10 ASP.NET Core Runtime x64 缺失时拒绝，自包含包显示内置并允许继续 |
| A56 | 首次安装、更新、重新配置和卸载服务，并注入创建、启动、停止、删除失败 | Server 2012 R2 兼容脚本完成正常生命周期；每个故障均使操作失败并显示阶段、返回码或异常原因，不出现安装成功假象 |
| A57 | 执行成功安装和至少一种失败安装后检查日志 | ProgramData 日志包含时间、依赖结论、安装阶段与失败原因，不含客户端密钥、CA 正文或完整 Agent JSON |
| A70 | 发布并安装两种模式，分别从旧版根目录安装和另一种模式执行“仅更新” | 四个程序/安装包产物名称区分模式；转换器与 Agent 使用同一模式；安装根目录的旧程序文件清理后写入完整新构建且无旧运行时混入；旧 `program` 子目录被清理，服务指向根目录，配置及身份状态保持 |
