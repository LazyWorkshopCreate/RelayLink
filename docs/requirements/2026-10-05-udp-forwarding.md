## 范围

用户明确要求在现有 TCP 能力上新增 UDP 转发并实现。支持普通云端入口和客户端授权互访，两种入口均转发到目标 Agent 可访问的固定 UDP 主机和端口。本文的具体边界与默认参数是本次实施方案，尚未单独评审，状态不因实现自动改为 Done。原首期“仅 TCP / 不提供 UDP”边界由本需求扩展；现有 TCP 行为继续有效。

仅转发单播 UDP 载荷；不提供广播、组播、IP 层组网、P2P、原始来源 IP 透传或通用服务发现。SQL Browser 返回的动态端口不会被解析、改写或自动创建通道；配置 UDP 1434 不等于支持命名实例自动发现。业务须自行处理丢包、超时、重试和重复报文。

## FR-UDP-01 配置和使用

- 服务端通道增加 `transportProtocol`：`tcp` / `udp`，省略默认 `tcp`；增加 `udpIdleTimeoutSeconds`，默认 60，允许 1–3600 秒。
- 配置由服务端管理和下发，Agent 本地不保存通道。管理页支持选择协议、编辑 UDP 空闲超时；两端状态页和只读 API 标明协议。
- TCP 与 UDP 可以使用相同地址、数值端口；同协议重叠监听不得同时启用。端口建议按协议检查，保存再次绑定校验。
- 互访入口继承目标通道协议和超时，仍由访问方 Agent 分配、持久化本机端口并报告状态。

## FR-UDP-02 数据和会话

- 报文边界与内容保持，包括零长度、二进制和最多 65507 字节的载荷；不将流分段当作独立 UDP 报文，不转发不完整报文。
- 每个入口的来源 IP 和来源端口构成独立会话；不同来源、通道、客户端、服务端之间不得混流。每会话使用独立目标 UDP socket，回包返回原来源。
- 首包触发认证会话上的隧道建立，有限排队；目标准备和审计放行之前不发送业务报文。没有在线 Agent、容量不足、ACL 拒绝或建立失败时丢弃，不构造业务错误报文。
- 任一方向成功转发会刷新空闲时间；超时回收会话。下次首包建立新会话，不恢复或重放旧载荷。
- 配置实际变化、禁用、删除、安全组撤销、控制断线和停止服务须释放隧道、目标 socket 与配额；无变化保存不撤销。

## FR-UDP-03 安全与资源

- 复用独立客户端认证、一次性隧道令牌、配置版本校验、连接/待建立上限、审计放行门槛及敏感日志边界。UDP 会话计入现有连接限额。
- 普通入口按实际来源 IP 检查应用层安全组；网络边界仍由部署防火墙/安全组负责。互访仍校验证书和访问证明，默认内层 TLS，明确关闭加密时才允许明文。
- 每会话最多排队 32 个报文，队列满丢弃新报文；不得无限排队。隧道写入有超时，空闲和取消及时终止双向任务。
- Agent↔Server 数据隧道仍为 TCP，不新增 UDP 公网数据入口。TCP 隧道存在队头阻塞，不承诺 UDP 实时延迟或网络层无损传递。

## FR-UDP-04 增量兼容

用户于 2026-10-05 明确要求非破坏性增量保持旧客户端兼容。新版 Server 必须接受 v3 Agent 并保留普通 TCP 和授权 TCP 互访，初始及更新配置遵循旧结构与摘要。UDP 只向 v4 下发；不能把旧 Agent 不认识的 UDP 配置解释为 TCP。认证、TLS、一次性绑定、审计及资源门槛不因兼容而放松。版本锁定与升级边界见 [ADR-0025](../adr/0025-v3-client-compatibility.md)。
