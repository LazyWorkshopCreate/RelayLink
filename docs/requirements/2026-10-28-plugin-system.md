## 1. 背景与决定边界

现有普通代理按原始 TCP 复制，服务端看得见字节，但不解析应用。现有端到端互访默认在两个 Agent 之间加密，服务端只中继密文。现有 HTTP 反向代理在目标 Agent 处理 HTTP，服务端不解密浏览器 TLS。通道 tag 只用于管理列表筛选，不进入 Agent 快照。因此服务端目前不能按应用审计业务内容，客户端页面也不能按应用唤起本机程序。

本需求增加两类可选通道，让服务端成为这两类通道的加密终点并运行插件。既有普通代理、端到端互访、明文互访、UDP 和目标 Agent HTTP 反向代理保持原行为。草案未采纳前，不改变已发布行为。

第二类通道的目的与第一类相同，都是服务端流量审计。一条连接要能关联调用侧和目标侧的结果。

## 2. 范围

- 新增「服务端可视互访」和「服务端跳板代理」。只有这两类通道进入服务端插件。
- 被访问通道增加应用下拉。选定的应用写入保留 tag，选定后不能修改。端到端访问入口继承被访问通道的应用，不单独编辑。
- 首期内置 SSH、RDP、HTTP、HTTPS 四种服务端插件。能力按应用分别限定，见 FR-29。
- 服务端可保存目标账号的口令或私钥，用于服务端代登录。把凭据发给客户端必须另开策略。
- 客户端按通道能力降级：能唤起本机应用，但不能假装所有通道都有服务端审计或代登录。
- 浏览器只负责打开已注册协议。桥应用执行本机脚本。浏览器地址、页面脚本和管理页都不接触口令、私钥和脚本正文。
- 首期插件随服务端版本发布，不热加载、不从远端下载插件或脚本。
- 新建被访问通道时，表单最上方选择通道类型，下方只显示该类型需要的字段。编辑时通道类型不可改。

不在本需求内：替换现有端到端加密、改写现有 HTTP 反向代理的终止位置、UDP 应用审计、RDP 图形与剪贴板内容审计、终端全程录制、外部审批通知、自动向调用方安装根证书、第三方便携插件市场。

## 4. 功能要求

### FR-27 两类可审计通道

- 通道增加审计模式，取值仅 `none`、`server-peer`、`server-jump`。缺省和所有既有通道为 `none`。
- `server-peer`（服务端可视互访）只用于授权互访：调用方仍通过访问方 Agent 的 loopback 入口进入。调用方 Agent 与服务端、服务端与目标 Agent 各自建立 TLS。服务端解开两侧 TLS 后把字节交给插件，再按插件结果发向另一侧。它不是把现有 Agent 之间的内层 TLS 关掉。
- `server-jump`（服务端跳板代理）使用服务端监听地址，调用方不经过访问方 Agent。服务端在监听侧处理应用加密或明文，在目标侧经目标 Agent 到达 `targetHost:targetPort`。服务端与目标 Agent 之间的这一段使用 TLS。公网监听继续受既有安全组约束。
- 未加密应用流量只表示调用方与目标之间的业务字节可以是明文，仍须进入插件；不能因此取消服务端到目标 Agent 的腿部 TLS。
- 两类模式仅允许 TCP。不得与 UDP、现有 `applicationProtocol=http` 同时启用。现有端到端加密开关只对 `none` 且授权互访的通道有效。
- 通道类型只在创建时确定，见 FR-33。编辑不能把既有通道改成可审计模式，也不能在两种新模式之间切换。要更换类型必须删除后重建；删除沿用既有连接撤销。
- 协议按版本隔离。不能理解该模式的 Agent 不得收到这些通道或入口，也不得把它们当普通 TCP 运行。

### FR-28 应用标识

- 被访问通道的表单单独提供应用下拉，首期选项为未指定、SSH、RDP、HTTP、HTTPS。
- 选定后的规范值写入该通道 tag，格式固定为 `app:ssh`、`app:rdp`、`app:http`、`app:https` 之一。自由输入的 tag 不得新增、删除或伪造 `app:` 前缀。
- 未指定可以在后续维护中选定一次。已经选定的应用不能修改或清空；要更换必须删除通道后重建。
- 该保留 tag 仍显示在管理列表中，并继续可用既有 tag 筛选。除此之外，普通 tag 的筛选、数量和「只改 tag 不下发」规则不变。
- 运行时只把解析出的应用标识放入快照，不把整组筛选 tag 放入快照。应用从空到选定属于运行配置变化，并撤销该通道上的存量连接。通道类型本身创建后不能改。
- 端到端访问入口不保存自己的应用字段。展示、筛选继承和客户端唤起都读取目标通道当前应用。目标未指定时，入口没有应用。
- 应用与通道能力必须一致：UDP 不能带应用；现有 HTTP 反向代理只能是未指定、HTTP 或 HTTPS；服务端可视互访必须是四种应用之一；跳板代理在未指定时只能走未加密应用路径。不一致的配置拒绝保存。

### FR-29 服务端插件

- 插件只挂在 `server-peer` 和 `server-jump`。其他通道即使带有应用 tag，也不进入服务端插件。
- 插件由服务端随版本装载。首期只有内置 SSH、RDP、HTTP、HTTPS。不支持热更新、目录投递或远端安装。
- 未指定应用、找不到插件、插件失败、策略拒绝或审批超时，都不得连接目标，也不得退回原始复制。
- 阻断在连接目标前生效；已建立会话被策略切断时释放两侧资源一次。
- 审批在管理页完成。等待计入既有待建立连接配额，超时拒绝。首期不发送邮件、即时消息或 webhook。
- 四种应用首期能力如下。设计中的处理位置和故障行为是实现约束，验收以本表为准。

| 应用 | 首期必须提供 | 首期明确不做 |
|---|---|---|
| SSH | 识别应用标签；审计认证结果、会话、命令或子系统、端口转发和代理转发请求；可阻断这些动作；打开会话前可审批；目标侧使用服务端保存的口令或私钥登录；向调用方出示本通道自己的主机密钥 | 全程键入回放；冒充目标主机密钥；默认放行端口转发和 SSH agent forwarding |
| RDP | 连接前允许、拒绝和审批；审计来源、时间、字节和策略结果；在单独打开发放策略时配合客户端自动登录 | 解密图形、键入、剪贴板和驱动器重定向；服务端代做 NLA |
| HTTP | 审计方法、主机、去掉查询串的路径、状态、字节和耗时；按方法、主机和路径前缀允许、拒绝或审批；不记录凭据头和正文 | 改写正文；记录正文；HTTP/2 和 gRPC；替代现有目标 Agent HTTP 反向代理 |
| HTTPS | 终结调用方 TLS，解密后使用与 HTTP 相同的审计和规则；向目标重新发起并校验 TLS；证书或上游校验失败时拒绝 | 自动安装根证书；一证书冒充任意站点；对抗证书固定；把现有透传 TLS 的 HTTP 通道改为服务端解密 |

### FR-30 凭据与自动登录

- 目标账号的口令和私钥由服务端保存，管理接口只能写入、替换和删除，不能读回秘密。
- 秘密不写入客户端通道 JSON、快照、普通日志、审计详情或浏览器。
- 默认同一个账号由服务端在目标侧使用。SSH 首期就走这条路径。
- RDP 首期不能在服务端代登录。只有通道显式允许向客户端发放时，桥应用才能取用一次性凭据完成本机自动登录。
- 向客户端发放对 SSH 也是显式策略，默认关闭。发放一次有效、短时有效，并写入审计。审计只记账号标识和结果，不记秘密。
- 未打开该策略的通道，以及 `none` 模式通道，不提供目标秘密。客户端仍可按 FR-31 只凭地址唤起应用。

### FR-31 客户端唤起与桥应用

- Agent 本机页面是授权互访入口的唤起位置，包括服务端可视互访。标准代理和跳板代理在管理页提供同一唤起动作；本机没有桥应用时只显示或复制地址。
- 浏览器创建一次性 intent 后，打开已注册协议把 intent 交给桥应用。地址中只有 intent 和本机端口，没有令牌、口令、私钥、主机密钥或脚本。
- 桥应用向本机 Agent 取回入口、应用和已获准的凭据，再执行安装时自带的脚本模板。服务端和管理页不能下发或替换脚本正文。
- 本机覆盖脚本只能来自桥应用本机配置，参数只接受固定字段。缺少桥、缺少应用、应用与平台不匹配时，页面保留地址并说明原因，不把通道标成故障。
- 首期 RDP 唤起只要求 Windows。SSH 和浏览器唤起覆盖 Windows、Linux、macOS；目标程序不存在时给出明确失败。

### FR-32 降级、兼容与审计

- 客户端按通道能力降级，而不是要求所有通道都升级为可审计模式。
- 标准代理、既有端到端、既有明文互访和既有 HTTP 反向代理：可以在有应用 tag 和可达地址时唤起对应程序；没有服务端插件、没有服务端代登录。
- UDP 不提供应用唤起。
- 可审计连接的审计要能用连接 ID 关联调用侧和目标侧，并与既有连接审计区分。
- 审计可包含 SSH 命令、子系统、HTTP 方法和去掉查询串的路径。不得包含口令、私钥、Cookie、Authorization、HTTP 正文、RDP 图形或未获准发放的凭据。
- 既有「审计失败则不放行」规则适用于可审计连接的起始决定和凭据发放。

### FR-33 按类型创建，编辑时锁定类型

- 新建被访问通道的表单第一项是通道类型。未选择类型时不能提交。切换类型后，只显示并提交该类型的字段，不把前一种类型填过的监听、加密或插件字段一并保存。
- 类型至少包括：标准代理、UDP 代理、端到端互访、UDP 互访、服务端可视互访、服务端跳板代理。HTTP 公网反向代理和 HTTP 互访反向代理使用同一选择器；页面尚未提供其策略表单时，这两类继续由配置文件创建，但打开后类型同样不可改。
- 类型决定传输协议、是否授权互访、是否为现有 HTTP 反向代理，以及审计模式。这些成分创建后构成不可变组合。端到端互访和 UDP 互访里的「Agent 间加密」开关不是类型，编辑时仍可改。
- 编辑表单显示当前类型且不可操作，只渲染该类型仍允许修改的字段。不提供把标准代理改成互访、把端到端改成可视互访，或改 TCP/UDP 的控件。
- 更新接口若发现类型组合与已保存通道不同，拒绝本次保存，不写配置，不断开已有连接。更换类型只能删除原通道后新建。

## 6. 当前状态

整体仍为 Draft，不能把 A92–A107 全部标为通过。现已实现通道类型及保留标签、v7 可审计两种模式、HTTP/HTTPS 逐请求检查、SSH 目标指纹与动作审计、阶段期限/配额、应用流量和凭据恢复；用户授权的审查修复及测试证据见 [DEV-006](../development/plugin-system-improvement-plan.md) 与 [TST-009](../testing/plugin-system-remediation-verification.md)。

RDP 数据面（A99）、管理员批准闭环（A102 的批准部分）、凭据发放（A103 的发放部分）、桥应用及 intent（A104/A105 的唤起部分）尚未实现；仅有等待超时拒绝不等于完成审批。HTTPS/策略编辑仍由配置文件提供。跳板未选应用时保留原有原始转发，因此 A97 的“未指定应用”条款仍未验收；选定应用后的故障不降级。平台和容量验证按记录说明，不能用本机正确性测试替代。
