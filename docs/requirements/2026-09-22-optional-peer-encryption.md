## FR-16 互访通道加密开关

- 通道配置增加 `endToEndEncryptionEnabled`；仅在 `authorizedClientsOnly=true` 时生效。字段缺失按 `true` 处理，现有配置升级后继续加密。
- 管理页面在勾选“仅允许授权客户端互访”后显示“启用 Agent 间端到端加密”，默认勾选；创建和编辑均可调整。列表须明确标识“加密”或“明文”。
- 加密模式继续使用 Agent↔Agent TLS、目标证书指纹固定、访问密钥挑战证明及应用层半关闭封装。
- 明文模式不建立内层 TLS。两端仍须经过独立客户端身份、服务端映射授权、一次性数据绑定令牌和每连接随机挑战的 HMAC-SHA256 访问密钥证明；证明成功前，被访问 Agent 不得连接业务目标。证明上下文必须包含加密模式，防止跨模式复用。
- 明文模式在证明成功后将本机 TCP 与既有有界 `Data/Fin/Reset` 流直接双向复制，保留 TCP 半关闭、取消、超时、配额、审计和连接撤销语义，不得增加无界缓冲。
- 控制连接仍必须启用 TLS，以保护客户端密钥、访问密钥和配置下发。关闭业务流加密意味着服务端及数据链路观察者能够读取和篡改业务内容；管理页面和运维文档必须明确提示，只应在受信隔离网络或业务协议自身已经加密时使用。
- 通道加密设置属于运行配置。修改后须更新配置摘要并下发给目标 Agent，撤销该通道已有连接；新连接由服务端把当前模式同时通知访问方和被访问方。协议版本升级，旧 Server/Agent 不得与新版本静默混用。

## 验收标准

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A51 | 新增互访通道，分别保留默认值和取消加密勾选 | 默认保存为加密；取消后保存为明文；列表、公开查询和 Agent 状态显示与配置一致；旧配置缺少字段时仍为加密 |
| A52 | 分别通过加密和明文互访入口传输随机字节并执行单向半关闭 | 两种模式均精确双向传输并完成半关闭；加密模式有 TLS 开销，明文模式服务端转发载荷只包含访问证明和原始业务字节，不出现 TLS 握手记录 |
| A53 | 在两种模式发送错误访问证明，并在活动连接中切换模式 | 两种模式均在连接目标前拒绝错误证明；切换模式会撤销旧连接并只按新模式建立连接；其他通道不受影响 |
