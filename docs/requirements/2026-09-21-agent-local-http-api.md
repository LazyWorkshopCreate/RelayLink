## FR-15 Agent 本机只读 HTTP API

- API 与 Agent 本机状态页使用同一个 Kestrel 实例和 `dashboardPort`；只绑定 IPv4 loopback `127.0.0.1`。`dashboardPort` 为 0 时，网页和 API 同时关闭。
- 提供版本化 GET 接口：`/api/v1/status` 返回聚合状态，`/api/v1/channels` 返回被访问通道，`/api/v1/mappings` 返回端到端访问入口。保留旧 `/api/status` 作为兼容入口。
- 每个响应返回客户端 ID、控制会话在线状态和最近状态更新时间。通道包含 ID、显示名称、启用状态、访问模式与目标地址；入口包含 ID、启用状态、目标客户端/通道和实际 loopback 地址，未成功监听时地址为 `null`。
- API 仅反映 Agent 当前控制会话已确认的配置和实际监听状态；离线时在线状态为 `false`，通道和入口列表为空。
- API 不提供新增、修改或删除方法，不返回客户端密钥、通道访问密钥、目标证书指纹、端到端证书私钥或控制/数据令牌。响应使用 JSON、`Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。
- loopback 上的本机进程均可读取这些运维信息；部署方仍须使用操作系统用户与进程隔离保护 Agent 主机。不增加跨域访问能力，也不把 API 暴露到 LAN 或公网。

## 验收标准

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A49 | 第三方进程分别请求三个 v1 GET 接口 | 返回当前客户端、通道和入口 JSON；入口实际地址与 Agent 监听地址一致，离线语义明确 |
| A50 | 检查监听地址、响应头和响应正文，并向查询路径发送写请求 | 服务只监听 `127.0.0.1` 且与网页共用端口；响应禁止缓存且不含密钥或证书指纹；写请求返回 405，不改变状态 |
