## 1. 背景与决定边界

服务端目前只有两种对外接口。一是浏览器管理页使用的 `dashboard` 监听：匿名只读 API、管理员登录后的读接口与写接口，鉴权是 `HttpOnly` 会话 Cookie 加 `X-RelayLink-CSRF`。注意审计门槛的现状：ADR-0013 的"先落审计再放行"只覆盖登录、Agent 会话建立、普通代理 Start 与端到端 BindAccepted；管理员登录与凭据变更有审计，而**客户端、通道、访问映射、安全组的管理配置写目前完全不写审计**。二是 Agent 本机只读 API：`/api/v1/status`、`/api/v1/channels`、`/api/v1/mappings` 与 v2 分组接口，只绑定 `127.0.0.1`，这一组只有 GET；同端口另有 `/api/v2/admin/servers*` 写路由，但只改本机 Agent 的 `servers[]` 连接项，不涉及 RelayLink 服务端配置。

这两种接口都不适合程序化调用。Cookie 与 CSRF 面向浏览器，自动化进程保存 Cookie 等于保存管理员口令；本机只读 API 不含任何服务端配置。结果是运行在运维工作站的 AI agent 只能靠人读页面、抄字段、改表单，第三方应用也没有任何受支持的接入方式，只能自己拼 TCP 地址并假设隧道形态。

2026-11-05 用户明确要求两条能力：一是供 AI agent 调用的 skill、CLI 与服务端 API，用于管理服务端设置，只允许通过端到端加密的通道，并必须在服务端控制台授权；二是供第三方应用集成的 SDK，覆盖主流平台与开发语言。

本文档界定这两条能力的范围与验收。交付形态是 `.NET` 命令行程序、随其分发的 agent skill、以及多语言 SDK；服务端复用既有配置编辑、审计、幂等回执与授权互访路径，不改变普通代理、端到端互访、UDP 与目标 Agent HTTP 反向代理的既有行为。

范围判定沿用用户答复：SDK 以数据面为主，只提供有限的注册与申请能力；所有需要人工判断的动作仍在管理页面批准，不由自动化接口自批。

## 2. 范围

- 新增可选的自动化入口，仅供上述 CLI 调用，默认关闭。
- 自动化入口只接受 TLS，并且只能经既有授权互访（访问方 Agent 的 loopback 入口）到达；不得为它新增公网入口。
- "只经端到端加密通道"按下述口径验收，不含糊表述：跨主机链路必须是授权互访的内层 TLS，中途没有明文管理流量；服务端主机内部到自动化端口的那一段是 loopback 明文 TCP，由自动化监听自身的 TLS 覆盖，属主机内传输加密，不得对外称为端到端加密。精确边界见[设计 2.1](../design/ai-automation-and-sdk.md#21-只经端到端加密通道的精确含义)。
- 新增一次性配对流程：CLI 发起请求，管理员在管理页面核对并批准后，CLI 才能取得有时限的自动化令牌。
- 新增自动化 API：只读查询、受控写入、以及必须先获批的变更申请。
- 交付单一命令行程序，覆盖配对、查询、写入、变更申请与 skill 安装。
- 交付 agent skill：把 CLI 约束成 AI agent 唯一可用的动作面。
- 交付多语言 SDK：数据面接入，以及注册客户端、注册通道、申请访问通道的有限管理面。
- 实现时同步更新文档索引、目录规划说明、配置示例与验证记录；本需求文档只界定范围，不预建空目录或空验证文档。

不在本需求内：

- 公网可达的自动化入口或公网管理端口。
- 免批准白名单、配置文件预登记、自动批准、审批即放行的旁路。
- 多管理员、按角色分权的 RBAC；管理员账号模型保持现状。
- 用自动化接口修改管理员口令、管理员会话或本机 Agent 写会话。
- 通过 OIDC/OAuth 等外部身份提供方联合登录。
- 中继线协议（`NTP1` 帧）的对外开放或第三方实现许可。
- 把 Agent 嵌入第三方进程、SDK 自建隧道、SDK 实现打洞或多路复用。
- 配置热更新、写入型仪表盘、SQL 重放。
- 自动向第三方应用分发客户端密钥或通道访问密钥。

## 3. 用户需求

| 编号 | 需求 |
|---|---|
| U31 | AI agent 可以经 skill 与 CLI 读取服务端状态、客户端、通道、映射、安全组、审计与流量历史 |
| U32 | 上述通道只能走端到端加密链路，并且首次使用必须由管理员在服务端控制台人工批准 |

## 4. 功能要求

### FR-34 自动化入口与传输边界

- 服务端新增 `automation` 配置段，至少包含 `enabled`（默认 `false`）、`listenAddress`（仅允许 `127.0.0.1`，其它值拒绝启动）、`port`（默认 `18082`）、`certificatePemPath`、`privateKeyPemPath`、`sessionLifetimeMinutes`（默认 120，允许 15–480）、`maxPendingPairings`（默认 8）与 `maxAuthorizations`（默认 16）。
- `automation.enabled=false` 时该监听不启动，所有自动化路由在进程内不存在，不返回占位页面。开关变更在重启后生效，不提供热更新。
- 自动化入口只在 TLS 上提供 HTTP/1.1 与 HTTP/2，不接受明文 `http://`。不提供“为调试关闭 TLS”的开关，也不接受客户端用 `--insecure` 跳过校验。
- 端到端前提由三处共同保证：一是自动化入口只绑定 loopback；二是管理页面提供“为自动化创建接入通道”的专门动作，服务端生成通道时强制 `authorizedClientsOnly=true`、`endToEndEncryptionEnabled=true`、`applicationProtocol=raw`，且不允许管理员改这几个字段；三是通道保存校验拒绝任何把 `targetHost` 指向本机回环地址且 `targetPort` 等于 `automation.port`、却不同时满足上述组合的通道。第三条实际挡住的是“非授权互访”形态，因为只有 `authorizedClientsOnly=false` 会在服务端监听公网端口。
- 自动化入口端口不得与 `tunnel.port`、`tunnel.dataPort`、`dashboard.port` 或任何普通通道监听端口相同；冲突在启动预检和配置保存时拒绝。
- 自动化客户端不得使用浏览器管理会话 Cookie、管理员口令或本机 Agent 写会话。所有调用使用设备绑定的自动化令牌，并按 FR-35 的证明方式提交。
- 令牌、设备私钥、一次性用户码不得已以外的方式落盘或记录：不得进入命令行参数、URL、普通日志、审计详情、错误正文，也不得被写入任何文件。用户码的唯一例外见 FR-37：它必须出现在配对发起的一次性输出中，供 AI agent 转达管理员核对。

### FR-35 一次性配对与人工批准

- 配对采用设备码式流程，参照 OAuth 2.0 Device Authorization Grant（RFC 8628）的分步形状，但令牌与证明方式由本设计自定。
- CLI 首次使用时在本机生成设备密钥对（EC P-256），私钥只落本机受保护存储。随后提交配对请求，包含主体名、平台、CLI 版本、请求的 scope 集合与设备公钥。
- 服务端返回 `requestId`、一次性用户码（8 位、显示为 `XXXX-XXXX`）、过期时间与自身证书指纹。用户码缺省 10 分钟过期，单次使用。
- 管理员在管理页面的“自动化授权”面板查看待批准请求，逐项核对用户码与操作员屏幕上显示的一致，然后批准或拒绝。批准时只能缩小 scope 与令牌有效期，不能扩大；申请中未列出的 scope 不得获批。
- 用户码本身不能换取令牌。换取令牌必须由设备私钥对待签内容签名，内容包含 `requestId`、自动化实例标识与用户码摘要。
- 自动化实例标识必须是**持久化**的：首次启用时生成并存入自动化状态库，服务端重启后保持不变。不得复用既有 `ServerRuntime.InstanceId`——该值是每进程 `Guid.NewGuid()`、不持久化，直接复用会导致重启后所有令牌证明与 CLI 固定校验失效，与“重启后授权与令牌继续有效”冲突。详见[设计 §5.4 自动化实例标识必须持久化](../design/ai-automation-and-sdk.md#自动化实例标识必须持久化)。
- 未获批准的请求不能取得令牌；被拒绝的请求对 CLI 是终态，需重新发起。
- 同一设备短时间内重复提交用户码错误达 5 次，该请求作废；配对请求按「设备公钥指纹 + 主体名」限流，并对匿名端点另设进程级全局上限，超限返回服务端可重试的明确错误。**不能按来源地址限流**：经授权互访到达的连接来源恒为目标 Agent 拨号的 `127.0.0.1` 临时端口，既区分不了调用方，又会误伤合法 CLI。
- 待批准请求数量达到 `maxPendingPairings` 时，新请求被拒绝，不影响已建立的授权与既有连接。活动授权数量达到 `maxAuthorizations` 时同样拒绝新配对。
- 服务端记录每次批准与拒绝：请求主体、平台、scope、设备公钥指纹、批准时间、管理员账号与结果；不记录私钥与令牌。
- 管理页面可随时撤销任一活动授权；撤销对下一次调用立即生效，不等待令牌自然过期。撤销或过期不影响已有通道上的业务连接，也不删除已保存的配置。
- 不提供无需重新配对即可延长使用的方式：令牌到期后必须重新发起配对并再次人工批准。本需求不引入刷新令牌，理由与备选记录在 [ADR-0035](../adr/0035-ai-automation-over-peer-channel.md)。
- 不提供自动批准、配置文件预登记、IP 白名单免批准或“首次之后永久有效”的口子。

### FR-36 自动化 API 面

- 匿名可达的只有两个端点：`GET /api/v1/automation/info` 返回接口版本、是否需要配对与自动化实例标识，不含秘密；配对请求端点 `POST /api/v1/automation/pairing/requests` 受严格限流。
- 设备证明可达的端点只服务配对本身：查询请求状态、换取令牌。
- 令牌可达的端点分为只读查询、受控写入与变更申请，覆盖服务端现有的客户端、通道、访问映射、安全组、审计、流量历史与健康信息，并新增版本信息端点（服务端目前没有版本端点，`/api/v1/overview` 只含实例标识，`agentVersion` 是客户端维度字段）。
- 变更申请端点提供提交、查询列表、查询单条与撤销；批准与拒绝只在管理页面进行，不提供自动化接口。
- 统一响应契约：成功响应带 `requestId`；失败响应带稳定的 `error.code`、可读 `message` 与 `retryable`；写操作返回 `auditStatus`。字段名与分页形状在 [设计文档](../design/ai-automation-and-sdk.md) 中定义，CLI 与 SDK 不得依赖未列出的字段。
- 操作按风险分级，分级决定是否需要二次批准：

| 级别 | 内容 | 获批令牌下的行为 |
|---|---|---|
| A 只读 | 状态、快照（服务端运行与聚合视图）、客户端、通道、映射、安全组、审计、历史、健康、版本 | 直接执行 |
| B 受控写 | 修改显示名与 tag、上限与超时、启停通道、创建或修改安全组、删除未被引用的安全组、删除访问映射、撤销自己提交的待批申请 | 直接执行，逐次审计 |
| C 结构性写 | 新增或删除客户端、新增或删除通道、创建访问映射、修改通道的端到端加密开关 | 只能生成变更申请，管理页面批准后执行一次 |
| D 身份与授权 | 签发、延长或撤销自动化令牌、管理员口令、管理员会话 | 自动化接口不可操作 |

- 分级表之外的边界：客户端级启停不在 B 类（影响该客户端全部通道），自动化接口不可操作；承载自动化自身的接入通道与其访问映射不可经自动化停用或删除（会让 CLI 自断连接），请求返回拒绝并要求改走管理页面。
- 既有编辑器禁止修改已建通道的 `authorizedClientsOnly`，自动化首期 `channel.security` 只覆盖既有 PUT 已允许的端到端加密开关。
- 受控写入必须携带非空 `Idempotency-Key`；同键不同载荷拒绝，同键重放返回原结果。变更申请的提交按该键幂等；执行的一次性由 `applying` 中间态与服务端启动对账保证，不依赖该键。
- 审计门槛按 ADR-0013 的模式**扩展**到自动化面：所有自动化调用形成可关联的审计事件，包含主体、令牌标识、操作、目标与结果；审计存储不可用时，写操作与变更申请一律拒绝，只读请求放行并在文件日志告警。注意既有管理配置写（客户端、通道、映射、安全组）目前不写审计，因此这对 B 类写入是**新增**门槛，不是复用既有行为；只读不设放行门槛。
- 只读调用也记录审计，但允许按「同一令牌 + 同一方法与路径 + 60 秒窗口」合并计数，合并行仍记录端点、计数与首末时间以保持可关联；不同端点各自成行，并为每令牌设读请求上限。
- 自动化接口不得返回任何秘密：客户端密钥、通道访问密钥、凭据明文、私钥、证书私钥、一次性用户码的内部存储形式。下发 Agent 配置沿用既有“配置生成”语义，不新增秘密外泄面。
- 令牌、设备的 scope 与服务端当前配置版本无关地对每个请求重新校验；服务端重启后活动授权与令牌继续有效，撤销状态可持久化恢复。
- 凭据写入（口令与私钥）与凭据删除完全不经自动化接口，只能在管理页面完成；自动化接口不接受凭据相关的变更申请（提交即拒）。理由见 [ADR-0035](../adr/0035-ai-automation-over-peer-channel.md) 决定第 7 条与[设计的威胁矩阵](../design/ai-automation-and-sdk.md#12-安全后果)。

### FR-37 命令行程序

- 交付单一可执行程序 `relaylink`，随 `RelayLink.slnx` 构建，提供 Windows、Linux、macOS 的 x64 与 arm64 自包含版本。
- 命令覆盖：配对（发起、等待、状态、撤销、重新固定证书）、授权自查、健康与版本、客户端、通道、访问映射、安全组、审计、流量历史、变更申请与 skill 安装。
- 全局选项至少包含 `--profile`（多服务端）、`--json`、`--dry-run`、`--yes`、`--timeout` 与 `--verbose`。
- `--json` 输出带 `schemaVersion` 的稳定结构；人读输出不得用于脚本解析。
- `--dry-run` 只做本地校验与计划展示，不得提交任何服务端变更，也不得消耗一次性令牌或变更申请额度。
- 退出码固定为：`0` 成功、`2` 用法错误、`3` 未授权或未配对、`4` scope 不足、`5` 需要人工批准、`6` 服务端业务拒绝、`7` 审计或存储不可用、`8` 网络或证书固定失败、`9` 版本不兼容。
- 凭据存储优先使用操作系统凭据库（Windows DPAPI、macOS Keychain、libsecret）。不可用时回退到受保护文件（Windows ACL 与 Unix `0600`），并显式告警。
- 服务端证书指纹在配对时固定并持久化。指纹不匹配时硬失败，必须由人工执行重新固定；不提供跳过校验的选项。配对前的匿名端点（`/info`、发起配对）无法做固定校验，其版本信息只用于选择行为、不用于任何安全决策；首次连接使用自签证书时，CLI 打印 SPKI 摘要并要求操作员带外核对后接受。
- CLI 必须能从本机 Agent 的只读 API 发现自动化入口（按目标客户端与目标通道匹配映射上报的实际地址），也允许显式配置覆盖；两者都不可用时以明确错误退出，不猜测地址。
- 非交互式终端（无 TTY）不得阻塞等待交互式确认；需要人工批准的命令只打印后续步骤并以 `5` 退出，除非显式使用等待模式。
- AI agent 通常没有 TTY，因此配对发起后必须能取到一次性用户码并转达给管理员核对：用户码出现在人读输出的固定标记行与 `--json` 的 `data.userCode` 中，只出现一次，不写入任何日志或文件。不得为了“不落盘”而把用户码从输出中彻底移除，否则 agent 无法完成配对。
- CLI 不得自动重试非幂等写操作，不得在失败后静默改写服务端配置。

### FR-38 agent skill 合约

- 交付一个 skill 目录，至少包含 `SKILL.md`（含 `name` 与 `description` 元数据）、参考文档与包装脚本；打包随 CLI 发行物一起提供。
- skill 的允许动作面只有 CLI：不得直连 HTTP 端点，不得自行实现 TLS、证书固定、令牌或配对流程。
- skill 只读取 CLI 的 `--json` 输出；不得读取令牌文件、设备私钥、服务端配置文件或日志原件。
- skill 必须声明所依赖的 CLI 版本区间与自动化 API 版本；不匹配时拒绝执行并提示升级，不得降级或改用手工 HTTP。
- 每个动作映射到明确 scope。CLI 返回 `4` 时 skill 必须停止并提示如何申请扩展 scope，不得改写参数重试。
- C 类变更必须先 `--dry-run` 展示计划并取得人工确认后才能提交申请；提交后只报告申请标识与待批准状态，不得声称已生效。
- 把用户码呈现给操作员是 skill 的必备能力：agent 必须原样转达 CLI 输出中的用户码，并提示管理员在服务端控制台核对。skill 不得自行批准、不得改写用户码、不得把用户码写入文件。
- skill 不得输出或回显秘密字段；发现响应中含疑似秘密时停止并报告异常，不写入任何文件。
- 以上是提示层约束，不是可强制执行的安全边界。验收覆盖两类证据：交付物内容审查，以及在至少两种具名 agent 宿主中的受控示范执行（覆盖宿主发现 skill、调用包装脚本、处理退出码 `4` 与 `5`、转达用户码）。宿主 agent 绕过 skill 直连 HTTP 的残余风险在威胁矩阵中声明，不声称已被消除。
- 包装脚本依赖宿主机 Node.js 运行时，必须在 `SKILL.md` 前置要求与安装输出中声明；不得假设宿主已具备。
- 安装方式只支持把 skill 目录复制到目标宿主约定位置，不在运行时从远端下载或更新。

### FR-39 SDK 数据面

- SDK 不实现中继协议。它面向“入口”：授权互访时是访问方 Agent 的 loopback 端口，普通代理时是服务端业务监听地址。
- 入口解析优先级：显式配置优先；未配置时读取本机 Agent 的 v2 只读 API（`/api/v2/status`、`/api/v2/channels`、`/api/v2/mappings`），只接受 `127.0.0.1`；Agent 离线或列表为空时返回明确错误，不猜测地址。
- TCP：一次业务流一条连接，支持单向半关闭、超时、取消与背压；连接上限与重试策略由应用决定，SDK 不隐藏失败。
- UDP：单 socket 会话，保留报文边界，空闲回收语义与通道一致；重传、去重与顺序由应用负责。
- HTTP：只提供通道对应的基础地址与 Host/Origin 约束说明，不代做 Host 覆写、来源校验或证书处理。
- 错误模型跨语言一致，至少区分：入口不可用、隧道拒绝、目标连接失败、超时、配置漂移与本地用法错误。
- SDK 不缓存、不持有客户端密钥、通道访问密钥或任何中继令牌；不提供协议帧、多路复用、打洞或 VPN 能力。
- 数据面链路的加密强度由通道配置决定：授权互访默认内层 TLS，SDK 不得关闭或降级；普通代理入口的明文体性由部署与业务自身 TLS 承担，SDK 不得宣称已加密。

### FR-40 SDK 有限管理面

- SDK 管理面只调用 FR-36 的自动化 API，沿用同一端到端通道、同一配对与批准模型。
- 允许的三个动作：注册客户端（申请）、为当前客户端注册通道（申请）、申请访问通道（互访映射申请）。首期不含“更新通道”：更新属 B 类直接生效操作，应由 CLI 完成并在文档中说明这一分工，不要让调用方以为更新也走申请。
- 三个动作在管理页面批准前不产生任何配置变更、不签发密钥、不下发快照。
- 申请提交与状态查询必须幂等且可恢复：超时或进程重启后能按申请标识继续查询，不重复创建。
- 批准后 SDK 只得到标识与状态，不取得客户端密钥：Agent 配置仍由管理员在管理页面下载与分发。SDK 不得声称“登记即可连接”，并须在文档中写明完整上线路（分发配置 → 安装启动 Agent → 服务端固定其端到端证书指纹 → 建映射并使入口可连）。
- 首期只有 C#/.NET SDK 提供完整管理面。其余语言受语言依赖约束（仅标准库/JDK/内置模块）无法读取操作系统凭据库，也难以在不引入依赖的前提下实现设备签名与配对凭据共享，因此首期只提供数据面；扩展方式须另立 ADR。不得把“六语言都支持管理面”写成首期承诺。
- SDK 不得把任何密钥写入日志、指标或异常消息；它本身不持有中继密钥。
- SDK 不得读取审批队列中其它主体的申请，不得代替管理员批准或拒绝。
- 拒绝、过期、取消与撤销对 SDK 是可区分终态，必须能报告可读原因。

### FR-41 平台、语言与交付

- 语言基线：C#/.NET、Java、Python、TypeScript/Node、Go、Rust；具体最低版本在设计文档中固定，不在本需求内逐版本承诺。
- 操作系统基线：Windows 10 与 Windows Server 2019 以上、主流 Linux 发行版（glibc 与 musl 分别说明）、macOS 12 以上。移动端不在本需求内。
- 所有语言使用同一份接口契约来源；方法语义、错误码与字段名在各语言间保持一致，接口形状按语言惯例适配（这两件事不矛盾：形状可惯用，语义必须一致）。
- 每语言实现保持最小依赖，优先纯托管或无原生扩展方案；不得因 SDK 引入服务端或 Agent 的运行依赖。
- SDK 版本独立于文档版本、`schemaVersion` 与线协议版本；同时支持的自动化 API 版本区间必须写明，并至少兼容前一个次版本。
- 发布物附校验和与来源证明，发布流水线在 CI 内产出，不依赖人工上传。
