## 背景与范围

Windows Agent 以 LocalService 运行，缺失事件源时无法自行注册 Windows Event Log 来源，导致连接告警未持久化；注册被拒绝时，原日志只有通用消息，无法区分密钥、身份和重复会话问题。本需求统一 Server 与 Agent 的运行文件日志、拒绝原因及排障信息。

本文汇总此前明确采纳的 Agent 文件日志决定，以及服务端文件日志与拒绝诊断需求。Accepted 表示需求已采纳，不代表全部目标环境验收完成；实际证据与未完成项见[验证状态](../testing/verification-status.md)。SQLite 审计、流量历史、逐业务连接诊断继续承担原有职责。

## FR-24 统一运行文件日志

- Server 与 Agent 使用日志库写入结构化文件；正常服务运行不依赖控制台或 Windows Event Log 事件源，覆盖启动、宿主异常、控制会话及已有业务运行日志。本机 Agent Web 后端共用 Agent 日志管道，配置保存失败须记录底层文件系统异常，页面保持通用错误响应。
- Info/Warning 普通日志保留 14 天；Error/Critical 错误日志永久保留，即程序不按时间或文件数量自动删除。两类分别输出，并按天或单文件达到 10 MiB 时轮转；轮转不能覆盖旧错误文件。默认不启用 Debug/Trace，不要求归档压缩或新增日志查询页面。
- 过期普通文件在后续打开或轮转时清理；停机期间不要求后台清理。正常退出须关闭并刷新文件；文件系统拒绝写入或磁盘已满时允许将日志库内部错误输出到标准错误，不承诺故障期间持久化成功。
- Agent 默认写入配置目录的 `logs/`，标准 Windows 安装为 `C:\ProgramData\RelayLink\Agent\logs`；升级、重新配置及卸载保留运行日志。Server 默认使用配置目录的 `logs/`，支持指定独立日志目录；Docker 与 systemd 模板使用持久化数据目录，升级和重启保留日志。
- 日志目录受服务账号权限保护，程序安装目录只存程序。运维负责错误日志备份、磁盘容量和人工清理；“永久保留”不包含抵抗人为删除、存储损坏或主机丢失。

## FR-25 明确控制连接拒绝原因

- 在可返回协议错误帧的注册及配置确认阶段，服务端提供固定原因标识，区分客户端不存在、停用、密钥错误、无效身份、已固定身份不匹配、重复会话、无效首帧、配置确认不一致及注册期间配置变更。
- Agent 读取注册、配置确认及在线控制循环中的服务端错误帧，记录错误码、固定原因、阶段和本机服务端归属；可读解释由本地固定映射生成。服务端运行日志记录相同拒绝原因、客户端 ID 和可用的来源地址，并保留既有拒绝审计。
- 不返回提交或期望的密钥、身份指纹值、配置正文、异常堆栈或自由文本。未知原因、未知错误码或畸形错误详情使用安全回退，不将远端原始载荷直接写入日志。
- 兼容原有 v3 错误帧和既有错误码；旧服务端未提供具体原因时，Agent 仍记录错误码并提示查看服务端审计。精确原因须两端都更新后生效。
- TLS 未建立、帧头不合法或认证前连接配额已满时，允许直接关闭连接，不为返回原因而绕过资源限制或额外建立 TLS。Agent 记录本地异常，服务端记录可用的失败或容量原因。
- 拒绝与自动重连仍为 Warning，采用普通日志保留策略；认证、身份固定、慢速重试和多服务端故障隔离规则保持既有语义。

## FR-26 诊断关联与敏感信息边界

- 运行日志包含时间、级别、消息及必要的异常；关联信息按事件提供：Agent 服务端级事件包含 `profileId`、`clientId`，会话或业务事件提供可用的 session/connection/channel/mapping ID。进程启动等全局事件无需伪造客户端归属。
- 不记录密码、注册密钥、访问密钥、令牌、CA 正文、证书私钥、完整配置、请求正文、业务载荷或 SQL 文本。文件系统异常可保留错误类型、堆栈和路径，HTTP 响应不暴露这些底层详情。
- 原有 Agent 逐业务连接 JSONL 继续记录阶段、字节计数、耗时和错误类型，按服务端归属隔离，采用 4 MiB 与一个历史文件的有界轮转；它不替代控制连接告警。
- 运行日志不替代 SQLite 审计、审计放行门槛或分钟流量历史，不新增业务重放、运行日志管理页面、外部日志服务或动态日志配置。

## 验收标准

沿用 A72–A74，不因文档归档而重编号；原需求文档保留链接。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A72 | Agent 写入不同级别日志，模拟过期文件、达到大小阈值并重启；制造配置保存失败 | Info/Warning 与 Error/Critical 分文件；普通日志超过 14 天可清理，错误日志跨时间及多次轮转仍保留；重启追加，归属和异常可定位；保存失败页面返回通用错误且日志不泄露凭据 |
| A73 | 分别制造不存在、停用、错误密钥、无效或变更身份、重复会话及错误配置确认，并查看两端日志；读取旧和未知错误详情 | 服务端返回准确固定原因，Agent 记录错误码、原因和配置项归属；旧帧兼容，未知详情安全回退，日志无凭据或载荷；不能返回错误帧的情况保持资源限制 |
| A74 | Server 写入普通与错误日志，模拟过期和大小轮转，再重启；指定日志目录并执行配置预检 | 普通日志保留 14 天、错误日志不自动清理，按天及 10 MiB 轮转；服务账号可写指定目录，预检无日志副作用；Docker/systemd 使用持久化目录，SQLite 审计行为保持既有要求 |
