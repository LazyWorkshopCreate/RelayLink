## 1. 项目目标

使用 .NET / C# 开发一套反向 TCP 代理服务，使云端内网业务服务能够访问分布在不同网络中的 TCP 服务。Windows、Linux 或 macOS 客户端主动向 Linux/Windows 服务端建立连接，无须为客户端所在网络配置公网入站映射。

云端服务器具有公网 IP，控制端口和独立数据端口允许 Agent 接入；业务代理端口、管理仪表盘仅供云端局域网/VPC 内访问。云安全组或防火墙负责网络边界；普通通道可额外使用应用层安全组限制来源 IP，不替代部署环境的网络访问控制。

## 2. 已确定需求与设计假设

### 2.1 用户已确定的需求

| 编号 | 需求 |
|---|---|
| U01 | .NET 和 C# 技术栈 |
| U02 | 服务端运行在有公网 IP 的 Linux 或 Windows 云虚拟机 |
| U03 | 控制和数据接入端口供 Agent 访问，业务调用和仪表盘走内网 |
| U04 | Agent 运行在 Windows、Linux 或 macOS；Windows 以 Windows Service、Linux 以 systemd、macOS 以 launchd 托管，也可用控制台调试 |
| U05 | 首期仅支持 TCP，主要代理各地 SQL Server |
| U06 | 仪表盘匿名只读，按客户端分组展示通道、状态与流量历史；管理员登录后可管理客户端与通道配置 |
| U07 | 注册必须提供密钥，每客户端一个独立密钥，由服务端配置维护 |
| U08 | 通道由服务端集中维护，每客户端一个 JSON 文件 |
| U09 | 客户端认证后获取通道；客户端本地不维护通道配置；管理保存后服务端自动下发新快照 |
| U14 | 控制与数据连接使用独立端口；只有控制会话完成认证和配置确认后，才能按需建立绑定到该会话的数据连接 |
| U15 | 普通代理数据通道以简单双向 TCP 字节复制为基线；加密或额外业务数据封装须经过对应业务实验验证后才引入 |

### 2.2 本设计采用的默认决策

以下为便于形成可实施方案的建议，不代表已经获知实际规模。

- 首期单实例服务端；不提供集群、自动故障切换和跨节点迁移。
- 使用 .NET 10 LTS，具体 Windows/Linux/macOS 版本须在实施前按官方支持矩阵核对。
- 一个客户端代表一台 Windows、Linux 或 macOS 代理进程，可代理该设备可访问的多个 TCP 目标。
- 一个通道对应一个固定的“服务端 IPv4 监听地址:端口 → 客户端侧目标主机:端口”；新增普通通道默认监听 `0.0.0.0`，可改为具体内网地址。
- 控制连接默认使用 TLS；服务端 `tunnel.tlsEnabled` 与 Agent `useTls` 同时设为 `false` 时允许纯 TCP，密钥仍参与身份认证。普通数据入口当前使用原始 TCP，不受上述 TLS 开关保护；仅适用于受信隔离链路或业务协议自身提供端到端 TLS 的场景。安全组不替代传输加密。
- 服务端启动时加载配置；仪表盘保存会校验并原子写入对应客户端文件、更新服务端监听，并向在线 Agent 下发新快照。客户端重连也获取当前快照。
- 仪表盘匿名访问仅提供只读数据；管理员使用服务端配置中的账号登录后可新增、删除、修改或禁用通道。
- 服务端把普通与端到端通道的分钟级流量增量持久化到 SQLite，默认保留 90 天；仪表盘可匿名查看历史，但不记录业务载荷、SQL 内容或凭据，也不作为计费依据。
- Agent 主机必须保持运行和联网，才能持续代理。

## 3. 术语和访问模型

| 术语 | 含义 |
|---|---|
| 服务端 | Linux 或 Windows 云服务器上的代理服务程序 |
| 客户端 | 各地 Windows、Linux 或 macOS 上的代理程序，以下也称 Agent |
| 访问方 | 云端内网中调用数据库的业务服务 |
| 通道 | 服务端代理监听端点与远端目标端点的一条配置映射 |
| 控制连接 | Agent 发起的长期连接，默认使用 TLS，用于注册、配置、心跳和授权建立数据隧道 |
| 数据隧道 | Agent 发起到独立数据端口的 TCP 连接，完成一次性令牌绑定后每条仅承载一条业务连接 |
| 会话 | 一次成功认证并完成配置确认的 Agent 在线周期 |

例如：云端应用访问 `10.20.0.10:21433`，服务端通过上海 Agent，将字节转发至该 Agent 可访问的 `192.168.10.20:1433`。另一个地点可以同样使用 `192.168.10.20:1433`；两者通过不同的客户端身份和云端代理端口区分。

注意：通道不是单条数据库连接。一个通道可同时承载多条连接，每条连接有独立数据隧道。

## 4. 功能需求

### FR-01 客户端注册与身份

- 客户端本地仅配置服务端地址、控制端口、数据端口、客户端 ID、密钥和本机运行参数。
- ID 必须在服务端预先存在；不允许匿名注册或自动创建客户端。
- 密钥错误、客户端禁用、协议版本不兼容均不得建立可转发会话。
- 认证前不得返回通道信息；认证后只返回该客户端自己的配置。
- 同一客户端 ID 仅允许一个有效会话。新连接不得挤掉仍存活的旧会话；旧会话判定离线后允许重连。
- 密钥、数据隧道令牌不得进入日志、仪表盘和统计接口。

### FR-02 配置集中管理

- 服务端统一维护基础配置与客户端目录，目录中每客户端一个 JSON 文件。
- 每个客户端文件包含身份、启用状态、独立密钥、客户端连接上限和通道集合。
- 通道至少包括唯一 ID、名称、启用状态、服务端监听地址/端口、目标地址/端口、连接上限和目标连接超时。
- 管理端新增普通通道时，服务端监听地址默认填 `0.0.0.0`（所有 IPv4 网卡）；监听端口由服务端从 `19000` 起跳过已分配及当前无法绑定的端口后建议并自动填入，管理员仍可手动修改。建议不预留端口，保存时须再次校验和绑定；若被其他进程抢占，应清晰报错，不静默改端口。业务调用方应连接服务端实际可达 IP 或域名，不能连接 `0.0.0.0`。业务端口的可达范围由安全组或防火墙限制。
- 相同服务端监听端点不能分配给多个启用通道；不能占用控制入口、数据入口或仪表盘端点。
- Agent 只在内存中使用服务端下发的通道快照；获取失败不得用旧的落地缓存启动转发。
- 仪表盘保存的通道新增、删除、禁用、端口或目标变化会立即更新监听并下发给在线 Agent；通道任何字段实际变化时，须断开该通道的既有连接，相同内容重复保存不得断开。手工改文件和密钥轮换仍须安排重启。
- 配置语法错误、重复 ID、无效字段和端点冲突必须在启动时明确报错；不得静默忽略。

### FR-03 TCP 转发

- Agent 主动连接服务端控制端口；每条已获授权的业务连接按需主动连接独立数据端口。两个入口不接受对方的首帧类型。
- 服务端不得主动拨号连接 Agent 公网地址。
- 支持二进制、双向、长连接及多个并发连接，保留字节内容与方向内顺序。
- 普通代理完成数据连接绑定及目标就绪握手后直接复制原始 TCP 字节，不再对业务内容分帧或加密；敏感业务必须由业务自身 TLS 或部署网络提供保密性与完整性。
- 不解析、修改或重试 SQL/TDS 内容，不注入 PROXY protocol 等业务前导字节。
- 服务端收到业务连接后，通知指定 Agent 建立数据隧道并连接目标。
- 目标未就绪之前不得向目标发送业务字节；等待受时间和数量上限约束。
- 目标不可达、Agent 离线、容量已满、建立隧道超时，应及时关闭该业务连接，不返回自造 SQL 报文。
- 支持 TCP 半关闭：一方发送结束后，另一方向仍可返回剩余数据。
- 数据隧道断开会终止对应业务连接；不恢复原 TCP 连接、不重放 SQL、不自动恢复事务。

### FR-04 生命周期与恢复

- Agent 在 Windows 支持 Windows Service，在 Linux 支持 systemd，在 macOS 支持 launchd 开机启动，也支持控制台运行用于调试。
- 服务端在 Linux 由 systemd 托管，在 Windows 由 Windows Service 托管。
- 控制心跳建议每 15 秒一次，45 秒未收到对应响应判离线。
- 普通网络错误采用带随机抖动的指数退避重连，最大间隔 30 秒。
- 认证失败、重复会话、配置不兼容等明确错误采用较慢重试，避免持续快速请求。
- 控制会话断开后停止该客户端新连接接入，并清理其待建立和已建立数据隧道。
- 恢复后只接受新的业务连接，旧业务连接由应用重新打开。
- 默认不因正常连接长时间没有 SQL 流量而回收它；长查询和连接池空闲连接需要正常工作。

### FR-05 仪表盘与通道管理

首页按客户端分组展示通道，支持按 ID/名称搜索及状态筛选。管理端作为独立前端项目构建，由 Server 同源托管；建议每 5 秒拉取一次快照，编辑弹窗打开时暂停自动刷新。全量刷新必须使用分页聚合快照，一次返回该页客户端、通道和访问入口，不得按每个客户端分别轮询子资源；后续分页须限制并发，同一页面不得重叠执行多个刷新周期。前端技术选型见 [ADR-0004](../adr/0004-standalone-admin-web.md)。

| 层级 | 必需字段 |
|---|---|
| 总览 | 服务启动时间、客户端在线数/总数、可接入通道数/总数、当前活动连接、上下行速率 |
| 客户端 | ID、名称、启用状态、会话状态、Agent 版本、上线时间、最后心跳、心跳 RTT、最近断线原因 |
| 通道 | ID、名称、服务端端点、目标端点、启用状态、监听状态、可接入状态、目标最近连接结果和时间 |
| 连接统计 | 待建立数、活动数、接收总数、建立成功数、建立失败数、建立后异常结束数 |
| 流量统计 | 两个方向累计字节及近 5 秒平均速率 |

必须明确以下区别：

- **客户端在线**：控制会话正常，配置已经确认。
- **通道可接入**：通道已启用、端口监听成功且对应客户端在线；不代表 SQL 登录成功。
- **目标最近可达**：最近一次实际 TCP Connect 成功；不是持续探测，也不代表数据库授权或查询健康。
- **未知**：尚无目标连接记录，或 Agent 已重连、断线，原记录只能作为历史参考显示。

页面显示统计起始时间和数据刷新时间。获取失败时保留旧数据并标识过期，不将旧状态继续当成实时结果。

- 所有上述查询和仪表盘页面无需登录，且不得返回客户端密钥、令牌或管理员密码哈希。端到端访问入口也在匿名只读页面按客户端以表格展示；公开查询只返回入口 ID、启用与当前上报状态、本机地址及目标客户端/通道，不返回访问密钥、证书私钥或访问方固定的目标证书指纹。
- 管理员账号由 `server.json` 的 `dashboard.admin` 配置，密码仅保存为 PBKDF2-SHA256 哈希；登录后使用短期 HttpOnly 会话 Cookie 与 CSRF 令牌。
- 登录后可添加、编辑和禁用客户端，并下载创建时生成、以后可再次下载的 Agent 配置文件；客户端密钥只出现在受保护的下载响应和服务端配置文件中，不进入匿名查询 API。
- 顶部“实时监控”旁仅登录后显示“安全组”入口，点击弹窗查看、添加、编辑、删除安全组。每组至少包含一个 IPv4/IPv6 单地址或 CIDR；普通通道可选择一个安全组，不选择表示允许任意来源。设置后只按 TCP 连接的实际来源地址放行，拒绝不匹配者；修改规则后撤销不再允许的存量连接。被通道引用的安全组不得删除，需先解除引用；端到端专用通道不使用此来源规则。
- 禁用客户端须完整保存其配置，不因其他客户端已有端到端访问入口而拒绝；立即停止该客户端的云端通道监听，撤销其作为访问方或目标方参与的全部待建立及已建立连接，关闭控制会话，并拒绝后续业务连接和认证。访问入口与通道配置保留，重新启用后按原配置恢复。
- 启用 TLS 时，服务端从自身配置的 CA 公钥证书生成下载配置中的 Base64 信任材料；管理员不填写 Agent 本机 CA 路径，Agent 不依赖操作系统根证书库。
- 登录后可新增、删除、修改或禁用通道（显示名、监听和目标端点、连接上限及目标连接超时）。实际变更时须校验完整配置并原子替换对应客户端 JSON、更新服务端监听、向在线 Agent 下发带版本号的配置快照，并仅断开变更通道的待建立与已建立连接；相同配置重复保存不得中断连接。访问入口删除时仅断开该入口的已有端到端连接。
- 点击通道流量数值后弹窗显示按客户端与通道聚合的历史流量图；不展示业务载荷。历史值是每分钟窗口内两个方向的增量字节；端到端通道只统计服务端可见的密文 DATA 载荷字节，不作为计费依据。
- 未登录的写操作必须被拒绝；不提供修改客户端密钥或运行时启动/停止通道的独立 HTTP 接口。

### FR-06 运维与诊断

- 提供配置检查命令，在正式启动前校验结构、范围、重复和静态冲突。
- 提供结构化日志，按客户端、通道、会话和连接 ID 关联。
- 区分认证失败、端口占用、目标拒绝连接、DNS 失败、超时、数据中断和容量限制。
- 服务端离线客户端仍保留在仪表盘中，不因断线消失。
- 提供只读存活与就绪检查；就绪表示服务本身完成配置和监听初始化，不要求全部远端 Agent 在线。

## 5. SQL Server 接入要求

1. 在目标 SQL Server 启用 TCP 并设置固定端口。访问方使用 `tcp:服务端内网地址,代理端口`，不依赖实例自动发现。SQL Browser 使用 UDP 1434，超出首期 TCP 范围。[SQL Server 官方连接排障说明](https://learn.microsoft.com/en-us/troubleshoot/sql/database-engine/connect/network-related-or-instance-specific-error-occurred-while-establishing-connection)
2. SQL 登录和权限仍由数据库负责，代理不持有数据库账号密码。
3. SQL TLS 与 RelayLink 控制 TLS 是不同机制；普通数据通道不再提供外层 TLS，敏感数据库连接须启用 SQL 自身 TLS。使用代理地址连接时，要验证数据库证书名称是否匹配；支持的 SqlClient 可配置 `HostNameInCertificate`。[SqlClient 官方属性说明](https://learn.microsoft.com/en-us/dotnet/api/microsoft.data.sqlclient.sqlconnectionstringbuilder.hostnameincertificate?view=sqlclient-dotnet-core-6.1)
4. 首期验收以固定 TCP 端点、SQL 认证为基准。Windows 集成认证、Kerberos/SPN、Always On 路由、故障转移、多子网和额外反向连接不纳入首期兼容承诺，需要专项验证。
5. 代理不会降低全国链路物理 RTT；业务需控制频繁串行数据库往返，合理使用连接池和批量查询。

## 6. 非功能需求与容量基线

### 6.1 正确性和资源控制

- 数据无篡改、无跨连接混流、无跨客户端配置泄露。
- 慢读写必须通过有界缓冲和背压控制内存；不能无限排队。
- 一个目标或一条数据隧道失败不能关闭其他通道；整个控制会话断开只影响所属客户端。
- 不记录业务载荷、SQL 语句及数据库凭据。
- 首期不保证服务器故障时服务连续；进程重启会断开所有存量业务连接。

### 6.2 建议压测基线（尚未实测，不是容量承诺）

| 项目 | 建议初始目标 |
|---|---|
| 服务端测试资源 | Linux 或 Windows 4 vCPU、8 GiB、1 Gbps 网卡，记录实际 CPU 型号和带宽限制 |
| 配置规模 | 100 个客户端，每个 5 个通道，共 500 个通道 |
| 总活动业务连接 | 1,000 条，另测突发连接建立 |
| 聚合有效载荷 | 100 Mbps，两方向字节之和；分别测试大块与小包 |
| 稳定性 | 连续 24 小时，预热后内存、句柄、任务数无持续增长 |
| 突发 | 100 个新连接/秒持续 60 秒，记录成功率和排队情况 |
| 健康链路成功率 | 指定容量内建立成功率至少 99.9%，排除明确注入故障的时间窗 |
| 时延 | 分别在 RTT 20/80/150 ms 下测业务连接建立 P50/P95/P99；不预设跨地域毫秒承诺 |
| 故障感知 | 控制黑洞在最后有效心跳后约 45 秒内识别；活动阻塞写按技术文档超时释放 |
| 仪表盘 | 100 客户端/500 通道快照读取 P95 小于 1 秒，刷新周期 5 秒 |

建议配置默认总连接上限 2,000，属于保护阈值，不能当作已证明的生产容量。部署前按真实 SQL 连接池总量与公网出口限制校准。

## 7. 验收标准

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A01 | 正确/错误密钥注册 | 正确身份收到自己的配置；错误身份没有配置或代理权限 |
| A02 | 同 ID 启动两个 Agent | 已在线会话保持，新会话明确被拒；离线判定后可重新注册 |
| A03 | 抓取 Agent 网络连接元数据 | 控制与数据分别连接服务端的控制和数据端口，没有服务端反向拨号 |
| A04 | 两地配置相同目标内网 IP | 云端不同代理端口准确访问各自目标，无串流 |
| A05 | 修改配置不重启，再重启 | 重启前原快照不变；重启后重新下发新快照 |
| A06 | 无效 JSON、重复端口、端口被外部占用 | 检查或启动明确失败，日志指出位置；不部分运行冒充成功 |
| A07 | 随机二进制大流与并发双向流 | 两端长度和哈希一致，内存受限 |
| A08 | 发送端半关闭，接收端延迟返回 | 返回数据完整，另一方向不会被提前关闭 |
| A09 | 目标拒绝、DNS 失败、超时 | 单连接按时失败，统计分类正确，其他目标不受影响 |
| A10 | 断网、黑洞、Agent 崩溃、服务端重启 | 及时回收资源，自动重连，新连接恢复；旧连接不被假装恢复 |
| A11 | 长查询及连接池闲置后查询 | 健康链路正常工作，不被短业务空闲超时误杀 |
| A12 | SqlClient 连接并执行查询/事务/大结果集 | 固定端口访问成功，数据正确；中途断网返回错误且不重放事务 |
| A13 | 重复、过期、跨会话数据令牌 | 全部被拒绝，不关联到其他连接 |
| A14 | 超上限和慢读客户端 | 快速拒绝或有界等待，恢复后计数和资源正确 |
| A15 | 仪表盘和 API | 匿名只读且不含密钥；登录与 CSRF 生效；客户端增改禁、通道增改禁删按授权生效并下发；配置可下载；历史图表按客户端/通道展示，状态和字节方向一致 |
| A16 | 容量与 24 小时压测 | 达到约定环境基线并提供结果；未实测值不标为已通过 |
| A17 | 安全组实机连通验证 | 控制和数据入口仅供 Agent 可达，内网可访问业务端口和仪表盘；明文数据入口的网络保护方案有证据 |

## 8. 首期不包含

UDP、SQL Browser、HTTP 域名路由、SOCKS、VPN/IP 层组网、P2P 打洞、客户端远程升级、SQL 审计、数据库健康查询、告警发送、集群和无损会话迁移。通道运行时配置和历史统计已由后续明确需求纳入，参见 [ADR-0002](../adr/0002-runtime-channel-configuration.md) 与 [ADR-0003](../adr/0003-traffic-history-persistence.md)。

## 9. 实施前需要补齐的信息

这些信息影响部署和性能验收，不阻碍按当前设计开始原型。

- 实际客户端/通道数量、每个数据库峰值连接数、连接池配置和数据流量。
- Windows 版本及架构、SQL Server 版本、驱动版本、SQL TLS 和认证方式。
- 目标云服务器 Linux 发行版、内网地址、可用代理端口范围、公网带宽。
- 全国站点是否允许到控制端口的 TCP/TLS 及独立数据端口的 TCP 出站；仅允许 HTTP 代理的站点需要额外方案。
- 是否需要长期历史、业务告警或高可用；这些作为后续范围单独评估。
