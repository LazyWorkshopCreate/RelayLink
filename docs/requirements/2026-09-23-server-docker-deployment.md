## 背景

Linux Server 需要在保留原生 systemd 部署方式的同时，提供可重复的一键 Docker Compose 启动入口。现有安装与使用指南的信息密度过高，需要按部署场景和操作步骤重组。

## FR-18 Docker Compose 交付

- 提供可从仓库源码构建 Server 和管理前端的多阶段 Dockerfile。
- 提供 Linux Docker Engine 使用的 Compose 配置，一并持久化服务端配置、客户端文件和 SQLite 数据。
- 普通通道端口由运行配置动态决定，Compose 必须避免固定端口清单阻断新增通道。
- 提供首次初始化、启动和停止脚本；初始化时生成管理员密码哈希，不保存明文密码，也不覆盖已有配置和数据。
- 容器日志应设置轮换上限，停止服务不得默认删除持久化数据。
- 安装文档按部署方式、配置、Agent、通道、排障和升级拆分为短步骤、表格及命令块。

## 验收标准

| ID | 标准 |
|---|---|
| A58 | `docker compose config` 能解析配置，服务使用 host 网络并挂载配置及数据库目录。 |
| A59 | 首次启动脚本生成不含明文管理密码的配置；重复运行保留已有配置；停止脚本保留数据。 |
| A60 | 在 Linux Docker Engine 完成镜像构建、配置预检、容器启动、就绪检查、重启持久化和动态普通通道转发。 |

## 安全边界

- Compose 仅支持 Linux Docker Engine；host 网络意味着端口直接绑定宿主机，仍须配置主机防火墙或云安全组。
- 入门配置可关闭 TLS 以便受控环境验证，但生产环境和 Agent 互访必须按部署文档启用控制 TLS。
- 真实配置、密码哈希、客户端密钥、证书私钥和数据库均保存在被 Git 忽略的本地目录，不进入镜像或仓库。
