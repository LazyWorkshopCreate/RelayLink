## FR-12 Linux Agent 与服务端管理页互访（2026-09-20）

- 提供 `linux-x64` 自包含 Agent 发布包和 systemd 服务模板。Linux Agent 与 Windows Agent 使用同一配置 schema、线协议、通道模型、互访加密开关、端口状态和本机只读状态页，不引入 Linux 专用通道语义。
- Linux Agent 程序目录由 root 管理；包含独立客户端密钥的配置、自动生成的端到端身份、端口状态和诊断日志位于仅 Agent 服务账号可读写的状态目录。升级程序不得隐式覆盖或删除这些状态。
- 当 Linux Agent 与 Server 部署在同一主机时，可将 Server 管理页仅绑定 `127.0.0.1:18080`，再为该 Agent 配置目标为 `127.0.0.1:18080` 的普通授权互访通道。获准访问的其他 Agent 通过既有端到端访问入口访问；不得为管理页面增加绕过通道授权、证书固定或访问密钥证明的特殊路径。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A42 | 发布 `linux-x64` Agent，并以 systemd 服务账号启动、重启和停止 | 配置检查成功，服务自动启动并优雅停止；程序目录不可写，状态文件权限受限；重启复用身份和本机入口端口 |
| A43 | Linux Agent 创建目标为 Server `127.0.0.1:18080` 的授权通道，仅给指定访问方创建入口 | 指定访问方可从本机 loopback 打开管理页；无映射或错误证明的客户端不能连接目标；管理端口无需对外开放；默认加密时服务端中继只见互访密文 |

## FR-13 macOS Agent（2026-09-20）

- 提供 `osx-x64`（Intel）和 `osx-arm64`（Apple Silicon）两个自包含 Agent 发布包与 launchd 服务模板；macOS 不增加 Server 发布包。
- macOS Agent 与 Windows、Linux Agent 使用同一配置 schema、线协议、通道模型、互访加密开关、端口状态和本机只读状态页，不引入 macOS 专用通道语义。
- 程序目录由 root 管理，launchd 使用独立低权限账号运行；配置、客户端密钥、自动生成的端到端身份、端口状态和诊断日志只能由该服务账号读写。升级程序不得隐式覆盖或删除这些状态。
- 初始压缩包未做 Developer ID 签名和 Apple 公证。生产分发须按组织策略完成签名、公证和 Gatekeeper 验证，不以关闭 Gatekeeper 作为安装步骤。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A44 | 分别发布 `osx-x64` 与 `osx-arm64` Agent，并在对应架构 macOS 上以 launchd 启动、重启和停止 | 两个产物架构正确；配置检查成功，服务自动启动并优雅停止；程序目录不可写，状态文件权限受限；重启复用身份和本机入口端口 |
| A45 | Intel 与 Apple Silicon Agent 分别完成普通通道和授权互访连接，并执行错误密钥、断网重连、睡眠/唤醒及 Gatekeeper 检查 | 协议和授权行为与其他平台一致，无平台专用通道或明文回退；资源最终释放，恢复后仅建立新连接；签名/公证状态与安装策略一致 |
