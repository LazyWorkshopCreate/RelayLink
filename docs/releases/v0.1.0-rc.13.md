# RelayLink v0.1.0-rc.13

这是在 v0.1.0-rc.12 之后引入可审计通道（插件系统）、协议 v7 和凭据库的候选版本。可审计通道覆盖 HTTP/HTTPS 与 SSH 两类应用，支持服务端可视互访与跳板代理；RDP 数据面、完整审批闭环和桥应用仍未实现。

## 主要更新

- **两种可审计通道**：`server-peer`（服务端可视互访）和 `server-jump`（服务端跳板代理）。通道类型在创建时锁定；应用标签 `app:ssh`、`app:rdp`、`app:http`、`app:https` 只接受规范小写值，混合大小写、重复或非规范值明确报错。
- **协议 v7**：线协议从 v5 升到 v7。v6 引入 `inspectionMode`、派生 `application` 和目标腿 TLS/访问证明；v7 增加 `InspectionActive`（25）与 `InspectionTargetReady`（26）阶段通知，区分目标就绪与业务 active。Server 继续接受 v3–v6 的原有 `none` 能力；可审计通道只下发给 v7，server-peer 要求双方 v7，server-jump 要求目标 v7。
- **HTTP/HTTPS 逐请求检查**：使用 Kestrel 虚拟连接和 YARP 转发，每个 HTTP/1.1 请求单独解析、匹配策略、必要时等待审批并写入审计后才转发。覆盖 Content-Length、chunked、keep-alive、流水线、`Expect: 100-continue`、临时响应和 WebSocket 升级；CL/TE 冲突、重复 Host/Content-Length、CONNECT 和非 origin-form 等歧义请求失败关闭。HTTPS 校验上游 TLS，自定义 CA 仍要求 serverAuth 用途和名称匹配。
- **SSH 检查**：按通道固定目标主机 SHA-256 指纹，目标主机认证通过后才读取并发送目标凭据。允许决定先持久化审计，再连接目标或执行 shell/exec/subsystem；每次动作前都有对应审计，拒绝审计失败仍保持拒绝。每个 caller channel 独立保存 pty/env/window-change/signal，并有 32 channel、64 KiB 初始化、64 并发请求等上限；未桥接的 TCP/agent/X11 forwarding 明确拒绝。
- **生命周期与资源**：建立、首头、审批和目标连接使用分阶段期限；首次 pending 持有到业务 active 后释放，后续审批使用有界租约且不重复计算连接。故障双向 abort、正常半关闭排空、空闲回收和阻塞写期限在 Server 与 Agent 两端一致；管理员断开或配置撤销会回收容量。
- **审计与计量**：HTTP 每个请求记录 decision/response（状态码、双向字节、请求关联）；SSH channel 关闭记录退出码/信号和字节；peer/proxy 连接关闭有最终字节快照。新增 `applicationToTarget`/`applicationToCaller` 业务字节口径，与 `peerCiphertext*` 分离；分钟历史只追加列，不改写旧行。
- **凭据与秘密库**：通道凭据与配置 JSON 分离，保存在加密秘密库。变更按“持久化意图、原子替换、记录结果”执行，操作 ID 支持幂等重试和 24 小时回执过期；结果审计失败由后台对账补齐。删除通道或客户端会写可恢复删除标记并清理旧凭据和前门主机键，同 ID 重建不会继承旧秘密。
- **配置与管理面**：可审计通道在文件加载和 API 保存时要求控制 TLS；server-peer 可用性按双方 v7、readiness、地址、映射和目标材料判定。RDP 审计入口禁止新建和重新启用，存量可停用/删除；缺少证书材料的 HTTPS 不允许新建，但已有文件配置仍可编辑。相对证书路径在编辑后保持原文，配置目录搬迁后重新解析。
- **Agent 本机页**：显示本机互访入口的在线状态并支持复制地址；修复互访入口表格的横向滚动条。按 ADR-0034 移除“本机管理令牌”输入框和 `X-RelayLink-Local-Token` 要求，写请求继续校验 Host、Origin、短期 HttpOnly SameSite=Strict 会话与 CSRF。
- **文档与验证**：新增 ADR-0030–ADR-0034、插件系统需求/设计（仍为 Draft/Proposed）、TST-009–TST-013 专项验证记录和配置示例。本机单元 358/358、集成 156/156（含真实 v3/v4/v5 旧 Agent）；tag 上会重新执行 CI 与发行构建。

## 升级与兼容性

- 先升级 Server，再升级需要使用可审计通道的 Agent。可审计通道要求协议 v7；旧的 v3–v6 Agent 继续使用原有 `none` TCP/UDP/HTTP，不需要为了普通转发同时升级。
- 现有通道配置无需改写；但可审计通道需要控制 TLS，SSH 通道需要管理员预先登记目标主机指纹，HTTPS 通道需要配置文件中的证书材料。
- RDP 审计通道不能新建或重新启用；已有配置可查看、停用和删除。完整 RDP 数据面、管理员批准页面、凭据发放、桥应用及证书/策略编辑表单仍未实现，不能把当前的“等待后拒绝”当作审批闭环。
- Agent 本机写接口不再要求管理令牌。同机任何能打开 `127.0.0.1:18081` 的用户都可以修改该 Agent 的连接配置，因此只适用于单用户主机或由管理员操作的主机；多用户主机不要用 LocalSystem 或 root 运行 Agent。
- 管理页与 Agent 状态页仍只监听回环地址并使用明文 HTTP；本版本不改变普通代理、UDP 和目标 Agent HTTP 的处理位置。

## 验证与限制

- 本机 Windows 完成后端单元 358/358、包含真实 v3/v4/v5 的集成 156/156，前端检查与网站构建通过；最终跨平台结果以 tag 对应的 CI 和发行流水线为准。
- 本候选未在 Linux/macOS 原生环境重新执行完整集成，也未执行容量压测或跨主机灾难恢复；这些边界不因本机通过而消除。 macOS 原生集成测试暂排除两条 inspection 半关闭用例（`PluginLifecycleTests.Client_half_close_drains_the_reverse_response_and_ends_completed` 与 `PeerConnectionTests.Server_jump_relays_plaintext_over_target_leg_tls_and_blocks_unhandled_applications`）：macOS 上这两条路径的反向响应仍会丢失，属已知未修复问题；Windows/Linux 继续全量执行。
- 插件系统需求 REQ-001O 和设计 DES-009 仍为 Draft，ADR-0028/0029 仍为 Proposed；本版本不把它们写成已完成验收。
