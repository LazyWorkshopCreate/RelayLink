# RelayLink v0.1.0-rc.14

本版本正式放弃插件系统（服务端应用层审查通道与客户端 Bridge）开发，通过反向提交彻底清理相关代码与文档，回归纯代理定位；同时合入 Agent 本机页原生工具入口（ADR-0042）、AI 自动化管理面与多语言 SDK 源码基线，以及 CI 和发行改进。

## 主要更新

- **放弃插件系统开发，回归纯代理定位**：正式放弃自 `v0.1.0-rc.13` 尝试的服务端应用插件与可审计通道路线，以及后续实验性的客户端 Bridge 与内部自签代码签名方案。已通过反向提交彻底移除服务端可审计通道（`server-peer`、`server-jump`、HTTP/HTTPS 与 SSH 逐请求/动作检查、凭据库、审批、协议 v6–v7）、`RelayLink.Bridge`、Bridge 安装/打包/签名脚本及对应需求、设计与 ADR 文档，仅保留 `v0.1.0-rc.13` 历史发布日志。项目重新聚焦纯代理定位：普通 TCP/UDP 转发、授权端到端互访、目标 Agent 侧 HTTP/HTTPS 反向代理、应用层安全组与连接生命周期审计。
- **线协议与配置回归 v3–v5**：服务端线协议回归并稳定在 v3–v5，继续兼容既有 v3–v5 Agent（v3 TCP、v4 UDP、v5 目标 Agent HTTP/HTTPS 反向代理）。配置加载与通道管理 API（`ChannelCreateRequest` / `ChannelUpdateRequest`）严格拒绝未知字段（含已废弃的插件与审计通道字段）；分钟流量历史写入改用显式列名，兼容已有含额外列的 SQLite 历史库。
- **Agent 本机页原生工具入口（ADR-0042）**：移除独立客户端 Bridge 后，Agent 本机状态页直接为在线、已就绪的互访入口提供浏览器 HTTP/HTTPS 链接、普通 TCP 的 `ssh://` 链接与可复制 SSH 命令，并在 Windows 上提供不含凭据的 `.rdp` 连接文件下载；UDP 继续提供本机地址复制。认证与证书确认全部交由操作系统与目标工具处理。
- **AI 自动化管理面、CLI、Skill 与多语言 SDK（源码基线）**：合并默认关闭、仅绑定 `127.0.0.1` 且强制 TLS 的可选 `automation` 管理面（REQ-001P / DES-010 / ADR-0035 / ADR-0036），仅允许经既有端到端加密授权互访通道接入，采用一次性配对码、管理页面人工批准、短时设备绑定令牌（EC P-256、无刷新令牌）、A/B/C 风险分级、变更申请审批与完整审计。仓库同步合入 `relaylink` CLI（`src/RelayLink.Cli`）、`relaylink-admin` agent skill（`skills/relaylink-admin/`）、`contract/` 契约与六语言（.NET/Python/TypeScript/Go/Java/Rust）面向入口的数据面 SDK 源码。
- **管理台与本机页同步更新**：服务端管理页面新增自动化授权与变更申请审批面板，并保留互访入口在线状态与地址复制；Agent 本机页继续沿用 ADR-0034 同源写会话与 CSRF（无本机管理令牌文件），并补充原生工具入口单元测试。
- **CI、发行与稳定性修复**：开源仓库使用 GitHub 托管 runner，增加九项发布资产清单与 `SHA256SUMS` 校验、macOS Agent 打包预检、产物上传重试与测试重试；修复 `PeerRelayRegistry` 关闭审计竞态、`SecretFilePermissions` macOS 临时目录符号链接解析与 `DatagramListener.Stop` 并发释放；站点依赖升级 `sanitize-html` 至 `2.18.2`。

## 升级与兼容性

- **从 `v0.1.0-rc.13` 升级须清理插件配置**：如果曾在 `v0.1.0-rc.13` 中配置过可审计通道（如 `inspectionMode`、`application` 等字段或 `credentials/` 秘密库），升级到 `v0.1.0-rc.14` 前须从 `server.json` 和 `clients/*.json` 中移除这些已废弃字段，否则服务端会因未知字段拒绝启动。既有普通 TCP/UDP 与目标 Agent HTTP/HTTPS 反向代理配置可直接沿用。
- **协议与 Agent 兼容**：Server 支持 v3–v5 线协议，不再接受 v6/v7 帧。若节点此前安装过 `v0.1.0-rc.13` Agent，请同步升级到 `v0.1.0-rc.14`；v3–v5 旧 Agent 的普通转发与互访路径继续兼容。
- **SQLite 历史与审计库兼容**：`traffic_minute` 已改为显式列名写入，直接沿用 `v0.1.0-rc.13` 生成的含额外列流量库不会失败；`audit_event` 在启动时按需增量补齐自动化关联列（`automation_grant_id`、`device_key_thumbprint`），无需重建既有审计库。
- **自动化管理面默认关闭**：`automation.enabled` 默认为 `false`，未显式启用时不启动监听、不注册路由，不影响既有管理页、代理与互访行为；启用时须配置本机 TLS 证书，并通过端到端加密授权互访通道访问。
- **安全边界维持不变**：管理页与 Agent 本机页仍只监听回环地址并使用明文 HTTP；Agent 本机写接口按 ADR-0034 仅适用于单用户主机或由管理员操作的主机，多用户主机不得以 LocalSystem 或 root 运行 Agent。

## 验证与限制

- 本机 Linux（WSL）已通过全量校验：AdminWeb 类型检查、格式化与组件测试（10/10），AgentWeb 构建、格式化与工具入口测试（4/4），静态网站构建（14 个版本、双语 74 页）与站点测试（5/5），.NET 单元测试（256/256）及开启 Peer TLS 的完整集成测试（103/103）；Windows 与 macOS 实机校验及打包结果以本标签触发的 CI 与发行流水线为准。
- AI 自动化与多语言 SDK（REQ-001P / DES-010）仍为 Draft 阶段基线，尚未纳入本次 9 个自动发行资产（CLI 与六语言 SDK 需从源码构建）；跨平台（Linux/macOS/arm64/musl）SDK 验收、第二种具名 AI 宿主验收与 .NET SDK 管理面验收仍待后续补齐。
- Windows Agent 安装包目前未签名，macOS Agent 发行包未做 Developer ID 签名与 Apple 公证；本候选未执行容量压测或跨主机灾难恢复测试。
