# RelayLink v0.1.0-rc.10

这是在目标 Agent 上提供 HTTP/HTTPS 应用代理的候选版本。公网入口与加密互访都由目标 Agent 校验并转发到固定 Web 上游，同时收紧 WebSocket 来源校验、空闲超时和客户端地址头处理。

## 主要更新

- 新增 HTTP 应用协议。目标 Agent 使用 Kestrel 虚拟入口和 YARP 转发已授权的 HTTP/1.1 请求，支持 HTTP/HTTPS、WebSocket、SSE 与流式正文；业务入口不占用额外操作系统监听，Server 与访问方 Agent 不解析 HTTP。
- 公网通道由 Server 监听后经数据隧道交给目标 Agent；授权互访仍使用访问方 loopback 与 Agent 间内层 TLS。两种入口按通道策略校验并覆写 Host 与 Origin。
- HTTPS 入口的 PEM 证书保留中间证书链，并交给 Kestrel 的 ServerCertificateChain，不依赖系统信任或 AIA 下载补链。
- WebSocket 的 Upgrade 按逗号分隔的协议标记识别。公网与互访都必须配置非空 Origin 允许列表；列表为空时拒绝 WebSocket，包括未带 Origin 或同源的握手。
- 公网 WebSocket 活动空闲默认为 300 秒，不能再配置为 0。互访通道仍可显式设为 0，表示不因空闲关闭。maxWebSocketConnections 为 0 时等于通道连接上限。
- 始终删除 Forwarded、X-Forwarded-*、X-Real-IP、True-Client-IP、X-Client-IP 和 CF-Connecting-IP，再按已认证入口重建转发头。stripRequestHeaders 只追加精确头名，空列表或 null 项不能重新打开内置项。通道撤销、禁用或策略失配时释放并移出对应 HTTP 宿主。

## 升级与兼容性

- NTP1 当前为 v5。Server 同时接受 v3/v4/v5，可先升级 Server。旧 v3 Agent 继续使用普通 TCP 和授权 TCP 互访，v4 Agent 继续使用 TCP/UDP。HTTP 只向 v5 下发，目标 Agent 必须为 v5；HTTP 互访还要求访问方为 v5 且 endToEndEncryptionEnabled=true。v1/v2、未知版本和连接内版本切换仍被拒绝，新 Agent 连接旧 Server 未提供自动回退。
- JSON schemaVersion 不变。既有通道缺少 applicationProtocol 时保持 raw；HTTP 通道必须使用 TCP。HTTP 策略和证书在相关 Agent 重启后生效，不提供热更新。
- 破坏性配置变更：公网 publicAllowedOrigins 与互访 peerAllowedOrigins 都必须设置为非空 Origin 允许列表，不能再留空以跳过来源校验。公网通道的 webSocketActivityTimeoutSeconds 不能再设为 0；省略时默认为 300 秒。互访通道仍可显式设为 0。升级前按 [HTTP 运维说明](../operations/http-reverse-proxy.md) 补齐允许列表并检查公网空闲超时。
- 升级前备份配置、身份、服务端 SQLite 数据及证书。公网 HTTP 没有浏览器 TLS，只适用于受保护网络或明确接受明文的测试。普通 TCP/UDP 行为保持 v0.1.0-rc.9。

## 验证与限制

- 本候选的 HTTP 代理与本次安全修复在本机通过单元测试 137/137，以及启用互访 TLS 的集成测试 81/81。覆盖来源拒绝、分片读取的 HTTP 状态行、WebSocket 空闲与并发上限、客户端地址头剥离、宿主释放和 HTTPS 中间链。本次未重跑旧 v3/v4 二进制矩阵，也不把尚未执行的跨平台 CI 记为已完成验收。
- 尚未完成真实浏览器登录、Cookie、CSRF 与长期容量验收。HTTP 需求保持 Accepted，设计保持 Draft。不支持 HTTP/2、HTTP/3、gRPC 或 CONNECT 正向代理，也不自动改写响应正文。
- Windows 安装包未签名，macOS 包未签名或公证。详细需求、设计及 ADR 仍按各文档标注的评审状态维护。
