# RelayLink v0.1.0-rc.16

本版改进授权互访的中继建立流程。新版 Server 和两端 Agent 会在控制连接上核对同一次握手，并在目标服务就绪后放行业务。管理台和 Agent 本机页现在能区分加密中继、明文中继和加密状态未知。

## 主要更新

- 授权 TCP 和单播 UDP 互访支持新的就绪确认。目标方校验访问证明后才能准备目标服务，访问方收到就绪确认后才发送业务数据。握手不匹配、建立超时或授权变更会终止本次连接。
- 慢目标的控制写入与访问方读取心跳及其他连接的处理相互独立。建立期间重新核对映射、传输协议和加密模式，业务空闲计时从连接放行后开始。审计区分建立失败、撤权中止和正常结束。
- 管理台显示每条连接建立时的加密模式。关闭业务加密时会提示服务端可以读取载荷，HTTP/HTTPS 互访强制加密。Agent 本机页按实际就绪情况统计入口，并说明入口是否需要重启、Agent 是否已连接 Server。窄屏下可以看清地址、端口和操作按钮。

## 升级与兼容性

- 可先升级 Server，再升级访问方和目标方 Agent。三端均支持新能力时启用新的中继握手。与旧端通信时沿用对应版本的就绪流程，仍执行通道访问证明和配置的加密策略。
- 现有通道和映射配置可以继续使用。v3 Agent 支持 TCP，单播 UDP 要求两端支持 v4 或更高版本，HTTP/HTTPS 互访要求 v5。旧 Server 未报告原始 TCP 或 UDP 入口的加密模式时，界面标记为未知。

## 验证范围

- Windows x64 已通过 314 项单元测试和 142 项集成测试。兼容性矩阵使用发行包中的 v3、v4 Agent 和旧 v5 Server，覆盖加密与明文 UDP、错误访问证明及目标准备失败后的首包处理。
- 来源仓库的合并提交 `12d850e` 通过 Linux、Windows、macOS arm64 和网站的 GitHub Actions 检查。三个平台的 314 项单元测试均通过。常规集成套件在 Windows 通过 122 项，在 Linux 和 macOS 各通过 121 项，两台 runner 均因缺少原生 QUIC 支持跳过一项回环实验。
- QUIC 已在本机回环地址上验证握手、收发和半关闭。此版本的业务流量仍经 Server 中继，P2P 直连、自动回退和双 NAT 实网验证属于后续工作。
