每批使用准确的提交范围，不提交 `.local/`、证书私钥、生成的身份、测试运行载荷或凭据。代码功能与设计、示例、必要测试同批同步；尚未激活的批次不能标为完整 HTTP 可用。若 PoC 推翻接口假设，先修正设计并记下证据。

已识别的审查重点：入口就绪先于浏览器 TLS 握手；HTTP 上游结果与隧道就绪分开；ConfigAck 与 active/readiness 分开；Profile/通道/连接上下文隔离；互访 scheme/authority/版本绑定证明；浏览器证书与互访身份独立；旧端过滤 HTTP；不创建授权旁路监听；底层客户端内部重试不能仅凭 YARP 无重试功能就认定无重放。

本机以受信测试 CA、随机空闲 loopback 端口、仓库外或被忽略目录中的临时配置启动独立 Server、目标 Agent、访问方 Agent 及 Web 测试目标；记录进程启动与实际连接证据，验收后停止本次创建的进程，不修改系统信任、服务安装或外部运行实例。跨平台 CI 与本机 Windows 验收分别报告。

最终本机证据及目标环境缺口见 [HTTP 验证记录](../testing/http-reverse-proxy-verification.md)。de76df7 的五项远端 CI 已核对成功，证书链补充作为独立批次提交；最终 SHA 的跨平台检查直接以 Actions 结果核对，不把既有成功迁移到新提交。
