状态：Draft（中继控制面已接入，直连仍在验证）\
版本：v0.5.0\
更新日期：2026-11-27\
调研日期：2026-11-27

## 范围与现状

在两端都运行 Agent 的授权互访中，由 Server 继续决定谁可以访问哪个通道。两个 Agent 若能直连，业务流量直接在它们之间传输。直连不可达时，通过同一台 Server 中继，并沿用目标通道指定的加密模式。以 RDP 为例，用户始终连接访问方 Agent 的同一个回环端口，由目标 Agent 按通道配置连接内网主机的 RDP 端口。

```mermaid
flowchart LR
    A[访问方 Agent] <-->|直连：加密 QUIC 或明文 TCP| B[目标 Agent]
    A <-->|回退 TCP 数据隧道| S[RelayLink Server]
    S <-->|回退 TCP 数据隧道| B
```

当前实现每次互访都经 Server 配对两条 TCP 数据隧道。加密通道由访问方校验目标证书指纹，目标方校验通道访问密钥的挑战证明，然后才连接业务目标。现有 UDP 业务使用长度封装，经 TCP 隧道转发。已实现的协议见[互访设计](agent-to-agent.md)和 [UDP 转发设计](udp-forwarding.md)。本文的选路与租约均为提案，取舍见 [ADR-0043](../adr/0043-peer-direct-with-relay-fallback.md)。

首期拟覆盖**授权 raw TCP 与单播 UDP 的加密和明文两种模式**。管理员独立选择业务加密策略（默认开启）和选路策略（默认「仅中继」）。只有目标通道明确设置 `endToEndEncryptionEnabled=false` 且选择「优先直连」，Server 才允许尝试明文直连。应用始终使用原来的本机 TCP 或 UDP 端口。[互访加密开关](../adr/0016-optional-peer-traffic-encryption.md)

当前新版 Server 和 Agent 可协商 `relayControlReady`，用于加密及明文中继的双端握手确认、目标拨号授权和目标就绪通知。业务入口仍经 Server 中继，部署配置尚无直连选项。已接入的帧见[互访协议](agent-to-agent.md)，端到端与 QUIC 回环实测见[验证状态](../testing/verification-status.md)。

| 入口 | 本方案中的处理 |
|---|---|
| 加密授权 raw TCP，选择优先直连 | 两端具备能力时尝试直连。任一端缺少能力时直接使用加密中继 |
| 加密授权单播 UDP，选择优先直连 | 按来源建立独立会话。直连在 QUIC 可靠流上转发完整报文，回退沿用现有加密 UDP 中继 |
| 明文授权 raw TCP，选择优先直连 | 使用通过认证的 Agent 间 TCP 直连传输业务字节。不可达时走原明文 TCP 中继 |
| 明文授权单播 UDP，选择优先直连 | 每个来源会话在独立的明文 TCP 直连上以长度封装传输报文。不可达时走原明文 UDP 中继 |
| 授权 HTTP/HTTPS、自动化管理通道 | 两者均强制加密。HTTP/HTTPS 首期继续中继，保留入口上下文证明和 Host/Origin 策略。自动化管理通道沿用现有加密约束 |
| 云端应用或公网浏览器连接 Server 的入口 | 继续由 Server 接入。此类连接缺少可以参与协商的访问方 Agent |

## 连接如何建立

1. **授权。** 访问方通过已有的 TLS 控制连接提交 `requestId` 和 `mappingId`。Server 从已认证会话确定调用方，按已确认配置检查映射、目标通道、加密模式、双方在线状态及配额，为这次请求分配一个 `connectionId`。直连和回退共用这个逻辑连接及配额。只有满足直连条件的两端才会收到协商消息。
2. **发现地址。** 双方通过各自的 TLS 控制连接交换本次候选地址和短期 ICE 凭据。加密路径使用 UDP 候选，Agent 可从拟用于 QUIC 的 UDP 套接字向部署在 Server 主机上的 STUN 服务获取 NAT 映射。明文路径单独收集 TCP 候选。控制连接的源端口和另一种传输协议的映射都不能作为已验证的数据端点。[STUN 规范](https://www.rfc-editor.org/rfc/rfc8489.html)
3. **检查可达性。** 两端仅检查与通道模式匹配的候选，限制检查次数和时间。同一局域网可用内网地址，可达的 IPv6 地址也可参与。明文首期拟支持 ICE-TCP 主动端和被动端配对，访问方或目标方均可发起 TCP 连接，业务角色由 Server 授权决定。双方都没有可达的 TCP 接收端时回退，TCP 同时打开的跨平台成功率不作为首期前提。[ICE 规范](https://www.rfc-editor.org/rfc/rfc8445.html) · [ICE-TCP 候选](https://www.rfc-editor.org/rfc/rfc6544.html#section-3)
4. **验证对端。** 加密路径在选中的 UDP 地址对上建立 QUIC，由访问方校验目标证书固定指纹，目标方在 TLS 1.3 保护的流内验证通道访问密钥证明。明文路径在选中的 TCP 连接上执行下节的会话绑定和访问证明。两种直连证明都绑定双方身份与角色、控制会话、映射、目标通道、业务协议、加密模式、`connectionId`、选路序号和随机挑战。目标 Agent 与已确认通道快照核对模式，访问方与本次控制面授权核对。此时只交换认证消息。[端到端身份决策](../adr/0011-client-level-e2e-identity.md) · [QUIC 的 TLS 规范](https://www.rfc-editor.org/rfc/rfc9001.html)
5. **核对同一条已认证连接。** 一次选路只允许一条传输连接完成业务认证。两端各在该连接上生成新的随机挑战，把按角色排序的双方挑战和第 4 步的授权上下文纳入认证记录，并由此得到同一握手标识。Agent 将该标识绑定本地实际的 TCP 连接或 QUIC 连接及其双向流，直到结束都不换绑。两端从各自原 TLS 控制会话发送认证就绪回执（`Ready`），附握手标识和各自的一次性首租请求号。Server 须收到来自预期两端、角色互补、属于本次选路且握手标识一致的两份回执。完全相同的回执只处理一次。同一角色在同次尝试更换握手标识或请求号，或双方握手标识不符，均关闭候选并终止，不回退。
6. **首租确认后才允许拨号。** Server 在同一逻辑连接内串行处理授权变更、撤销和放行，复核双方已确认的配置版本，选定直连。同一 SQLite 事务提交起始审计及配额占用记录后，才通过原控制会话向两端授予首租，分别回显各自的首租请求号。Agent 按下文的本地期限校验后回执。只有两端均已确认、当前授权仍有效，Server 才向目标方发出绑定本次握手的一次性目标准备指令。目标方在本地租约内按快照连接 TCP 目标或准备专属 UDP 套接字，重复指令不触发第二次拨号。仅单侧收到首租时，目标零拨号。起始审计提交后若无法确定放行结果，终止该连接。[起始审计门槛](../adr/0013-sqlite-audit-gate.md)
7. **确认业务目标就绪。** 目标准备成功后，目标 Agent 经原 TLS 控制会话报告结果，回显 Server 在第 6 步发送指令时新生成的一次性许可值。Server 校验许可值、报告方的目标角色、两端会话、`connectionId`、选路序号、握手标识、模式及当前放行状态，再经访问方的原 TLS 控制会话确认。访问方只在这些字段与本地等待状态一致且首租仍有效时，才交付业务字节或将 UDP 队列移交给该路径。数据连接上的单字节或首段业务数据不能推进状态。先到的目标服务问候数据受有界背压约束。迟到或过期的确认为无效，目标拨号失败或撤权时关闭本次连接。UDP 就绪只表示目标套接字准备完成。

每条业务 TCP 连接独占一条 Agent 间连接。加密模式使用 QUIC 的双向可靠流并禁用 0-RTT 业务数据，明文模式使用经验证的 TCP 连接。两者均保留有界缓冲、背压和单向 EOF，另一方向可继续传回尾部响应，直到 EOF 或现有半关闭排空时限到期。空闲按业务活动计时，传输保活不计入业务流量。[QUIC 流与流控](https://www.rfc-editor.org/rfc/rfc9000.html)

## 明文直连的认证与可见范围

每次获准尝试明文直连时，Server 通过双方已认证的 TLS 控制连接下发本次尝试专用的短期绑定密钥。双方在选定的 TCP 连接上按访问方、目标方两个角色分别完成随机挑战应答，验证对方持有本次密钥。目标方还须使用通道访问密钥校验访问方的 HMAC-SHA256 证明。两类证明使用独立用途标识，绑定同一授权上下文。密钥本身不在明文路径发送，绑定只消费一次且随尝试取消或到期失效。两个 Agent 均确认成功并取得 Server 审计放行后，才接入业务。此模式沿用 ADR-0016 的服务端身份信任模型，不进行业务 TLS 握手。

被动端只在本次获准的探测窗口内监听，并限制未认证握手的并发量。选路完成后关闭监听和未选连接。明文业务与 ICE 检查共用已验证的 TCP 连接，按 ICE-TCP 的分帧规则区分 STUN 与应用数据。TCP 载荷逐字节转发，UDP 载荷沿用下一节的报文封装。只打通 UDP 时，加密通道可能直连成功，同一对 Agent 的明文通道仍可能走中继。[ICE-TCP 数据传输](https://www.rfc-editor.org/rfc/rfc6544.html#section-10)

挑战应答只保护建连授权。RelayLink 对后续明文业务不提供机密性或抗篡改保护，链路上的观察者可读取载荷，能干预链路的一方可修改载荷。直连时业务数据绕过 Server，明文回退时 Server 也能读取业务载荷。按现有约束，只有直连和中继所经网络均受信隔离，或业务本身提供加密与认证时，才适合启用明文优先直连。[明文互访的安全边界](../adr/0016-optional-peer-traffic-encryption.md)

## 单播 UDP 直连

**会话与首包。** 本机 UDP 入口按来源 IP 和端口隔离会话。首个报文触发一次授权与选路，每个来源会话独占一个 `connectionId`、一条 Agent 间连接和一个目标 UDP 套接字。加密直连使用独立 QUIC 连接上的双向流，明文直连使用独立 TCP 连接。回包只发往原入口上的原来源。建立期间首包和后续报文进入同一队列，每来源最多 32 个，满时丢弃新报文。放行前切换到中继时由最终选定的路径一次性接管该队列，避免同一首包经两条路径投递。

**报文边界与回收。** 直连流沿用现有的 4 字节大端长度加 UDP 载荷，范围为 0–65507 字节。长度 0 表示一个有效空报文。接收端读满一条记录后只发送一个业务 UDP 报文，长度越界或记录截断则结束该来源会话并丢弃残缺记录。任一方向成功转发完整报文后刷新 `udpIdleTimeoutSeconds`，包括空报文。UDP 会话没有半关闭，空闲、撤权或流中断时一并释放队列、目标套接字和配额。原入口仍可接收其他来源的报文。[UDP 需求与报文验收](../requirements/2026-10-05-udp-forwarding.md)

**承载选择。** 两种模式都使用可靠流，可复用现有报文编解码和最大载荷约定，无需自行实现分片重组。代价是跨 Agent 路径丢包时，同一来源的后续报文会等待重传。对实时加密业务，可另行评估 RFC 9221 原生 QUIC DATAGRAM。.NET 10 的 `System.Net.Quic` 公共 API 未公开 DATAGRAM 收发接口，单个 DATAGRAM 帧还受协商大小和路径 MTU 限制。[.NET 10 QUIC 公共 API](https://learn.microsoft.com/en-us/dotnet/api/system.net.quic.quicconnection?view=net-10.0) · [RFC 9221 第 5 节](https://www.rfc-editor.org/rfc/rfc9221.html#section-5)

## 哪些失败可以回退

Server 串行决定每个 `connectionId` 的路径。探测期间不发送会触发旧 Agent 绑定中继的 `PeerOpen` / `PeerOpenGranted`。已开始的直连尝试须由两端原控制会话确认同一尝试已经结束、候选已关闭且未放行。只有可达性失败允许回退，另一端可以确认已取消且没有本地认证错误。任一端报告认证失败、状态冲突或结果不明，均终止。Server 复核当前授权和原配置版本，作废直连序号与凭据，以新选路序号和双方独立的一次性令牌建立中继。加密通道只回到有内层 TLS 的中继，显式明文通道只回到明文中继。模式变更撤销旧连接。

双方已协商本草案能力时，直接选择中继和回退中继均复用现有的隧道绑定、起始审计和访问证明。业务目标就绪由目标经 Server 的 TLS 控制面向访问方确认，核对目标角色、两端会话、逻辑连接、选路序号、模式及本次已认证的中继配对。回退后的新配对不能消费直连尝试的确认。两端不发送或解析旧的单字节就绪标记。中继寿命仍由 Server 持有的数据连接控制。未协商新能力的旧端从一开始走原版中继，沿用该版本原有的就绪信号及数据链路信任边界。

| 情况 | 本次连接的处理 |
|---|---|
| 通道仅中继、旧端未声明直连能力、本机缺少传输依赖，或在发起直连前就没有策略允许的候选 | 双方支持该业务协议时从一开始走中继，按双方已协商的能力和通道加密策略建连。任一端不支持该业务协议时拒绝请求 |
| 该模式的候选用尽，直连传输在认证前不可达 | 双方控制会话仍有效、确认仅是可达性失败且尚未放行业务时，转入相同加密模式的中继。探测占用现有建立时限的一部分，为中继绑定和目标准备预留时间 |
| 固定指纹不符、访问证明错误、授权或配置变化、协议状态异常、审计失败 | 终止本次请求。路径切换不能绕过身份、授权、审计或配额 |
| 已发出直连放行、放行结果不确定、目标准备失败或业务开始后断线 | 结束本次连接并丢弃残留队列。TCP 由应用重新连接，UDP 由会话回收后的下一份新报文重新触发授权。两条路径间不重放已发字节或旧报文 |

每次尝试绑定当前 Server 配置项、双方控制会话及选路序号。握手超时无法判明原因或任一端无法确认取消时，按失败关闭。完成、超时、撤销和回退可并发到达，逻辑连接只记录一次终态、释放一次配额。探测套接字、定时器和排队任务均随本次尝试取消。

## 授权寿命与可观测性

**撤权。** Server 按客户端、通道、映射和连接 ID 登记直连。禁用客户端、删除映射、通道有效配置变化或管理员断开单条连接时，Server 先取消待放行并停止续租，再经控制连接通知两个 Agent。收到撤销的端立即关闭本地业务套接字与对端传输，并回报结果。中继仍可由 Server 直接关闭数据隧道。[现行撤销规则](../adr/0009-revoke-connections-on-channel-change.md)

**首租与续租。** 每端在首次发送本次 `Ready` 前，用包含系统挂起时间的本地单调时钟记录起点。首租截止为该起点加授予时长，且受既有建立截止和本连接租期上限约束。重发同一请求沿用同一起点，收到授权或回执不重新计时。已进入活动状态才可续租。每次续租使用新序号，按本端发送该请求的时刻计算新期限，应答必须在旧租约有效期内到达。两端控制会话健康且授权有效时 Server 才可签发。两台机器无需比较各自的时钟读数。

**截止与断线。** 首租确认、开始拨号、异步目标准备完成、移交 UDP 队列和转发前均检查当前状态与本地期限。截止时取消进行中的 I/O 并释放资源。已过期的指令不能重新拨号、取包或续租。端点若无法可靠计入挂起时间，须在系统恢复时、恢复任何 I/O 前一并作废待授租请求和存量租约。无法保证这一顺序的平台不声明直连能力。控制断线即时关闭所属直连，静默分区最迟于剩余租期届满时停止。Server 重启或 Agent 重连均须重新授权。租期上限和续租间隔待实测确定。

**重启时恢复占用。** 首租签发前持久化的占用记录包含 Server 实例、逻辑连接、双方客户端和会话、通道、占用额度以及该连接不可调高的最大租期。Server 平时只有在双方经原控制会话确认该连接已关闭，或最后可能签发的租约已过保守上界后，才归还额度。重启时，单实例 Server 须在接纳任何共用额度的新连接前，按未结清记录重建全局、双方客户端及通道占用。从新实例取得独占权、确认旧实例已停止签发的本地单调时刻起，保守等待每条记录中的完整最大租期及计时误差裕量，再结清旧直连。重启前后不比较单调时钟读数，调小配置、墙钟跳变或再次重启均不能提前回收。无法恢复占用时暂停使用受影响额度的新放行。

**审计与计量。** 起始审计一旦提交，该逻辑连接就只对应一条结束记录，即使首租仅部分送达。此前的失败记拒绝。重启清理须按路径区分，中继可沿用 `server_restart` 结清，可能存续的直连标记为“等待租约到期”，暂不写结束。结清记录和持久占用释放在同一事务按连接 ID 幂等执行。审计分别记录路径、业务模式、回退或结束原因。中继计 Server 实际转发字节，直连按访问方的分方向累计量及序号去重，最后上报后到结束之间的缺失量记为未知，不能用零补齐。[流量与审计设计](audit-and-traffic.md)

## 探测目的地与资源边界

Server 只向本次获准的对端转发候选。**实际发包的 Agent 在首个 UDP 探测或 TCP 连接请求之前**，按本服务端配置项已确认的探测策略检查规范化后的目的 IP、传输协议、目的端口及实际出口接口。候选只接受 IP 字面量，先将 IPv4 映射的 IPv6 地址还原再做匹配。首期排除未指定、回环、广播、组播、链路本地（含带作用域的 IPv6）及本站明确排除的本机或管理端点，拒绝规则优先。网络安全组仍负责网络 ACL。

公网反射候选须由可信 STUN 服务将实际观测的协议、源 IP 和端口与提交方的控制会话及本次尝试关联，探测方经已认证控制面核对该记录。其他候选须命中管理员独立配置的对端站点地址与端口范围和出口接口。私网目的地默认拒绝，局域网直连需明确允许该对端的目标地址。站点网段重叠且无法区分地址归属时跳过。对端自行上报的网卡、网段或端口不能扩大许可。相同检查适用于重试、新发现的对端反射候选及地址变化，未经批准的新路径不得由传输库自动发包。

除每次协商的候选数、期限和并发上限外，Agent 分别按已认证对端身份和规范化目的 IP 扣减跨连接的速率与并发额度，检查和预占通过后才发包。更换 `connectionId`、重连、更换目标端口或地址写法不能重置对应预算。单个候选被排除时继续检查其他合格候选。开始前就没有合格地址时，双方确认未发起直连，保持零探测，Server 可独立授权同模式中继。凭据或授权校验失败仍终止。STUN 服务另限请求速率与应答大小。日志和匿名状态不保存候选明细、ICE 密码、通道密钥或载荷。[ICE-TCP 安全考虑](https://www.rfc-editor.org/rfc/rfc6544.html#section-12)

Server 负责授权与证书指纹分发。Agent 私钥保存在所属服务端配置项的本机身份目录。

## 协议兼容与实现前要验证的事项

拟在 v5 的 `Register` 中按业务协议和承载模式声明支持的直连组合，由 `RegisterAccepted` 显式确认。Server 只在两端均支持目标通道选定的组合时发送协商消息。另一种模式可达或具备能力都不能代替本次授权。旧 v5 Server 缺少确认时，新 Agent 使用现有 v5 中继。对旧 v3/v4/v5 Agent，Server 沿用各版本已有的快照、摘要和帧序列。UDP 两端均为 v4 及以上、但缺少对应直连能力时走同模式 UDP 中继。任一端为 v3 时拒绝 UDP，TCP 互访照常。HTTP 仍要求 v5。选路策略由 Server 存储，本机入口、SDK 调用和 Agent 的配置导入方式沿用现状。具体线格式、消息编号和配置字段留待协议评审。[既有版本兼容决策](../adr/0025-v3-client-compatibility.md)

加密直连需先证明 **ICE 选中的 UDP 路径能交给 QUIC 持续使用**。重新绑定一个 UDP 端口可能得到另一条 NAT 映射，应在两个实际 NAT 后验证探测、QUIC 握手与持续双向传输。明文直连另测 TCP 主动/被动候选及已选连接的复用。Windows 服务、Linux、macOS Intel/Apple Silicon 的 Agent 按实测支持分别声明能力，缺少 QUIC 依赖不会阻止独立验证明文 TCP 承载。[.NET QUIC 平台依赖](https://learn.microsoft.com/en-us/dotnet/fundamentals/networking/quic/quic-overview)

.NET 10 公开的 QUIC 监听和客户端选项接受 IP 端点。回环实验保留探测用的两个 UDP 套接字，在各端通过仅连接本机 QUIC 端点的 UDP 套接字传递包。Windows 上已在该路径验证真实 QUIC 握手、双向传输、空报文、65507 字节报文和流半关闭。实验使用预先指定的对端，仅验证套接字复用方案。候选验证、真实双 NAT、路径迁移与性能仍待实测。[监听选项](https://learn.microsoft.com/en-us/dotnet/api/system.net.quic.quiclisteneroptions?view=net-10.0) · [客户端选项](https://learn.microsoft.com/en-us/dotnet/api/system.net.quic.quicclientconnectionoptions?view=net-10.0)

以下为首期完整验收场景。探测预算、租期和直连成功率均待测量。

| 场景 | 应观察到的结果 |
|---|---|
| 加密或明文 × TCP 或单播 UDP × 直连或回退 | 八种组合逐项验证。用合成载荷检查加密路径的机密性及明文路径的可读性，核对审计中的路径和模式。两种模式均须先授权和审计才放行 |
| 缺省加密配置、HTTP/HTTPS 互访、自动化管理通道 | 缺省值仍为加密。两类强制加密通道均不得申请明文承载，错误模式不得放行到目标 |
| 明文 TCP 候选不可达但 UDP 可达、缺少明文能力、跨模式重放、修改加密开关 | 前两种按配置走明文中继。错误角色、错误证明或重放一律拒绝且目标零拨号。模式变更撤销相关待建立与活动连接，加密失败不会产生明文流量 |
| 同一局域网、可达 IPv6、两个独立 NAT | 记录实际选中地址类型、建连耗时和成功路径。直连时大流量双向校验正确，Server 数据端口没有该连接的业务字节。RDP 静置后仍能操作，TCP 半关闭后可收到尾部响应 |
| UDP 两个来源并发，先测直连，再测强制中继 | 在两种路径上逐一发送 0、1、32769、65507 字节报文并核对完整回包、边界和归属。流被截断时目标收到零份残缺报文 |
| UDP 首包协商期间回退、队列满、空闲或撤权 | 回退不重复投递已排队的首包，队列已有 32 个报文时丢弃新报文。空闲回收后新报文可触发新会话，撤权后新报文被拒绝。均不重放旧队列，其他已授权通道可继续工作 |
| UDP 直连经受可控丢包 | 用同一对 Agent 对比直连与中继的首次回包时间、已建立会话的 P95 往返时延和超时比例。单独记录队列丢弃，检验可靠流重传对延迟的影响 |
| 禁用 Agent 间 UDP、受限 NAT、STUN 不可用 | 仅尝试本模式允许的候选，有可达候选时仍可直连。候选全部不可达时在预算内回到同模式中继，目标业务只准备一次 |
| 新 Server 配旧 Agent、旧 v5 Server 配新 Agent | 缺少 UDP 直连能力但两端支持 v4 及以上时分别验证加密和明文 UDP 中继。任一 v3 端参与时拒绝 UDP，TCP 回归通过。旧版快照摘要一致 |
| 错误指纹、错误证明、跨会话重放、起始审计写入失败 | 对应逻辑连接拒绝，目标零拨号，明文和中继均不能绕过拒绝 |
| 探测超时与就绪同时到达、放行丢失、已用连接断开 | 最多一个选定路径、一次业务拨号。无字节重放，任务、缓冲、配额和审计均可核对 |
| 撤销映射、手工断开、控制链路静默分区或 Server 重启 | 已知断线立即关闭，静默分区在租期上限内停止传输，迟到续租无效。同一 Agent 的其他服务端配置项不受影响 |
| 首租单侧送达、任一端首次授权延迟超过本端期限、端点在拨号前挂起超过租期 | 两端未确认有效首租时不下发目标准备指令。过期指令在恢复后也不能拨号、取包或补续。目标已在期限内开始拨号而结果迟到时，关闭套接字且业务零交付 |
| 同次尝试有多个候选同时可达，交换来自不同实际连接的两份 `Ready` | 即使逻辑连接号、选路序号和角色均正确，握手标识不符仍须拒绝，目标零拨号、无中继回退。重复相同回执只消费一次 |
| 明文直连及新能力回退时，目标拨号失败、数据流出现旧就绪字节、TLS 控制面目标就绪迟到或来自旧路径 | 访问方不发送本地业务字节、不移交 UDP 首包。正例中，仅当前目标经 Server 确认后开始传输，提前到达的合法服务问候能完整交付 |
| 重叠私网、链路本地、IPv4 映射别名、错误出口或端口，连续换连接探测同一目的地 | 排除的地址在两个方向均零出站（含 TCP 首次连接）。同一身份换目的地仍受身份预算约束，同一目的 IP 换端口或连接号仍受目的预算约束。另验两端明确许可的局域网候选可互通 |
| 全局上限为 1，两端静默分区后 Server 重启，另一对 Agent 申请新连接 | 旧直连仍可能有效时新申请拿不到同一额度。过保守期限才释放并写唯一终态，迟到消息不重新占用，缺失字节为未知。覆盖审计事务提交前后崩溃、首租部分送达、连续两次重启 |
| 一端报告不可达，另一端报告认证失败、在建立截止前未确认取消或已收到首租 | 终止该逻辑连接，目标不重复准备，不签发中继令牌。只有双方确认同次直连尝试结束且符合回退条件，才能选择同模式中继 |
