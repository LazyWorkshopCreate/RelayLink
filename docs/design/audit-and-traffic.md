## 1. 现状与调研

当前服务端的控制会话、普通代理和端到端中继分别管理连接生命周期；管理员登录由 `AdminSessionService` 处理。`ILogger` 主要用于运行诊断，缺少统一的结构化审计事件，也没有可查询的审计持久化。原历史服务将普通代理累计快照写入 JSONL，逐次清理时重写全文件；端到端中继虽在 `MetricsRegistry` 记录双向密文字节，却被历史采样排除。

SQLite 的 WAL 模式允许读者与写者并发，但同一时刻仍只有一个写事务；长期读事务会妨碍 checkpoint，不能把它当作无限并发的日志服务器。`Microsoft.Data.Sqlite` 连接对象不宜跨线程共享；按操作打开连接并利用连接池，设置有限 busy timeout。批量事务适于分钟汇总和有界事件写入。[SQLite WAL 文档](https://sqlite.org/wal.html)、[Microsoft.Data.Sqlite 锁与重试](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/database-errors)、[事务说明](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/transactions)、[连接字符串说明](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/connection-strings)。

## 2. 已实现的分钟流量存储

服务端使用本地 SQLite 的 `traffic_minute` 表，主键为 `(minute_utc, client_id, channel_id)`。UTC 整分钟存储该窗口增量；无流量、无连接状态变化的分钟不写空行。字段包括普通代理双向业务载荷字节、端到端双向**密文 DATA 载荷**字节、连接接受/成功/失败数。普通与端到端字节分列，历史 API 的 `bytesToTarget`、`bytesToCaller` 返回两者合计，并额外给出端到端密文字节供调用方区分；不声称服务端知道端到端明文大小。管理页折线图展示分钟增量及所选时段合计，不再称为重启后归零的累计值。

采样最多每 5 秒刷新一次同一分钟的记录，按运行时单调累计计数的差值写入；相同计数不重复入账。每次写入以事务提交，提交成功后才推进内存基线。进程重启从零基线继续累加数据库记录；计数器重置按新计数计算。分钟归属是**采样时刻**，边界可能偏差一个采样间隔，异常退出可能损失尚未采样的字节，所以不作为计费或法务精确证据。查询 24 小时以内返回分钟点，7 天以内按 15 分钟聚合，更长范围按小时聚合，以限制图表点数。默认保留 90 天，每天清理过期窗口；需要备份 `.db` 以及 WAL/SHM 文件，备份宜使用 SQLite 在线备份机制或停服后复制，不能只拷贝主数据库文件。

旧 `.jsonl` 配置自动把 SQLite 路径派生为同名 `.db`，在初始化时一次性导入旧行并将相邻累计快照换算为增量；旧文件不删除、不继续写。导入标记与数据同事务提交，重启不会重复导入。旧数据的首个样本包含之前未采样时段的累计值，无法恢复真实分钟分布。新部署示例直接使用 `.db` 路径。数据库本身不加密；部署必须限制服务账号的文件/目录权限并按敏感数据策略启用磁盘加密。

容量按活跃通道估算：一个持续有流量的通道 90 天最多约 129,600 条分钟记录；大量通道持续传输时需监控数据库、WAL 增长及清理耗时。本地 SQLite 方案仅针对单服务端实例，不适合多实例同时写同一网络共享文件。

## 3. 审计日志

审计与诊断日志分离，默认写入本地 SQLite 的独立 `audit_event` 表，并与已配置的流量历史共用数据库文件。审计记录只包含元数据，不记录密码、会话 Cookie、CSRF、客户端密钥、访问密钥、证书私钥、业务载荷或 SQL 文本。事件字段包括全局事件 ID、UTC 时间、类型、结果、原因、连接和会话关联 ID、客户端与通道 ID、来源 IP、时长、双向字节数及服务实例 ID。查询接口仅管理员可用并限制时间范围与页大小，匿名仪表盘不展示审计记录。来源 IP 脱敏和导出接口尚未实现。

事件口径：

| 类别 | 起始事件 | 结束/拒绝事件 | 记录位置 |
|---|---|---|---|
| 管理登录 | `admin_login_success` | `admin_login_failure`、`admin_logout`；`admin_session_expired` 待实现 | 管理会话认证边界 |
| Agent 控制连接 | `agent_session_ready` | `agent_session_closed`、认证/配置拒绝 | 注册与控制会话 `finally` |
| 普通代理连接 | `proxy_connection_opened` | `proxy_connection_closed`、建立失败/拒绝 | 目标就绪与转发 `finally` |
| 端到端访问 | `peer_connection_opened` | `peer_connection_closed`、授权/建立拒绝 | 双数据端绑定与中继清理 |

“建立”应指业务流可以开始传输，而非 TCP accept；未认证/未就绪的连接以拒绝事件记录，避免把探测流量统计为成功连接。同一逻辑连接共享 `connection_id`；开始事件和结束事件各写一次，结束包含结束原因、时长及最终字节数。登录失败仅保存提交的用户名（长度限制并做控制字符清理）与源地址，不保存提交的密码。审计原因码使用固定枚举，异常堆栈留在受控诊断日志，不进入审计表。

### 可靠性、安全与资源限制

当前实现以 1024 个等待请求的容量门和单写锁串行写入 SQLite。成功登录、Agent Ready、普通代理 Start、端到端 BindAccepted 都必须等待起始审计落库；容量满或数据库不可写时拒绝新建立（fail closed），但已有业务流仍可继续转发。结束事件在清理阶段写入；端到端结束异步写入，失败记录诊断错误。进程重启时为缺少结束记录的普通/端到端连接和 Agent 会话补写 `server_restart`。正常停机时端到端结束事件尚无有界排空机制；登录失败/未认证连接的独立限速和写入水位监控也未完成。

审计默认保留 90 天，可通过 `audit.retentionDays` 设为 1–3650 天。`audit.filePath` 可指定库文件；未配置时使用 `history.filePath` 对应的 SQLite 文件，历史也未配置时位于服务端配置文件目录的 `audit.db`。使用 WAL；与流量历史共库时两者共享 SQLite 写锁。管理员通过 `GET /api/v1/admin/audit` 查询最近 1–2160 小时，支持事件类型、客户端 ID、分页（每页最多 100 条）；匿名不能查看。管理页登录后可打开审计弹窗。正式保留期限、远端备份和不可篡改要求应由使用场景决定；本地 SQLite 加文件 ACL 不能证明日志不可篡改，不应称作合规 WORM 审计。数据库满、只读权限、高并发背压、停机排空与真实部署仍需验收。

## 4. 迁移与验收边界

流量统计和审计日志已在仓库实现，但当前运行中的本机/远端服务仍需更新部署后才会生效。旧 JSONL 原件应至少保留一个备份周期；迁移校验应比较导入前后各客户端/通道的总增量，注意旧文件首个样本的累计归属误差。生产部署前需检查数据库目录权限、剩余空间、WAL 备份与 90 天清理效果，并执行真实部署故障演练。
