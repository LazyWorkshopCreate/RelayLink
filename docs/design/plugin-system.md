当前代码已实现两类可审计通道的 HTTP/HTTPS 逐请求策略、SSH 固定目标主机键与动作前审计、协议 v7 分阶段生命周期、应用字节计量、相对配置路径保存及凭据变更/删除恢复。跳板未指定应用时保留原有腿部 TLS 字节转发，它不提供应用检查，不能作为 A97 已验收的证据。选定应用后，拒绝和故障不会降级为该路径。

RDP 数据面、管理员批准 API/页面、凭据发放、桥应用及证书/策略编辑表单仍未实现。RDP 审计入口拒绝新增/重新启用，存量可停用、删除；HTTPS 材料和 SSH 目标主机指纹由配置文件提供。以下有关桥应用、发放和批准流程的章节继续表达设计目标，不能当作可执行功能。普通代理、端到端/明文互访、UDP 和目标 Agent HTTP 反向代理保留原路径。

## 1. 调研结论

对照当前实现和协议文档，服务端要按应用审计，缺的不是一个日志字段，而是明文所在的位置。

| 现有路径 | 服务端实际能看到的内容 | 对插件的含义 |
|---|---|---|
| 普通代理 | 数据端口上的原始 TCP。SSH、HTTPS、RDP 的应用加密仍是密文。数据端口没有 RelayLink TLS | 只能做字节计数和连接元数据，不能审计命令或 HTTP 路径 |
| 端到端互访，加密 | Agent 之间内层 TLS 的密文记录 | 服务端不能运行内容插件 |
| 端到端互访，明文 | 访问证明之后的业务字节，但服务端不是加密终点 | 不适合作为「两侧分别加密、只在服务端解密」的审计通道 |
| HTTP 反向代理 | 隧道元数据。HTTP 和浏览器 TLS 在目标 Agent 终止 | 不能把这套通道改成服务端审计，否则推翻 [ADR-0026](../adr/0026-http-proxy-over-tcp-tunnels.md) |
| 通道 tag | 只在管理列表筛选，不进快照，不触发下发 | 不能直接当成插件主键，除非单独规定保留值 |

因此新增可选的 `inspectionMode`，而不是复用 `endToEndEncryptionEnabled=false` 或 `applicationProtocol=http`。`applicationProtocol` 继续只表示现有的 `raw` 与目标 Agent HTTP。应用标识另用保留 tag，避免两个「HTTP」指同一种处理。

应用协议本身也限制首期深度：

- SSH 有明确的传输、认证和通道分层（RFC 4251–4254）。服务端可以同时扮演 SSH 服务端和 SSH 客户端，从而审计会话和命令。端口转发和 agent forwarding 会把未经审计的字节送出会话，首期默认阻断。
- HTTP 可以在请求头完成后做决定，正文保持流式。查询串、Cookie 和 Authorization 不适合进审计。
- HTTPS 是 HTTP 外面的 TLS（RFC 8446）。要审计 HTTP，就必须终结调用方 TLS 再向目标重新发起 TLS。调用方信任的是服务端证书。站点若做证书固定，连接会失败，这是预期，不是要绕过的障碍。
- RDP 的 NLA/CredSSP 把客户端认证绑定到目标身份。服务端若要看见图形或剪贴板，需要自己实现 RDP 服务端和客户端并使用保存的口令向目标重新认证。这是独立协议栈，不能放进首期。首期 RDP 只做连接级控制和凭据发放。

自定义协议 URL 会出现在进程参数和浏览器历史中。口令、私钥和管理令牌不能放进 URL。一次性 intent 加上桥应用自己的配对密钥，把秘密限制在 loopback 上。

## 2. 通道模型

```text
inspectionMode = none | server-peer | server-jump
application    = 空 | ssh | rdp | http | https     （由保留 tag 派生）
```

`none` 保持今天的转发。新模式只允许 `transportProtocol=tcp`，且 `applicationProtocol` 必须仍是 `raw`。与 UDP 或现有 HTTP 反向代理组合时拒绝保存。

### 2.1 服务端可视互访

用于原来的授权互访场景。调用方仍连接访问方 Agent 的 `127.0.0.1` 端口。映射、访问密钥和客户端身份保留。

```mermaid
flowchart LR
  app[本机应用] --> caller[访问方 Agent]
  caller -->|腿部 TLS| server[服务端插件]
  server -->|腿部 TLS| targetAgent[目标 Agent]
  targetAgent --> target[目标服务]
```

两侧腿部 TLS 的服务端身份都是 RelayLink 服务端证书，Agent 用已经内嵌的控制面 CA 校验。目标 Agent 的端到端客户端证书不再充当这一跳的对端身份；它仍留给 `none` 的端到端通道使用。

字节在服务端插件处汇合。SSH 和 HTTPS 插件向目标重新产生应用密文，目标 Agent 只把腿部 TLS 解开后的字节复制到 `targetHost:targetPort`。HTTP 和未加密跳板流量则是明文进、明文出。RDP 首期在插件处不做应用解析，两侧字节原样对接，但连接前的允许、拒绝和审批仍然发生。

访问证明改为两段，避免两侧 Agent 还要共享一条应用密钥通道：

1. 数据连接先完成现有的一次性绑定。
2. 再建立腿部 TLS。
3. 访问方向服务端证明映射密钥；服务端再向目标 Agent 证明同一连接。证明输入包含模式 `server-peer`、连接 ID 和挑战，不包含密钥本身。
4. 证明完成前，目标 Agent 不得连接业务目标。

### 2.2 服务端跳板代理

用于原来的标准代理场景。调用方连接服务端监听地址，不需要访问方 Agent。

```mermaid
flowchart LR
  caller[外部调用方] --> server[服务端插件]
  server -->|腿部 TLS| targetAgent[目标 Agent]
  targetAgent --> target[目标服务]
```

监听侧按应用处理：SSH 和 HTTPS 由插件终结，HTTP 和显式的未加密模式直接读明文。目标侧始终先做服务端到目标 Agent 的腿部 TLS，再由目标 Agent 连接既有目标地址。这样未加密应用不会把业务明文放回今天那种无保护数据端口。

公网一侧的明文仍和普通代理一样暴露在监听路径上。安全组继续按来源地址生效，通过之后才进入插件。

未指定应用只允许出现在跳板代理的未加密模式，用于尚无专用插件的 TCP。此时插件主机只提供连接级允许、拒绝、审批和字节计数，不猜测协议。

### 2.3 合法组合

| 模式 | 应用 | 调用侧 | 目标侧 |
|---|---|---|---|
| `none` | 空或四种应用 | 保持现有路径 | 保持现有路径。应用只供客户端唤起 |
| `server-peer` | 必须是四种之一 | 本机应用到 loopback，再腿部 TLS | 插件输出经腿部 TLS 到目标 Agent |
| `server-jump` | SSH 或 HTTPS | 插件终结应用加密 | 插件重新发起应用加密，外面包腿部 TLS |
| `server-jump` | HTTP，或空且明确为未加密 | 明文进入插件 | 明文经腿部 TLS 到目标 Agent |
| `server-jump` | RDP | 首期不解析 RDP | 首期原样对接，外面包腿部 TLS |
| 任一新模式 | 空，且要求应用加密 | 拒绝保存 | 拒绝保存 |

现有 HTTP 反向代理可以带 `app:http` 或 `app:https`，供客户端打开浏览器。它的 `inspectionMode` 必须是 `none`，服务端插件不运行。

## 3. 应用 tag

管理端在被访问通道的新建和编辑表单上提供单独下拉，不把应用混进逗号分隔的 tag 文本框。

保存规则：

- 规范 tag 只有 `app:ssh`、`app:rdp`、`app:http`、`app:https`。大小写在写入时折成小写，存储只保留规范值。
- 同一通道至多一个。它计入现有 32 个 tag 上限。
- 自由 tag API 若带有任何 `app:` 前缀，返回 400，并提示使用应用下拉。
- 值从空变为某个应用时允许一次。之后的 PUT 若缺少它、改变它或换成另一个 `app:`，返回 400。
- 编辑表单在已选定后显示该值且不可改。未选定时维护页面可以选定一次。

快照投影：

```text
application: null | "ssh" | "rdp" | "http" | "https"
```

其他 tag 仍不进入运行配置比较，只改它们不提升需要下发的运行配置、不撤销连接。`application` 进入运行配置比较。首次选定应用时撤销该通道连接。`inspectionMode`、是否授权互访、传输协议和 `applicationProtocol` 组成通道类型，只在创建时写入；编辑请求改变其中任一项则整次保存失败，连接保持原样。

端到端入口的快照在下发时复制目标通道的 `application`，映射配置里不落第二份。目标应用变化后，下次已确认的快照会带上新值。入口页面没有应用下拉。

## 4. 服务端插件主机

插件是服务端进程内的固定注册表，接口按应用 ID 查找。首期四个实现随 `RelayLink.Server` 发布。不扫描目录，不 `Assembly.Load` 外部文件，不提供热更新。

每条可审计连接一个插件会话，顺序固定：

1. 完成模式自身的认证和腿部 TLS。
2. 按应用找到插件。找不到则关闭。
3. 插件给出 `allow`、`deny` 或 `approve`。这一步还没有业务目标连接。
4. `approve` 在管理页等待，默认 60 秒，配置上限 300 秒。等待占用通道已有的待建立配额。全局未决审批超过 256 条时直接拒绝。
5. 允许之后插件才处理字节，并在需要时连接目标。
6. 任一异常、取消、超时或对端关闭，都结束两侧并各释放一次。异常路径不得改走原始复制。

字节管道使用有界缓冲，沿用现有半关闭：一侧读到 EOF 时关闭另一侧发送，反方向继续直到结束。SSH 和 HTTP 在自己的会话关闭规则之外仍要遵守这个资源限制。

策略数据放在通道的插件配置里，由服务端集中保存和下发只读副本。Agent 不解释策略。策略变化按通道撤销存量连接。

### 4.0 本轮已实现的检查边界

HTTP/HTTPS 使用 Kestrel HTTP/1.1 消息边界与 YARP 逐请求转发，逐请求放行审计成功后才向目标发出该请求。拒绝 CL/TE 歧义、重复主机/长度、CONNECT 和非 WebSocket 升级；WebSocket 只检查升级请求，不解释帧内容。上游流每条连接只能建立一次，不自动重连或重放业务请求。见 [ADR-0033](../adr/0033-http-inspection-request-boundaries.md)。

SSH 的 `inspection.ssh.targetHostKeySha256` 是管理员配置的 OpenSSH `SHA256:` 指纹，必须匹配后才能发送口令或发起私钥认证；缺失时旧配置仍可加载但该通道不可用。不采用自动 TOFU。`allowTcpForwarding`、`allowAgentForwarding`、`allowX11Forwarding` 为 true 时拒绝配置；命令前缀只匹配 exec 字符串，不是 shell 沙箱。每会话最多 32 个 channel，每 channel 初始化最多 32 条/64 KiB，各自维护 env/pty 状态并清空已消费队列。见 [ADR-0032](../adr/0032-ssh-target-trust-and-action-gates.md)。

保留 `app:` 前缀忽略大小写识别，但只接受规范小写值。`App:ssh` 等旧自由 tag 现在明确拒绝，管理员应人工确认其原意后改成规范值或普通自由 tag。不要自动把旧标签升级为可执行应用。

配置起点见 [脱敏示例](../../config/examples/inspection-client.example.json)。其中指纹与密钥都是占位，必须换成实际目标公钥的可信指纹和独立随机值；启用前要求 Server 控制 TLS 和 v7 Agent。HTTPS 和 SSH 证书/秘密不由浏览器表单上传。

### 4.1 SSH

两侧会话使用 Microsoft.DevTunnels.Ssh 3.12.42（MIT，2026-08 仍在发布）。不自研握手。调用方看到的是本通道自己的主机密钥，目标口令或私钥只在向目标认证时从秘密库解密。

调用侧把 RelayLink 当成 SSH 服务端。服务端为每个通道生成或保存自己的主机密钥，不复制目标的主机密钥。桥应用把这个主机密钥写入它自己维护的 `known_hosts`，避免操作员对未知主机键做永久确认。

目标侧由插件作为 SSH 客户端连接，认证材料只用秘密库里的口令或私钥。默认阻断：

- SSH agent forwarding
- X11 forwarding
- 直接 TCP 转发和远程端口转发

可配置为拒绝的还有 shell、exec、subsystem（含 SFTP）和命令前缀。默认允许 shell 和 exec，以便普通登录可用。SFTP 首期只允许或拒绝，不记录每个文件。

本轮审计记录前门用户名与认证结果、目标认证结果、channel 动作与最多 1024 字符的 exec 命令、subsystem 名称、被拒绝的转发类型，以及 channel 关闭时的字节、耗时与目标退出状态/信号。协议主版本和认证方法尚未形成独立审计字段，仍属后续设计目标。不记录口令、私钥和全程键入。

审批点在打开 shell、exec 或 subsystem 之前。拒绝时 SSH 通道不打开，目标侧没有对应会话。

调用侧认证默认不使用目标口令。访问方 Agent 已经证明映射后，桥应用向本机 SSH 提供一次性登录材料，使 `ssh` 能非交互登录到 RelayLink 前门。跳板代理没有映射证明，调用方必须使用该通道单独配置的前门账号，或由已配对的桥应用领取一次性材料。两种情况下目标口令仍留在服务端，除非打开 FR-30 的发放策略。

### 4.2 RDP

首期不链接 RDP 解析器。插件在腿部 TLS 和授权完成后做连接级决定，然后双向复制字节。

审计记录来源、客户端、通道、起止时间、双向字节、允许或拒绝原因，以及配置里声明的用户名。不从 RDP 字节里提取用户名，以免把未验证的明文误当成身份。

自动登录只走客户端发放：桥应用在 Windows 上写临时 `.rdp`，用凭据管理器登记目标，启动 `mstsc`，在进程结束后删除登记和临时文件。口令不出现在命令行参数里。非 Windows 首期返回明确的不支持。

后续若要做图形、剪贴板和驱动器审计，需要新的 RDP 协议栈和新的验收，不在 A99 内。

### 4.3 HTTP

只处理 HTTP/1.1。请求头读完后才做决定，头上限 64 KiB。决定之后正文以有界缓冲转发，不全量缓存。

审计字段：方法、host、path、状态码、双向字节、耗时、调用方或来源地址。path 去掉查询串和 fragment。删除并不记录 `Authorization`、`Proxy-Authorization`、`Cookie`、`Set-Cookie`。其他头不进审计，除非以后的规则明确列出名称且该名称不在上述集合中。

规则按顺序匹配方法、host 和路径前缀，动作是 `allow`、`deny`、`approve`。没有命中时，若配置了「非 GET、HEAD、OPTIONS 需要审批」则等待，否则允许并审计。WebSocket 升级只按规则允许或拒绝，不检查帧内容。

这条路径不改 Host 和 Origin，也不替换目标 Agent 上的 YARP。需要现有 Host 覆写时继续使用 HTTP 反向代理，而不是跳板插件。

规则和 HTTPS 材料写在通道 JSON 的 `inspection` 里，不下发到 Agent。磁盘保留原始相对路径，运行时按所属客户端 JSON 的目录解析；编辑通道、客户端和绑定身份都不能把解析后的绝对路径写回。`approvalTimeoutSeconds` 为 1 到 300，缺省 60。`approveUnsafeMethods` 为真时，没有命中规则的 POST 等方法进入审批；当前还没有审批页面，等待结束后拒绝。`rules` 按顺序匹配 `methods`、`host` 和 `pathPrefix`，动作为 `allow`、`deny` 或 `approve`。HTTPS 还要 `https.certificatePemPath`、`https.privateKeyPemPath`，可选 `https.upstreamName`（缺省为目标主机）和 `https.upstreamCaPemPath`（缺省使用系统信任）。证书更换算运行配置变化。管理页尚未编辑这些字段。

### 4.4 HTTPS

调用侧使用管理员放入服务端受保护目录的证书终结 TLS 1.2 或更高版本，ALPN 接受 `http/1.1`，也兼容未发送 ALPN 的调用方；解密后仅由 HTTP/1.1 解析器处理。上游 TLS 必须协商 `http/1.1`。私钥不下发、不进快照。首期一通道一张证书，不为每个站点动态签发，也不向调用方推送根证书。

解密后的字节交给 HTTP 插件的同一套规则和审计。向目标发起的 TLS 校验证书链和配置的上游名称；名称缺省为目标主机，也可以单独指定。校验失败则没有上游请求。

SNI、协商的 TLS 版本、调用侧证书指纹和上游证书指纹是后续审计字段目标，本轮尚未形成独立字段；当前使用 HTTP 请求/结果与连接级事件关联 HTTPS 操作。不记录会话密钥和私钥。

证书更换视为该通道的运行配置变化，撤销存量 HTTPS 连接。

## 5. 秘密库

每个被访问通道可以有多条登录材料，字段为标识、显示用户名、用途（`target` 或 `front-door`）、类型（口令或私钥）和加密后的秘密。秘密库文件在服务端配置目录的 `credentials` 下，与通道 JSON 分开，使用服务端首次生成的本地密钥做 AES-GCM。密钥文件和服务端配置一样只允许服务账号读取。管理接口是通道下的 `credentials`：写入、替换、删除，列表只返回标识、用户名、用途、类型和更新时间。

管理 API：

- 写入、替换、删除
- 列表只返回标识、用户名、类型和更新时间
- 没有任何读取秘密的管理响应

服务端代登录时，插件在目标认证的瞬间解密，用完即从缓冲区清除。向客户端发放时，服务端经已认证的控制连接把一次性秘密交给发起 intent 的 Agent；Agent 只在 loopback 上交给已配对的桥应用。控制连接必须是 TLS。发放记录包含通道、账号标识、调用方和结果，不包含秘密。一次领取后句柄作废。默认有效期 60 秒，且只能领取一次。

轮换秘密不影响已经建立的会话，只影响之后的认证。删除正在被策略引用的唯一账号时，新的需要该账号的连接拒绝，已建立会话按通道禁用之外的普通生命周期结束。

仓库示例只描述字段名，不提供可用口令或私钥。真实秘密库放在部署目录，不提交。

## 6. 客户端与桥应用

### 6.1 能力降级

| 通道 | 地址从哪里来 | 唤起 | 服务端插件 | 目标凭据 |
|---|---|---|---|---|
| 标准代理，`none` | 服务端监听地址 | 有应用且本机有桥时可以 | 无 | 无 |
| 端到端或明文互访，`none` | 访问方 loopback | 同上，程序连接 loopback | 无 | 无 |
| 现有 HTTP 反向代理 | 已有入口 URL | 打开浏览器 | 无 | 无 |
| 服务端可视互访 | 访问方 loopback | 按应用唤起 | 有 | SSH 由服务端持有；发放策略打开时桥应用可领 |
| 服务端跳板代理 | 服务端监听地址 | 管理页经本机桥唤起 | 有 | 同上 |
| UDP | 现有入口 | 不提供 | 无 | 无 |

降级是正常状态。页面用应用和模式说明「仅打开地址」或「服务端可审计」，不把缺少插件写成连接失败。

### 6.2 唤起顺序

Agent 本机写接口继续使用 [ADR-0034](../adr/0034-agent-local-write-session.md) 的同源写会话与 CSRF 校验（本机管理令牌已移除）。只读访客可以复制已经显示的地址，不能创建会领取凭据的 intent。

1. 持有本机写会话的本机页面或本机管理辅助页请求 `POST /api/v1/launch-intents`，声明 profile、入口或通道、应用和可选的账号标识。
2. Agent 对照已确认快照检查该入口是否允许这个应用。不允许则 400。
3. Agent 返回 `relaylink:open?intent=<id>&port=<本机端口>`。id 为 128 位随机数，60 秒内有效，使用一次。
4. 浏览器打开该 URL。操作系统启动已注册的桥应用。
5. 桥应用用安装时配对的密钥向 `127.0.0.1` 领取计划。只看到 URL 的其他进程没有配对密钥，不能领取。
6. 计划里的主机、端口和应用来自 Agent 快照，不来自 URL。需要秘密时，Agent 经控制连接向服务端申请，再交给桥应用。
7. 桥应用按本地模板启动程序。参数使用参数数组，不经过 shell 拼接。

配对在安装或首次启用时完成：管理员用本地管理令牌把桥应用公钥登记到该 Agent。未配对的桥只能被协议唤起，然后向用户显示未配对，不能取凭据。

管理页上的跳板代理按钮不直接打开业务地址。它要求操作员本机 Agent 代为创建 intent。本机没有 Agent 或没有桥时，管理页只提供地址复制。

### 6.3 脚本模板

模板随桥应用发布：

| 应用 | Windows | Linux 与 macOS |
|---|---|---|
| SSH | OpenSSH。口令走 `SSH_ASKPASS` 辅助程序，私钥用临时文件并限制 ACL | 系统 `ssh`，同样禁止把口令放进参数 |
| RDP | 临时 `.rdp` 加凭据管理器，再启动 `mstsc`；结束时删除 | 首期不支持，桥应用说明原因 |
| HTTP / HTTPS | 系统浏览器，URL 不含用户信息 | 同左 |

本机覆盖文件位于桥应用配置目录，只由该用户或服务管理员读写。占位符只允许 `host`、`port`、`username`、`identityFile`、`url`。未知占位符或试图加入命令行口令字段时，桥应用拒绝启动。服务端配置没有脚本正文这个字段。

注册协议使用 `relaylink:`。Windows 按用户登记，macOS 用应用的 URL type，Linux 用 `x-scheme-handler/relaylink`。不要求为了登记协议而提升为机器级管理员；读取管理令牌和秘密的权限仍遵守现有安装边界。

## 7. 协议与兼容

线协议当前为 **7**，Server 接受 v3–v7；v3–v6 保留各自已有的 `none` 能力。修复后的可审计通道仅下发给 v7，指向它们的映射同样过滤；server-peer 要求双方 v7，server-jump 要求目标 v7。旧 Agent 的未知字段忽略不作为安全边界。

v6 已引入的 `inspectionMode`、派生 `application` 和腿部 TLS 保留，v7 增加以下阶段契约，详细决定见 [ADR-0030](../adr/0030-inspection-lifecycle-protocol.md)：

- `Open`、`PeerOpen`、`PeerOpenGranted` 携带首次 active 前的有界等待预算及写入期限。TLS/访问证明、应用输入、审批、目标连接/认证分别使用自己的期限。
- 证明后的允许字节只表示调用方可以发送插件所需输入，不代表业务 active。首次审批一直占有 pending，目标也不预连接。
- `InspectionTargetReady`（26）由实际目标会话报告 TCP 已就绪，服务端验证连接归属；`OpenFailed` 同时路由普通与 peer 待建立连接。目标腿必须先承载 TLS/SSH 认证，才能判断业务是否就绪。
- 目标应用认证成功且审计落库后，发送 `InspectionActive`（25）通知双方转 active、释放首次 pending 并取消建立总期限。活动会话使用空闲、阻塞写和半关闭期限；后续请求审批使用有界操作名额，不重复转换连接计数。
- 保留 BindAccepted/Start 前持久化审计。`prepared` 表示准备好认证腿，`inspection_session_opened` 才表示业务 active；目标失败不增加业务 opened 计数。

没有管理员批准接口时，审批只记录等待、超时或取消并拒绝，不能产生 granted。管理员断开、通道/客户端撤销均会取消等待并回收资源。

## 8. 审计与流量

既有连接审计保留，事件通过同一 connection ID 关联；HTTP 再附请求序号，SSH 再附 channel 标识。当前事件与未来事件分开：

| 当前事件 | 含义 |
|---|---|
| `proxy_connection_opened` / `peer_connection_opened`，`prepared` | 已持久化的传输准备门槛，不表示上游认证成功 |
| `inspection_session_opened` | 目标就绪且应用认证成功，转 active |
| `inspection_decision` | 每请求/每动作允许、拒绝或等待；允许必须先写成功 |
| `inspection_response` | 请求 ID、HTTP 最终状态、显式 outcome/reason 及请求级应用字节；未开始响应的故障状态为 0，截断 200 仍记 failed；结果写入使用独立 5 秒收尾令牌 |
| `inspection_target_auth` / `inspection_action_result` | SSH 目标认证、目标接受/拒绝动作；不是命令执行完成的同义词 |
| `inspection_session_closed` | SSH channel 结束、退出码/信号、payload 字节和时长 |
| `inspection_approval_expired` | SSH 审批超时；HTTP 超时在决策中记录 `approval_timeout` |
| `proxy_connection_closed` / `peer_connection_closed` | 连接结束的原因、时间及同源字节；未准备成功走 rejected |
| `credential_change_requested` / `credential_saved` / `credential_deleted` | 凭据意图和已应用结果，通过操作 ID 关联 |

未来管理员批准/否决、凭据发放事件随对应功能实现，不预先伪造 `granted` 或 `credential_released`。审计中不保存 HTTP 查询串、Cookie、Authorization、正文、密码或私钥；SSH 命令详情有长度上限，不记录终端全程键入。已执行结果的审计故障记脱敏诊断，不假装回滚；后续新动作仍受前置门槛约束。

应用计量字段 `applicationToTarget` / `applicationToCaller` 与 `peerCiphertext*` 分离。HTTP 按目标侧成功写入/读取的应用流计量，包含头和消息编码、排除 TLS；因 YARP 正规化逐跳头和编码，它不是原始 caller 报文逐字节计数。SSH 只计 channel 数据，不计 SSH/TLS 传输开销和 keepalive；持续应用数据刷新空闲活动。分钟历史追加应用列，旧行默认 0，合计为普通 + 原互访 + 应用字节，各计一次。

秘密库响应与恢复契约见 [ADR-0031](../adr/0031-credential-mutation-and-deletion-recovery.md)。SQLite 和加密文件不构成跨文件事务；有限回执负责在结果审计故障或重启后补记真实结果。审计库仍是本地 SQLite，不称为不可篡改日志。

## 9. 管理端行为

被访问通道的新建表单把通道类型放在最上方，打开时默认是标准代理。类型被清空时，下方不展示业务字段，也不能提交。管理员切换类型时，表单只保留该类型需要的控件；从上一种类型带出来的监听地址、安全组、加密开关或插件字段不进入本次提交。服务端按最终类型校验，不接受隐藏字段里的另一套组合。

编辑时类型以只读文本显示，控件不可操作。下方仍只显示该类型允许修改的字段。通道 ID 维持今天的不可改。更新请求里的类型组合必须与已保存值一致，否则返回 400，不写文件，不撤销连接。要换成另一种通道，先删除再新建。

类型不单独存一份可与字段打架的枚举。它由下面四项共同决定，创建后这四项都不可改：

| 表单类型 | 传输 | 应用转发 | 授权互访 | 审计模式 |
|---|---|---|---|---|
| 标准代理 | TCP | raw | 否 | `none` |
| UDP 代理 | UDP | raw | 否 | `none` |
| 端到端互访 | TCP | raw | 是 | `none` |
| UDP 互访 | UDP | raw | 是 | `none` |
| HTTP 公网反向代理 | TCP | http | 否 | `none` |
| HTTP 互访反向代理 | TCP | http | 是 | `none` |
| 服务端可视互访 | TCP | raw | 是 | `server-peer` |
| 服务端跳板代理 | TCP | raw | 否 | `server-jump` |

管理页已经能创建的类型是前四类加上后两类。HTTP 两类的 Host、Origin 和证书字段仍按现有 HTTP 配置解释，本设计不另定语义。页面还没有这些策略控件时，新建下拉可以不列出 HTTP，已有 HTTP 通道一旦打开编辑，类型同样只读，保存不得把 `applicationProtocol` 改回 raw。

各类型都显示通道 ID、显示名称、筛选 tag、目标主机、目标端口、最大连接数、目标连接超时和启用开关。此外：

| 类型 | 额外字段 | 不显示 |
|---|---|---|
| 标准代理 | 监听地址、监听端口、安全组；应用可选 | 加密开关、UDP 空闲、插件策略、凭据 |
| UDP 代理 | 监听地址、监听端口、安全组、UDP 空闲超时 | 应用、加密开关、插件与凭据 |
| 端到端互访 | Agent 间端到端加密，默认开启，编辑时仍可改；应用可选 | 监听地址、端口、安全组 |
| UDP 互访 | 加密开关与 UDP 空闲超时 | 应用、监听与安全组 |
| HTTP 公网反向代理 | 监听、安全组、既有 HTTP 策略；应用只能是未指定或与入口 scheme 一致 | 插件代登录、旧式「仅互访」复选框 |
| HTTP 互访反向代理 | 既有 HTTP 策略；互访加密保持开启且不提供关闭 | 监听、安全组、插件代登录 |
| 服务端可视互访 | 应用必填。SSH 显示目标凭据和阻断项；RDP 显示凭据发放和「首期不解析内容」；HTTP 显示规则；HTTPS 显示证书、上游名称和规则 | 监听、安全组、旧的端到端加密开关 |
| 服务端跳板代理 | 监听、安全组；应用可为未指定或四种。未指定表示未加密审计。已选应用时字段与可视互访相同 | 旧的端到端加密开关、UDP |

应用下拉与筛选 tag 文本框分开。访问密钥由服务端生成，两种互访和可视互访都不提供密钥输入框。入口表格增加只读应用列，数据来自目标通道。默认新建类型是标准代理。

今天表单顶部的传输协议和底部的「仅允许授权客户端互访」由这个类型选择器替代，避免先填监听再勾选互访把字段藏起来。

审批列表只对已登录管理员开放，显示通道、应用、调用方、等待开始时间和规则摘要，不显示秘密和 HTTP 正文。允许和拒绝都要二次确认。

凭据表单只有用户名、类型和写入用的秘密框。保存成功后秘密框清空，列表不再显示秘密。

## 10. 故障

| 情况 | 行为 |
|---|---|
| 插件抛出异常 | 关闭两侧，审计失败，不降级 |
| 审批超时或队列已满 | 拒绝，目标零连接 |
| 目标 Agent 低于 v7 | 新模式通道对该 Agent 不可用，其他通道保持 |
| 腿部 TLS 或访问证明失败 | 按失败关闭，不改试旧内层 TLS |
| 秘密库不可读 | 需要秘密的新认证拒绝；不需要秘密的连接级 RDP 复制也停止，避免一半策略失效。实现时整条可审计通道失败关闭 |
| 桥未安装或未配对 | 转发不受影响；页面保留地址和原因 |
| 证书名称不符 | HTTPS 上游不连接 |

- 模式、快照和帧：`RelayLink.Protocol`
- 插件主机、SSH/HTTP/HTTPS/RDP 门控、秘密库和审批：`RelayLink.Server`

## 12. 建议实现顺序

以下只为了把以后的改动拆开，不是本阶段要写的代码。

1. 配置、保留 tag、快照过滤和非法组合校验，数据面仍不处理新模式。

## 13. 安全后果

启用新模式的部署方把该通道的应用明文托付给服务端。这与现有端到端通道的信任模型不同，所以必须显式选模式，不能作为升级默认值。

目标凭据集中在服务端后，服务端备份和主机权限变成凭据边界。向客户端发放会把边界扩大到操作员机器，因此默认关闭。

SSH 当前拒绝转发，也拒绝将转发配置项设为 true，避免调用方借 RelayLink 的目标认证打开插件看不见的隧道。未来若实现并另行批准转发支持，必须明确其审计边界，不能声称隧道内命令审计完整。

HTTPS 插件不是通用透明代理。它只处理管理员配了证书的通道。不要补一个全局根证书安装器来提高连通率。
