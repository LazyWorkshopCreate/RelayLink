# ADR-0025：非破坏性增量保留 v3 客户端兼容

状态：Accepted\
日期：2026-10-05

## 背景

UDP 增量只新增配置和报文封装，未改变既有 TCP 注册、绑定、转发或身份模型。rc.9 最初发布采用严格 v4 校验，导致升级 Server 后旧 v3 Agent 离线。用户明确要求非破坏性变更保持旧客户端可用，本 ADR 修正 [ADR-0024](0024-udp-over-independent-tunnels.md) 的升级策略。

## 决定

- Server 接受 v3/v4，按连接首帧锁定版本；连接内切换、v1/v2 和未知版本仍拒绝。响应使用该端版本，不依赖 AgentVersion 文本推断能力。
- v3 初始及更新快照不包含 UDP 通道、UDP 目标映射或新增 UDP 字段，配置摘要按旧序列化结构与字段顺序计算。配置变更和依赖映射下发也采用接收端版本。
- v3 Agent 保留普通 TCP 及授权 TCP 互访；混合 v3/v4 的互访按两端版本分别封帧，内层 TLS、访问证明和半关闭保持原行为。
- 普通 UDP 要求目标会话为 v4；互访 UDP 要求两端均为 v4，否则服务端拒绝，不把 UDP 转换为 TCP。数据绑定版本必须与所属控制会话一致，错误版本不消费绑定令牌。
- 可先升级包含此修复的 Server，随后按需升级 Agent。新 Agent 连接旧 Server 的自动降级不在本次范围；用户要求将修复合入 rc.9 并重新发布；同名旧包不包含修复，需核对重建版的最新 SHA256SUMS。

## 备选

- 强制全部升级：UDP 属于增量能力，不能据此中断既有 TCP 用户。
- 只放宽帧头：旧 Agent 的配置摘要仍会不一致，且可能误将 UDP 目标解释为 TCP。
- 移除版本号：无法识别能力和阻止连接内模式变化，不采用。

## 后果

维护两个已知版本的配置表示及摘要；未来非破坏性字段按能力下发，真正破坏性变更再制定明确迁移策略。版本选择不替代认证，不放松 TLS、身份固定、一次性令牌、配额或审计门槛。旧 Agent 不具备 UDP，管理员须为需要 UDP 的相关端升级。
