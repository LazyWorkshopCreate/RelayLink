# ADR-0013：SQLite 审计与新连接放行门槛

状态：Accepted\
日期：2026-09-18

## 背景

诊断日志可以帮助排障，但不能提供可查询、关联、持久的登录与连接生命周期记录。用户要求默认用 SQLite 保存审计，并在管理页面查看。若登录或业务连接已成功，而起始审计无法落库，会形成无法追溯的会话。

## 决定

单服务端实例使用 SQLite WAL 的 `audit_event` 表保存事件元数据；默认与已配置的流量历史共库，也可指定独立文件。起始事件必须在成功登录、Agent Ready、普通代理 Start、端到端 BindAccepted 之前提交；写入失败或等待容量达到上限时拒绝新建立。已在传输的数据流不依赖审计写入继续运行。结束与拒绝事件在相应清理或拒绝路径记录，失败写诊断错误；进程重启时为仍无结束记录的连接和 Agent 会话补写 `server_restart`。

写入使用容量为 1024 的等待门和单写锁；不记录密码、密钥、Cookie、CSRF 或业务内容。查询只允许管理员会话，限制时间窗口及分页，响应禁止缓存。默认保留 90 天。数据库目录必须由服务账号写入，外层网络继续限制管理页面可达范围。

## 备选

- 仅用 `ILogger`：不提供持久查询与起止关联，也难以判定审计缺失。
- 审计写入异步后立即放行：存储故障或崩溃时可能出现成功连接没有起始记录。
- 引入独立 PostgreSQL：可集中存储，但增加单实例默认部署依赖。

## 后果

审计数据库故障会使新登录和新业务连接失败，必须监控错误并备份 SQLite 主库及 WAL/SHM。单进程串行写入是有界的首期实现，高并发容量与停机排空仍需生产验证。SQLite 本身不能防止拥有文件权限者篡改，不声明为不可篡改合规审计。
