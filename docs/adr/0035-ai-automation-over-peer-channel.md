# ADR-0035：AI 自动化经既有加密互访通道并强制控制台授权

文档 ID：ADR-0035\
状态：Proposed\
日期：2026-11-05\
依据：用户于 2026-11-05 明确要求“供 ai agent 调用的 skill + cli + api，用于管理服务端设置，仅允许通过端到端加密的通道，且要求在服务端控制台授权”，并选择“管理页面人工批准 + 一次性配对码”与“运维工作站经 Agent 授权互访进入”。

## 背景

服务端管理 API 的鉴权对象是浏览器：进程内会话、`HttpOnly` + `SameSite=Strict` Cookie、写请求需 `X-RelayLink-CSRF`。审计门槛的现状必须说准：ADR-0013 的“先落审计再放行”只覆盖登录、Agent 会话建立、普通代理 Start 与端到端 BindAccepted；管理员登录有审计，而客户端、通道、访问映射、安全组的管理配置写**完全不写审计**。管理监听刻意维持明文 HTTP，远程管理者被要求在 Server 本机跑 Agent，经授权互访的内层 TLS 打开管理页（见[技术实现文档](../design/technical-design.md)第 3 节）。

AI agent 与自动化脚本无法在这套模型下安全工作：

- 保存 Cookie 等于把管理员口令的有效期复制到磁盘，且无法把“某个脚本”与“某次管理员登录”分开撤销。
- 为自动化新开公网加密端口，等于推翻既有“管理面不出 loopback”的取舍。
- Agent 本机 API 的只读端点只有 GET，且按 ADR-0034 明确不设口令；同一端口上的 `/api/v2/admin/servers*` 只改本机连接项，不涉及服务端配置。因此它不能承担管理面。

同时用户要求“仅允许通过端到端加密的通道”与“必须在服务端控制台授权”，这两条不能由静态密钥或 IP 白名单满足。

## 决定

1. 新增可选 `automation` 配置段，监听只允许绑定 `127.0.0.1`，只提供 TLS。默认关闭，端口缺省 18082。不提供关闭 TLS 或跳过证书校验的开关。
2. 可达性完全复用既有授权互访：管理页面提供“为自动化创建接入通道”向导，强制 `authorizedClientsOnly=true`、`endToEndEncryptionEnabled=true`、`applicationProtocol=raw`；校验在**通道保存、启动加载、`automation.port` 变更**三处执行，拒绝任何回环目标指向自动化端口、却不是授权互访形态的通道。要挡住的正是 `authorizedClientsOnly=false`：只有该形态会在服务端监听公网端口，把自动化端点挂到网上。不新增公网入口。
3. 身份使用设备密钥对（EC P-256）。首次使用走一次性配对：CLI 发起并显示 8 位用户码，管理员在管理页面核对用户码与 scope 后批准，CLI 用设备私钥签名换取短时令牌（缺省 120 分钟，可缩不可扩）。未批准不得换取；用户码单次使用、10 分钟到期、错误 5 次作废；换取在单个写事务内完成，避免并发双签发。
4. 令牌绑定设备公钥。每次调用同时携带令牌与设备签名证明（形状参照 RFC 9449，但头名为 `X-RelayLink-Proof`，不宣称规范符合性）。证明绑定方法、路径、令牌摘要、时间窗与一次性 `jti`。令牌复制到另一设备无效。配对前的匿名端点无法固定证书，其版本信息只用于选择行为、不作安全决策。
5. 不引入刷新令牌。到期后必须重新配对并再次人工批准。
6. 不提供自动批准、配置文件预登记白名单、IP 免批准或“首次之后永久有效”的口子。
7. 操作按风险分级：只读直接执行；受控写（显示名、tag、上限、超时、启停通道、安全组、删除访问映射、撤销自己提交的待批申请）直接执行并逐次审计；结构性写（客户端/通道增删、映射创建、通道的端到端加密开关变更）只能生成变更申请，由管理员在管理页面批准后执行一次；身份与授权类动作（签发/延长/撤销令牌、管理员口令与会话）自动化接口不可操作。凭据写入完全不经自动化接口。既有编辑器禁止修改已建通道的 `authorizedClientsOnly`，客户端级启停与“承载自动化自身的通道及其映射”也不可经自动化操作，避免自断管理面。
8. 配对请求、授权与撤销状态存入 `automation/state.db`（SQLite），不塞进受保留期裁剪的审计表。该状态是单机状态，不支持多实例或高可用部署。
9. 新增审计事件覆盖配对、批准、拒绝、令牌签发与撤销、每次调用与变更申请全生命周期；审计存储不可用时写操作与申请一律拒绝，只读放行并告警。注意既有管理配置写目前不写审计，因此这是对配置写入**新增**的门槛，不是复用既有行为。

## 备选

- **CLI 直接用管理员口令调现有 API**：拒绝。自动化持有人的凭证，无法按设备撤销，与“控制台授权”冲突。
- **管理页增发静态 API Key**：拒绝。静态密钥不绑定设备，复制即用，无法区分审批对象。
- **复用 Agent 本机 API 扩展为可写**：拒绝。其信任模型是“同机单用户”且无口令，写权会溢出到服务端配置。
- **直接开公网 TLS 端口 + 强制客户端证书**：拒绝。用户明确要求只走端到端加密通道，公网入口扩大攻击面并与既有部署模型不一致。
- **配对后签发长期令牌 + 刷新令牌**：拒绝。AI agent 长时间循环调用时，长有效期会把“一次性授权”悄悄变成“永久授权”；重新配对虽增加摩擦，但让每次授权都有人在场。
- **把授权状态写进审计表**：拒绝。审计受保留期裁剪，不能承担“当前是否有效”的语义。

## 后果

- 运维工作站必须能经授权互访到达服务端管理面，即至少有一个 `authorizedClientsOnly` 通道与一条访问映射；这是既有部署已支持的能力，但成为自动化的前置条件。
- 自动化入口若配置错误（例如**新建**一条非授权通道指向回环自动化端口，或先建通道再把 `automation.port` 改成该端口），三处校验会直接拒绝，而不是运行时静默暴露。注意既有编辑器本就锁死通道类型，无法把已建通道改成非授权形态，因此绕过路径是“新建”与“改端口”，不是“改类型”。
- “仅经端到端加密通道”需要精确表述：完整链路有四跳，其中两跳是主机内 loopback。跨主机的两跳是内层 TLS；服务端侧 loopback 由自动化监听自身的 TLS 覆盖（可固定校验）；CLI 侧到访问方 Agent 入口那一跳是明文，只靠 loopback 边界与访问密钥。任何一段 loopback 都不得对外称为端到端加密；四跳表与威胁落点见[设计 2.1](../design/ai-automation-and-sdk.md#21-只经端到端加密通道的精确含义)。
- 管理员必须在批准时核对用户码。文档要求带外核对，但流程本身无法阻止管理员不核对就批准；这一残余风险与既有“管理员可改一切”的性质一致。
- 只读调用也写审计，审计量会随 AI agent 调用上升；设计按「同令牌 + 同方法与路径 + 60 秒窗口」合并计数，合并行仍保留端点与计数，并为每令牌设读上限。
- 配对与令牌的限流不能按来源地址：经互访到达的连接来源恒为目标 Agent 的 `127.0.0.1` 临时端口。限流键改为设备公钥指纹与主体名。
- 服务端需要新增 `automation/state.db` 与自动化自身的证书链与私钥两个 PEM 文件，备份必须与 `clients/` 成套，单独还原会导致状态不一致；还原旧快照会复活已撤销的授权，须在还原后复核。
- 自动化状态是单机状态（SQLite + 进程内重放缓存 + 配置写锁），不支持多实例或高可用。
- 不引入多管理员或 RBAC；单管理员模型保持现状，scope 只约束自动化令牌，不改变人的权限。
- 不修改 `NTP1` 帧、协议版本、快照或既有管理 API，旧端组合行为不变。
