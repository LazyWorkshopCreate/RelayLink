# ADR-0012：普通通道的应用层安全组

状态：Accepted\
日期：2026-09-18

## 背景

原设计只依赖云安全组或主机防火墙约束业务端口，无法在 RelayLink 管理页面按普通通道维护来源地址。管理员需要将一个或多个 IP/CIDR 组成安全组，并指定给普通通道。

## 决定

安全组作为服务端配置存入 `server.json`，通道只保存可选的安全组 ID。未指定时保持任意来源；指定后以接受连接的 socket 实际来源 IP 匹配单地址或 CIDR，在创建 Agent Open 之前拒绝不匹配的连接。规则不作用于控制端口、独立数据端口、管理页面或端到端专用通道，也不读取可伪造的转发头。配置错误与引用缺失均拒绝加载或保存，运行时缺失则拒绝连接。

管理员会话和 CSRF 保护增删改；被通道引用的安全组不可删除。规则收紧后撤销已有的不匹配连接；通道绑定变更仍按 [ADR-0009](0009-revoke-connections-on-channel-change.md) 撤销该通道连接。云安全组/防火墙仍是外层网络边界，本功能不代替其限制，也不提供用户身份认证或传输加密。

## 备选

- 只修改云安全组：无法按通道管理，且依赖特定云厂商，不满足界面需求。
- 将来源规则下发给 Agent：普通业务入口在服务端，Agent 看不到原始调用方 IP，不能可靠执行。
- 在通道中直接维护地址列表：地址无法跨通道复用和集中更新。

## 后果

来源 IP 可能是 NAT、反向代理或负载均衡器的地址，运维需按实际网络路径配置；使用代理时不能把原始客户端 IP 当作服务端可见来源。安全组更新可能中断正在传输的 TCP 连接，业务自行重连。直接编辑配置文件仍需重启服务端。
