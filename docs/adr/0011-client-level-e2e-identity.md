# ADR-0011：端到端证书指纹按客户端自动登记

状态：Accepted\
日期：2026-09-18

## 背景

原实现把被访问 Agent 的证书指纹重复保存在每条授权通道，并要求添加通道时手动填写。这使同一 Agent 的身份散落于多个通道，也妨碍在 Agent 首次上线前创建授权通道。

## 决定

Agent 启动时仍由本机生成或加载端到端证书，在认证控制连接的 `Register` 中上报证书 SHA-256 指纹。服务端完成客户端密钥认证和配置确认后，将首次报告的合法指纹原子写入该客户端 JSON 的 `e2eCertificateSha256`；之后每次注册都必须与已固定值一致，不自动覆盖。授权通道只保存模式和独立访问密钥，不再保存证书指纹。创建访问入口时，从目标客户端的固定指纹生成访问方映射；目标客户端尚未登记时拒绝创建入口，但允许先创建授权通道。

原通道级指纹字段是错误的配置模型，不提供读取、归并或自动迁移。配置加载保持严格字段检查：客户端文件只要仍含 `channels[].e2eCertificateSha256` 就拒绝加载。升级前须从每条通道删除该字段；不要把其旧值直接当作已核验的客户端身份。未固定指纹的客户端在认证并确认配置后首次登记。现有访问入口中固定的目标指纹继续保留并与目标客户端身份比较；配置若因此不一致，同样拒绝加载，须由管理员核对后修正。

首次自动登记属于基于已认证客户端密钥的信任首见（TOFU），**不等同于带外核验**：拿到该密钥、控制初次注册路径或控制服务端配置的人可以在首次登记前抢占身份。管理页显示固定指纹，管理员在创建敏感访问入口前应通过独立可信渠道与目标 Agent 本机 `--show-e2e-fingerprint` 输出核对。证书丢失、重装或轮换时不接受新指纹自动覆盖；管理员须先停用相关入口、核验新身份，并通过受保护的配置维护流程显式更改客户端级指纹和相关访问入口固定值，之后重启服务。当前不提供网页端一键轮换。

## 备选

- 保持每通道手工填写：同一 Agent 身份重复维护，拒绝。
- 每次上线无条件覆盖：证书被替换时访问方会自动信任新身份，拒绝。
- 首次使用完全带外登记：安全性更强，但与自动上报并保存的本次需求不符；保留为高安全部署的人工核验步骤。

## 后果

首次上线必须有合法指纹报告，现有不发送该字段的旧 Agent 不能注册；升级时应先更新 Agent。包含旧通道指纹字段的客户端文件会使服务端启动失败，必须先人工删除该字段并核对现有访问入口配置。尚未上线的目标客户端可以配置授权通道，但不能创建到它的访问入口。管理界面不再要求在通道表单填写指纹；固定指纹作为客户端属性展示。此次改变替代 [ADR-0005](0005-agent-to-agent-tls.md) 的“不得自动信任首见”及通道级登记部分，其余端到端 TLS、访问密钥和服务器信任边界不变。
