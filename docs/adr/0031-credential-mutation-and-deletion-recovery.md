# ADR-0031：凭据变更结果与删除恢复

状态：Accepted\
日期：2026-10-31\
依据：用户明确要求按 [DEV-006](../development/plugin-system-improvement-plan.md) 实施改进方案。此决定只覆盖 B5，不批准桥应用或凭据发放。

## 背景

秘密库是独立加密文件，审计是 SQLite。原实现先改秘密库再写成功审计，后者失败会使接口报错，但秘密已经改变；删除通道也未清理凭据和服务端 SSH 主机键。二者不具备跨文件事务，不能靠调整一条审计的顺序声称原子提交。

## 决定

1. 凭据 PUT/DELETE 接受非空 UUID `Idempotency-Key`；缺省由服务端生成，响应头 `X-RelayLink-Operation-Id` 返回它。调用方需要处理响应丢失时必须自行保存并重用该键。同键不同请求或已删除通道的旧操作一律拒绝。
2. 顺序为输入校验、持久化 `credential_change_requested/pending`、原子替换加密 store、持久化结果审计。秘密变更与最小结果回执一起写入 store；回执包括操作 ID、请求摘要、非秘密元数据、是否应用和结果审计状态，不复制明文秘密。
3. PUT 保留原元数据响应并增加 `operationId`、`applied`、`auditStatus`。已应用而结果审计失败仍返回成功，`auditStatus=pending`；DELETE 保留 204/404，通过 `X-RelayLink-Audit-Status` 区分。已应用的删除重试仍返回原 204。预审计失败返回 503 且不应用；文件替换遇到无法确认的 I/O 故障时，响应明确要求按同一 ID 查询式重试，不声称未应用。
4. 每次实际变更生成并随回执保存独立审计 ID，事件 ID 由该 ID 与阶段确定（旧回执按操作 ID 兼容），SQLite 仅在相同 `event_id` 冲突时忽略重复；其他约束故障仍失败。后台每 10 秒最多补记 64 条结果；无需重放凭据变更、业务 SQL 或目标操作。回执总量最多 1024 条，已审计回执保留至少 24 小时，超过容量拒绝新变更，不删除未对账结果。24 小时之外不保证同键重试幂等；过期回执清理后若同键再次实际应用，使用新的审计 ID，不能被旧事件去重吞掉。替换前崩溃后重试可能留下多个 pending 意图，但同一已应用回执的结果仅记一次。
5. 配置写锁在外、秘密库锁在内。凭据路由在同一配置锁中检查通道存在并完成变更。删除先持久化 scope 标记并撤销连接，再移除配置，最后原子清除该 scope 的凭据、SSH 主机键并退休旧回执。清理失败保留标记，阻止读写和同 ID 重建；配置移除成功仍按成功响应，管理状态接口展示待清理项。恢复服务只清理当前配置已不存在的 scope；若配置仍存在，管理员重试删除。新建也先清理历史孤儿，不能继承旧秘密。
6. 服务模式初始化失败转为秘密库不可用，不阻止管理诊断和 `none` 通道启动。可审计入口失败关闭。管理健康接口为 `/api/v1/admin/credentials/status`，需要管理员会话，不返回秘密。读失败、错误 key、丢失 store 均不能被解释为空库。首次创建 key 时立即写空 store；已有 key 却无 store 的情况在重启后也失败关闭。

## 恢复与迁移

备份必须成套包含服务端/客户端配置和 `credentials/key`、`credentials/store`；操作回执与删除标记在加密 store 内。离线恢复匹配的一组文件并保持原文件权限后重启，先查看秘密库状态与待清理项，再开放可审计入口。只恢复 key 或只恢复 store 不能保证一致。

旧版本可能只创建 key 而从未写入 store。这与 store 丢失无法自动区分，因此也按不可用处理。管理员确认从未保存凭据或主机键后，可在停服且保留备份的条件下移出整个 `credentials` 目录，由服务重新初始化；不得为已有业务秘密执行此空库初始化。初始化失败后修复文件需要重启，运行时文件损坏不会自动生成新 key。

## 备选与后果

- 不采用“先写成功审计再修改”，它会在磁盘失败时留下虚假成功。
- 不采用写入后审计失败就回滚秘密库，回滚也可能失败，且并发读取和已使用的秘密无法回滚。
- 不把 SQLite 和秘密库移入一个新数据库；本轮保留现有存储边界，使用有限恢复元数据说明实际结果。
- 日常口令替换只影响后续目标认证；删除 scope 才撤销相关连接。恢复扫描可能在配置已删除后短暂显示待清理，期间禁止复用 ID。
