# ADR-0029：应用标识、内置插件与本机桥应用

状态：Proposed\
日期：2026-10-28

## 背景

可审计通道需要稳定的应用标识，供服务端选择插件、供客户端决定唤起 SSH、远程桌面还是浏览器。现有通道 tag 是管理员自由输入的筛选条件，明确不进入快照、不参与转发，且只修改 tag 不下发配置，见 [REQ-001E](../requirements/2026-09-21-client-management.md)。

用户要求应用在被访问通道上单独选择，保存进 tag，选定后不能修改，并由端到端访问通道继承。客户端从浏览器控制台唤起本机应用，同时避免浏览器拿到口令、私钥和过多连接信息。SSH 与 RDP 还要能使用服务端保存的账号完成自动登录。

## 决定

- 应用不是新的自由 tag。表单下拉在通道 tag 中写入至多一个保留值：`app:ssh`、`app:rdp`、`app:http`、`app:https`。未指定表示没有该 tag。自由 tag 编辑不能制造或删除 `app:` 项。选定后拒绝修改；更换应用必须重建通道。
- Agent 快照只增加由该 tag 派生的 `application` 字段，仍不下发其他 tag。端到端入口不保存应用，下发时从目标通道派生。这一例外只在本设计被采纳后生效；采纳前 FR-14 的 tag 规则保持不变。
- 服务端插件是进程内的内置组件，按 `application` 注册。首期不从磁盘加载程序集，不热更新，不提供远端插件包。只有 `server-peer` 和 `server-jump` 会调用插件。
- SSH、HTTP、HTTPS 在首期按应用协议处理到各自需求表所述的深度。RDP 首期只做连接放行、审批和元数据；不实现 RDP/CredSSP 协议栈，因此不审计图形和剪贴板。这是能力边界，不是把 RDP 通道退回 `none`。
- 目标口令和私钥放在独立的加密秘密库，不放进通道 JSON。管理 API 不返回秘密。默认由服务端在目标侧使用。发给客户端必须由通道策略打开，一次有效，并记审计。
- 浏览器不直接启动 SSH 或远程桌面。本机页面或管理页向本机 Agent 申请一次性 intent，再用已注册的 `relaylink:` 协议交给桥应用。intent 不含令牌和秘密。桥应用使用预先配对的本机密钥向 loopback 领取入口和获准的凭据。
- 脚本模板随桥应用安装，或由本机受保护配置覆盖。参数只有固定字段。服务端、管理页和网页不能替换脚本正文。
- 没有应用、没有桥、协议不匹配或通道不是可审计模式时，客户端降级为显示地址或只做不含秘密的唤起，不报成通道故障，也不向服务端申请目标凭据。

## 备选

- 继续把应用放在可编辑的自由 tag 中：调用方可以改标签来换插件，也和「tag 不下发」冲突。拒绝。
- 只增加独立字段、不写入 tag：不满足「保存到标签并沿用列表筛选」。派生字段加保留 tag 可以同时满足存储和运行时。
- 由网页或服务端下发脚本：浏览器和管理通道会变成代码执行入口。拒绝。
- 把口令放进自定义协议的 URL：地址会进入历史记录、进程参数和本机其他用户可见的窗口标题。拒绝。
- 首期实现完整 RDP 中间人：需要独立的 RDP 与 CredSSP 实现，不能和 SSH、HTTP 共用字节管道。列入后续，不塞进首期验收。
- 热加载第三方插件：与仓库「不引入热更新」的边界冲突，也缺少隔离模型。拒绝作为首期方案。

## 后果

管理员一旦选定应用，就不能在原通道上改正选错的值。客户端继承关系始终跟目标通道走，入口本身没有第二份应用配置。

服务端会保存目标凭据。秘密库和通道配置必须一起备份，同时必须限制服务账号读取。打开「向客户端发放」后，获准的本机用户能在发放时窗内看到该凭据，安全等级低于服务端代登录。

桥应用是每台操作员机器上的额外组件。未安装时，新通道仍然可以转发，只是没有一键唤起。只读的本机页面不能创建会发放凭据的 intent。

RDP 的首期审计不能被写成内容审计。若后续增加 RDP 协议栈，用新的需求和 ADR 扩展，不回头改写本决定的首期范围。
