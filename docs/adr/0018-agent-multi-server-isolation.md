# ADR-0018：Agent 按服务端配置项隔离运行上下文

状态：Proposed\
日期：2026-09-28

## 背景

[REQ-001J](../requirements/2026-09-28-multi-server-agent.md)要求同一 Agent 同时连接多个独立服务端。现有 Agent 只有一组连接配置、控制会话和内存快照，端到端身份及端口状态文件以 `clientId` 命名。本机 API 也假设只有一个客户端。不同服务端可能使用相同的客户端、通道和映射 ID，继续以这些 ID 作为进程内或文件系统的全局键会混淆状态。

## 决定

- Agent 本机为每个服务端配置项设置稳定的 `profileId`。它只是本机归属键，不进入服务端协议，也不能代替服务端颁发的 `clientId`。同一 Agent 进程创建多个独立运行上下文，分别持有凭据、CA、控制会话、快照、重连、连接和取消范围。
- 每个上下文仍使用现有单服务端线协议。普通通道和互访仅在其所属服务端内路由；服务端无需知道 Agent 还连接了哪些其他服务端。
- 新格式本机配置将进程级设置与 `servers[]` 中每个服务端的连接设置分开，新格式中 `profileId` 必须唯一。独立转换器在新 Agent 首次启动前迁移旧单服务端配置、端到端身份及端口状态；所有启动入口先运行转换器，成功后才启动 Agent。Agent 主程序只接受新格式，页面增删不处理旧格式。新版安装包的新装和重新配置只校验、写入新格式；新版服务端下载单项新格式，旧版下载文件需先由独立转换器处理。服务端不输出含其他服务端密钥的完整 Agent 配置。
- 端到端身份和端口状态按 `profileId` 分区；本机 loopback 监听使用全进程端口分配器，以 `(profileId, mappingId)` 作为键。转换器把单服务端旧状态迁入首个配置项的新目录；旧材料仅作受保护的回退来源，不能在运行时归属多个服务端。
- Agent 本机状态按 `profileId` 分组。现有 v1 接口在单服务端模式维持原响应；多服务端模式提供 v2 分组接口，v1 请求返回明确的不适用错误，避免把某个服务端误报为整个 Agent。本机监控页面仅监听 `127.0.0.1`，无需管理密码即可新增、删除服务端连接项；写请求校验本机来源与 CSRF 令牌。状态读取仍匿名，已保存注册密钥不通过页面或 API 读取。页面删除只解除本机连接，不删除远端客户端记录。

## 备选

- 每个服务端启动一个独立 Agent 进程：进程隔离更强，但本机状态页和互访端口范围可能冲突，也不能满足单实例同时管理的需求。
- 以 `serverHost` 或 `clientId` 作为隔离键：地址可能变更，且不同服务端可以使用相同客户端 ID，不能作为稳定归属。
- 扩展线协议传递全局服务端 ID：增加服务端升级和跨部署身份治理，当前各服务端独立运行不需要。
- 在 Agent 配置读取或本机页面首次新增时兼容旧格式：会让主程序长期携带两套解析、路径与身份规则，也使首次页面操作承担身份迁移风险；改为启动前一次性转换。
- 仅凭 loopback 绑定开放新增和删除而不校验请求来源：其他网页可能向本机端口发起跨站写入。采用来源校验和 CSRF 令牌；本机其他进程的访问由主机权限边界管理。

## 后果

Agent 的配置加载、运行状态、文件命名和本机 API 需要升级，并增加本机短期会话及 CSRF 校验，无需管理密码。每个服务端维持独立证书身份，既有服务端固定的指纹只在明确指定的旧配置项上沿用；误删或错误迁移身份仍需按 [ADR-0011](0011-client-level-e2e-identity.md) 的受保护流程处理。共享进程、操作系统、网络出口和磁盘仍是共同故障域；按配置项的有界配额可隔离正常运行中的资源竞争，但不承诺抵御整个主机故障。具体格式、迁移和验收见 [多服务端技术设计](../design/multi-server-agent.md)。
