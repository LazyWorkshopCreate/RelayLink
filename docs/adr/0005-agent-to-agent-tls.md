# ADR-0005：服务端协调的 Agent 互访与内层 TLS

状态：Superseded by [ADR-0011](0011-client-level-e2e-identity.md)（证书登记部分）和 [ADR-0016](0016-optional-peer-traffic-encryption.md)（强制内层 TLS 部分）；其余互访决策仍适用\
日期：2026-09-17

## 背景

新增场景要求位于两个内网的 Agent 通过服务端中继相互访问，同时访问方必须是已注册且得到授权的客户端。原有数据隧道止于服务端，不能直接视为 Agent↔Agent 端到端加密；原云端代理端口也没有业务调用方身份。

## 决定

服务端仍是可信的配置和授权控制平面。访问方映射、目标通道模式及每通道独立随机访问密钥都保存在服务端客户端配置中，随经过认证的控制连接下发给对应 Agent。访问方映射只可绑定 `127.0.0.1`。服务端在已认证会话上核对映射归属、目标可用性和调用方身份，才协调两条一次性数据隧道；被访问 Agent 在访问密钥认证成功之前不拨号目标。原云端代理监听只为非授权通道启动。

访问密钥经控制快照下发，因此任何启用互访配置的服务实例都必须开启 Agent↔Server 外层 TLS；纯 TCP 模式只保留给无互访配置的旧通道。业务数据在两条数据隧道之上另建 Agent↔Agent TLS。被访问 Agent 本机生成并持有端到端证书私钥，服务端只保存其公钥指纹并下发给获授权的访问方；访问方严格固定该指纹，不使用系统信任库、不允许信任首见。密钥轮换通过显式管理操作更新指纹。服务端中继的是内层 TLS 密文，不解码业务内容；连接长度、时间、客户端和通道标识仍可见。每条互访连接有独立内层 TLS 握手，受建立期限和既有资源配额约束。

访问密钥由至少 32 字节 CSPRNG 随机数生成，不使用密码短语。它是第二道授权凭据，不替代访问方的独立 Agent 身份。服务端存有该密钥且控制指纹分发，所以此方案的威胁模型**不包含恶意或已完全攻陷的服务端管理员**；“端到端”特指正常运行时服务端仅转发密文，不表示服务端控制平面在恶意情况下无法冒充端点。需要在不信任服务端管理员的前提下保持端点认证时，必须改为带带外校验的公钥信任与端点侧独占凭据，另立设计。

## 备选

- 仅沿用外层 Agent↔服务端 TLS：服务端能读取业务载荷，不能满足端到端保护。
- 自制 PSK+ECDH+AEAD 隧道：协议审计和重放/降级防护成本高，本期不采用。
- 自动信任首见证书：服务端或路径上的主动攻击者可在首次连接时替换身份，不采用。
- 双端直接 P2P/打洞：不保证企业 NAT 与防火墙可达，且超出仅主动连服务器的约束。

## 后果

必须新增互访请求/配对协议、双数据隧道的生命周期、Agent 本地 loopback 监听、端到端证书注册与固定、访问密钥的管理与保密字段、双端配置下发。控制服务端配置权限的人仍可授权访问，属现有管理信任边界。原有非授权通道与仪表盘读数须保持兼容，互访密文字节统计不能冒充应用有效载荷字节。
