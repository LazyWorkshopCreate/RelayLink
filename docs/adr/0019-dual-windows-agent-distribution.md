# ADR-0019：Windows Agent 双模式发布与程序目录替换

状态：Superseded（安装目录布局由 ADR-0020 调整）\
日期：2026-09-29

## 背景

原安装包从自包含改为框架依赖后，升级仍逐文件覆盖原目录。旧自包含安装留下的 `hostfxr.dll` 等运行时文件被新程序优先加载，导致配置转换器误判本机没有 x64 .NET 10，安装失败并停止服务。用户要求 Windows Agent 程序和安装包同时提供自包含、框架依赖两种构建，更新时整体替换程序文件夹。

## 决定

- `win-x64` Agent 与独立配置转换器按同一模式分别发布，生成自包含及框架依赖两套程序压缩包和两套 Inno Setup 安装包；文件名明确标注模式。
- 两种安装包共用 AppId、服务名和 ProgramData 状态目录，可用“仅更新”在两种模式间切换。自包含包携带 .NET 10 运行时，安装时仍检查 Windows x64 与 VC++ x64，不要求目标机另装 .NET；框架依赖包额外检查 .NET 10 ASP.NET Core Runtime x64。
- Inno 卸载记录和安装脚本留在 `{app}`，实际程序放在 `{app}\program`。预检停服后，安装器删除并重建整个 `program` 文件夹，再运行配置转换器并启动服务。升级旧版根目录安装时，清理根目录中的旧启动文件和核心运行时文件，并将已注册服务路径改为新位置；其余旧文件不再位于程序搜索路径。ProgramData 中的配置、身份、端口状态和日志不受程序目录替换影响；转换失败时服务保持停止。
- 发行流水线同时上传两种程序压缩包与两种安装包，并在 SHA-256 清单中区分。

## 备选

- 继续只提供框架依赖包并删除少数旧运行时文件：无法满足双模式交付，也可能留下其他过期程序集。
- 在同一目录继续逐文件覆盖：模式切换会残留对方模式的文件，已导致现场失败。
- 将卸载记录与程序一起删除：会破坏 Inno 对既有安装的卸载日志追加，故保留安装器根目录。

## 后果

自包含包更大，运行时安全补丁需通过重新发布 Agent 提供；框架依赖包较小，目标机须维护 .NET 10 ASP.NET Core Runtime x64。两个包均不含真实配置或密钥。更新期间程序目录会短暂不存在；安装失败不报告为成功，服务保持停止以便排查。旧版根目录的非程序文件和 Inno 卸载记录继续保留。

ADR-0017 的单一框架依赖交付决定由本决定取代。
用户随后要求程序直接位于 Agent 安装根目录；目录布局改由 [ADR-0020](0020-flat-windows-agent-installation.md) 决定，双模式发布继续沿用。
