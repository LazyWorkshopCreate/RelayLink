# ADR-0043：授权互访优先直连并按通道加密策略回退

状态：Proposed\
日期：2026-11-27

## 背景

现有互访由 Server 授权并转发全部业务流量。即使两个 Agent 在同一局域网内，RDP 等连接也占用 Server 带宽。双方都在 NAT 后时，实际能否双向通信取决于具体的地址映射和网络策略。

## 拟议决定

首期拟为授权 raw TCP 和单播 UDP 同时提供加密与明文直连。通道默认加密，选路默认仅中继。管理员显式关闭业务加密并启用优先直连时，才使用明文直连。Server 通过 TLS 控制连接协调两端，保持映射授权、访问证明、起始审计、配额和撤权。加密直连使用 QUIC 及目标证书固定校验。明文直连使用 ICE-TCP 检查通过的连接，双方验证本次会话绑定，目标方校验通道访问证明。[既有加密策略](0016-optional-peer-traffic-encryption.md)

两种承载均为可靠流。TCP 传输业务字节，UDP 每个来源会话复用已有长度封装，保留空报文与 65507 字节上限。放行前确认直连不可达时，只能回到相同加密模式的现有中继。认证失败则终止请求。TCP 断线后由调用方重连，UDP 会话结束后由下一份新报文触发建连，均不重放旧载荷。[设计与验收场景](../design/peer-direct-and-relay.md)

- 发起探测的 Agent 在首个网络包前检查规范化目的地址、端口和实际出口，按对端身份和目的 IP 分别跨会话限流。私网候选须由本站独立许可。
- 双方就绪回执须绑定同一条已认证传输。首租从每端首次发送就绪请求起计时，覆盖系统挂起。双方确认有效首租后才允许目标拨号。新协议下，直连和回退的业务目标就绪均由目标经 Server 的 TLS 控制面确认。
- 首次授租前，将起始审计和直连配额占用一并持久化。重启后先恢复未结清占用，再接受使用相同额度的申请。首期选择从确认旧实例停止签发起保守等待该连接的最大租期及误差裕量，再释放旧占用并结清审计，缺失流量标记为未知。

## 备选与取舍

| 方案 | 取舍 |
|---|---|
| 继续全量中继 | 兼容现有部署，Server 可直接切断数据流，带宽仍集中在中继主机。作为缺省策略保留 |
| 只允许直连 | 过滤 UDP 或缺少可用地址对的站点将失去原有互访能力 |
| 明文通道也使用 QUIC | QUIC 的传输加密是强制的，无法表达现有开关要求的业务载荷明文复制。独立的 TCP 承载能保留这项语义，代价是要验证第二种候选和传输 |
| 另行部署 TURN 中继 | 可提供标准 ICE 中继候选，但需要新的分配、认证和运维机制。首批回退可复用现有具备授权和审计的 TCP 中继 |
| UDP 直接使用 QUIC DATAGRAM | 丢失的帧不重传，适合对过期报文敏感的应用。采用前需解决 .NET 10 接口与路径 MTU 限制。首期以可靠流保留既有报文契约，接受同一来源可能等待重传的代价 |
| 每次续租都持久化到期时间 | 可缩短部分重启后的额度等待。首期按首次授租时冻结的上限恢复，避免在续租路径写盘及跨主机比较时钟。代价是重启后部分额度可能要等一个完整最大租期才能复用 |

## 后果

直连仍依赖 Server 的授权和控制连接。现行中继可在 Server 上关闭套接字，直连改由端点执行撤销，并以有限租期约束控制面分区时的撤权延迟。Server 需依赖端点上报才能统计直连字节。采纳前应分别验证各平台的 UDP/QUIC 直连和 TCP 直连。明文路径允许链路上的第三方读取或篡改未受业务协议保护的载荷，沿用 ADR-0016 的部署边界。当前有效的决策见[连接撤销](0009-revoke-connections-on-channel-change.md)、[身份登记](0011-client-level-e2e-identity.md)和[起始审计](0013-sqlite-audit-gate.md)。
