# ADR-0010：SQLite 分钟流量历史

状态：Accepted\
日期：2026-09-18

## 背景

[ADR-0003](0003-traffic-history-persistence.md) 采用 JSONL 周期性记录累计快照。当前实现每次采样后读取和重写全文件进行清理，读取历史也需扫描全文件；授权端到端通道的密文字节未进入历史。用户要求 SQLite 持久化、按分钟存储、默认保留 90 天，并覆盖端到端通道。

## 决定

单服务端实例使用 `Microsoft.Data.Sqlite` 写入本地 SQLite 数据库，WAL 模式。以 UTC 分钟、目标客户端 ID、通道 ID 为唯一键，保存该分钟两个方向的增量字节与连接数；普通代理字节和端到端密文字节分列存储，查询时提供合计。端到端业务明文不可见，也不估算明文字节。定期从运行时累计计数计算增量并 UPSERT，同一分钟多次采样累加；每日至少执行一次 90 天（可配置）清理。

旧配置若仍指定 `.jsonl`，在同目录派生 `.db`，一次性导入旧累计快照并换算为分钟增量；原 JSONL 保留，不再追加。首次旧样本会把此前累计量归入其所在分钟，因此迁移前的分钟精度无法恢复。新配置直接指定 `.db`。

## 备选

- 保持 JSONL：无需新依赖，但高频采样、查询和保留期清理会持续全文件扫描。
- PostgreSQL：适合多实例集中汇总，但给单实例默认部署增加外部依赖；本次不扩展现有服务端存储能力范围。

## 后果

数据库文件、`-wal` 和 `-shm` 均需服务账号写权限与备份策略。分钟归属以采样时刻为准，最多存在采样间隔级别的边界偏差；进程异常退出可能丢失尚未采样的少量字节，故不用于计费。SQLite 默认不提供静态加密，需依赖受限文件权限和磁盘加密。历史 API 的字节字段从“进程累计值”变为“该分钟增量”，前端图表和说明须同步变化。
