## 版本与适用范围

UDP 是 2026-10-05 增加的仓库扩展，支持普通云端入口和客户端授权互访的单播报文。现有 [v0.1.0-rc.8 发布说明](../releases/v0.1.0-rc.8.md)不包含这项扩展；使用 UDP 须采用包含该实现的同版本 Server 和 Agent，不能将站点内容更新视为新安装包已经发布。

当前源码的 Server 同时支持 v3/v4，允许先升级服务端，v3 Agent 继续使用 TCP；UDP 需要相关 Agent 升级到 v4。v3 不接收 UDP 通道或映射，涉及旧端的 UDP 请求被拒绝。本次重新构建 v0.1.0-rc.9 纳入兼容修复；此前同名包仍拒绝 v3。须重新下载并核对最新 SHA256SUMS，不凭文件名或缓存判断是否包含修复。旧通道省略 `transportProtocol` 时仍默认 TCP。具体方案的[需求](../requirements/2026-10-05-udp-forwarding.md)和[设计](../design/udp-forwarding.md)保持 Draft，[架构决策](../adr/0024-udp-over-independent-tunnels.md)保持 Proposed；本机验证与目标环境缺口以[验证状态](../testing/verification-status.md#2026-10-05-udp-转发req-001l)为准。

## 创建普通 UDP 通道

1. 按[安装与使用指南](installation-and-usage.md)准备 Server 和 Agent，确认目标 Agent 在线，并能访问目标 UDP 服务。
2. 在服务端管理页创建或编辑通道，选择 `UDP`，填写 Agent 所在网络可达的固定目标主机和端口。不要将 TCP 服务的端口直接当成 UDP 服务使用。
3. 填写服务端业务监听地址和端口，配置来源 IP 安全组。TCP 和 UDP 可使用相同数值端口；同协议的监听冲突会被拒绝。
4. 设置 `udpIdleTimeoutSeconds`，默认 60 秒，允许 1–3600 秒。应用向服务端的业务端口发送 UDP 报文，回包返回原调用来源。

每个来源 IP 和端口形成独立会话，目标看到 Agent 的 socket 地址，不能得到调用方原 IP。目标 socket 初始化成功只说明本机解析和准备完成，不证明目标服务在线或可达。

## 使用客户端授权互访

在服务端创建 UDP 目标通道和访问映射；通道及授权仍由服务端管理。访问方在 Agent 本机页面找到标为 UDP 的回环入口，应用向该 `127.0.0.1:<端口>` 发送 UDP，而非建立 TCP 连接。

入口协议和空闲超时继承目标通道。本机端口仍由访问方 Agent 分配并持久化。互访默认使用内层 TLS，Server 中继密文；管理员明确关闭通道加密时才采用认证后的明文中继。协议切换或实际配置变化会撤销旧会话并重建相关入口。

## 网络与安全

| 入口 | 防火墙协议 | 说明 |
|---|---|---|
| Agent 控制与数据连接 | TCP | 继续使用原有端口，不新增公网 UDP 数据入口 |
| Server 普通 UDP 业务端口 | UDP | 仅允许需要的业务来源，并配置应用层安全组 |
| 访问方 Agent 的本机业务入口 | UDP | 回环地址，由访问方应用使用 |
| Agent 到目标服务 | UDP | 目标服务须允许 Agent 的出站来源 |

Linux [Docker Compose](../../deploy/docker/README.md)采用 host 网络，业务端口不需要单独映射；自定义 bridge 网络须显式发布 `/udp`。普通 UDP 数据隧道不额外提供链路加密；敏感业务需要业务自身保护或默认加密的授权互访。安全组和防火墙不能替代业务身份认证。

## 报文、超时与排障

- 报文边界保留，支持零长度和最多 65507 字节载荷。每会话最多排队 32 个报文；队列满时丢弃新报文，不无限排队。
- 任一方向成功转发刷新空闲时间。超时会释放会话，下一个报文触发新会话；不恢复、重试或重放之前的载荷。
- UDP 经独立 TCP 数据隧道转发，TCP 重传会带来队头阻塞。业务仍须自行处理超时、重试、丢包和重复，不承诺实时延迟或无损传递。
- 不支持广播、组播、通用服务发现或动态端口改写。UDP 1434 通道不等于 SQL Browser 命名实例自动发现；RDP UDP 的真实业务兼容性仍需目标环境验证。

没有回包时，依次确认应用使用 UDP、入口协议与端口正确、目标 Agent 在线、安全组和防火墙放行、Agent 可达固定目标。检查两端日志和协议版本；仅看到会话已建立不能证明目标服务已经响应。进一步的封装、配额与生命周期说明见 [UDP 技术设计](../design/udp-forwarding.md)。
