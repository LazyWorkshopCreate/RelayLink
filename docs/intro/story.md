# story.md — RelayLink 开源项目介绍

## ① 用户意图对齐

- **目标受众**：开发者 / 技术同行。场合是开源项目首次对外亮相（GitHub README 之外的讲清楚版本），也用于技术分享。观众具备 TCP / TLS / .NET 基础，能读懂协议帧和时序图，不需要科普"什么是端口"。
- **核心目标**：讲完后观众相信三件事 ——
  1. RelayLink 解决的是一个真实且具体的工程问题（AI 时代数据中台回潮，但零售 / 多分支企业的数据分散在全国各地内网，第一步就卡在"数据出不来"）；
  2. 它不是玩具，控制/数据分离、一次性令牌、端到端加密互访这些设计都有明确的取舍理由，而且**已经在真实环境投产**（跨公网 RDP 连续运行一天、SQL Server 数据通道在另一环境投产）；
  3. 它的边界是诚实的 —— 它不是中台，只是中台前面那根管子；只做 TCP、不解析 SQL、普通数据通道是明文、集群和容量压测都还没做。
  希望观众记住：**反向连接 + 服务端集中配置 + 端到端加密互访**。希望他们去做：打开仓库看 ADR。
- **PPT 长度**：22 页。Hero 配额 6 页（封面 / 架构总览 / 连接时序 / 互访加密 / 真实环境投产 / 结束页），占 27%。
- **视觉调性**：极简克制、工程感、线条化、冷色、留白围绕焦点、信息密度高但不拥挤。
- **内容边界**：
  - 必讲：**开场背景（数据中台回潮 → 零售企业数据分散 → 第一道坎是连通性）**、问题场景、整体架构、双端口与一次性令牌、一条连接的完整时序、三层凭据、互访端到端加密、**真实环境投产情况（RDP 连续一天 / SQL Server 通道投产，且必须紧跟"跑起来 ≠ 压测通过"）**、可运维性、能力边界与验证状态。
  - 定位红线：**RelayLink 不是数据中台，是中台前面那根管子**。全篇不得暗示它做数据建模、指标、特征或训练；它只负责让"汇聚"这件事先成立。
  - 不讲：逐字段配置手册、安装命令详解、SQL Server 连接字符串细节、ADR 编号逐条罗列、审计模块（仅设计未实现）。
  - 禁碰：不宣称"已通过容量验收"；不把设计文档里的拟定压测基线说成实测结果；**不把"投产运行一天"写成"容量已验证"**（真实场景观察 ≠ 受控压测）；RDP 登录后数十秒出画面的根因未确认，不得写成"已解决"。
